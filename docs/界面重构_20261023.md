# 界面重构（2026-10-23）：删掉无用表单，按成熟产品的逻辑重排

起因：作者反馈「目前的 GUI 有些无用表单，可以删了，而且我还是不满意目前的交互逻辑，按成熟产品的逻辑优化它」。
这一轮只动界面与交互，不动随机引擎与写盘逻辑（写完用自检与实机确认没碰坏）。

## 一、判定「无用表单」的四条标准

1. **不是一个入口能解决的事，就不要摆两个按钮**：同一个"生成/应用"动作在敌人页原来有 5 个入口
   （预览 / ② 写入方案层 / ①+② 一次写 / 用这个方案玩 / 切回本体），人得先判断该按哪个。
2. **已经停用的管线不该留在界面上**：旧敌人管线（v0）整块折叠面板约 11,273 字符，主部署早就强制
   `_e["on"]=False`，那些控件对现在这条线是死表单 —— 整块删除（不是藏起来）。
3. **说明性文字不是表单**：常显六行「当前生效的规则」、三条「小提示」、环境卡里 7 项诊断清单，
   都属于"需要时去读文档/展开看"的内容，不该常占版面。
4. **破坏性动作必须走显式按钮**：方案库原来双击一行 = 直接写入游戏；双击是"打开"的语义，
   容易误触。现在双击 = 用这个方案玩，写入必须点按钮。

## 二、信息架构

| 页 | 页内的东西 | 动作在哪 |
| --- | --- | --- |
| 职业物品随机 | 第 1 步随机项目 / 第 2 步合理度 / 结果 / 环境（一行，详情可展开）/ 更多设置（折叠）/ 详细记录（折叠） | 这一页底部的固定条：① 生成 · ② 写入 · 还原 · 保存到方案库 · 启动游戏 |
| 敌人随机 | 左列「随机规则」卡（特殊池 / 演出开关 / 数值 / 种子比例 / 生成 + 预览 / 预设与手动指定） | 卡里的「生成方案层并应用」；右列「当前方案」卡里有「用这个方案玩」「切回法魂本体」 |
| 方案库 | 左列表 + 右详情（常驻） | 详情面板底部：用这个方案玩（主）· 写入游戏（次）· 收藏 / 载入 / 复制 / 导出 / 删除；右键菜单收不常用动作 |

底栏按页签显隐：只在物品页出现。敌人页与方案库页的动作都在页内，底栏整条收起
（原来在敌人页也摆着"① 生成随机方案"和一个"本次写入 物品…"的摘要，容易误以为是当前页的按钮）。

## 三、删掉的东西

- 旧管线（v0）折叠块：总开关 / 游戏进程 / 敌人摆放 / 法魂专属 / 未接项 / 右下重复的三个按钮 —— 整块删除；
  对应的 `enemy_on`、`enemy_pools`、`enemy_source`、`enemy_visual`、`enemy_emevd`、
  `enemy_keep_unkillable`、`enemy_same_type`、`enemy_seed_sep`、`enemy_type_tree`、
  `enemy_cls_rates` 这些控件变量与它们的联动方法（`_refresh_enemy` / `_enemy_cfg` /
  `_enemy_restore` / `enemy_preset` / `enemy_layer` / `_toggle_enemy_legacy` 等）一并删除。
- 物品页「结果」卡里的三条小提示（与底栏/按钮旁注重复）。
- 「当前生效的规则」六行常显列表 → 压成一行：规则：传送门守卫 / 有血条的位 → BOSS；六类 BOSS 互换；常规三族互换；其它不动。
- 敌人页左卡动作行里重复的「用这个方案玩」（右卡已有）。
- 底栏「生成 / 写入 / 还原 都在窗口底部（物品与敌人一起）」的旧文案 → 改成与实际一致的说明。

## 四、改掉的东西

- 敌人页只有一个生成入口：`enemy_v1_apply` —— 物品页有方案就一次写入物品 + 敌人，没有就只写敌人。
  人不用再记"这次该按哪个按钮"。
- 物品页「环境」卡压成一行：检测结果 + 重新检测 / 指定 MOD 目录 / 补一份原始备份 / 「逐项详情 ▸」
  （逐项清单默认收起，出问题时才展开）。
- 方案库双击 = 用这个方案玩（`_lib_on_dbl`）；详情面板主按钮改成「用这个方案玩」，「写入游戏」降为次按钮。
- 敌人页的状态与挂载操作集中到右列「当前方案」卡（挂载状态那行原来在最底下，和按钮隔得很远）。
- 底栏按页签显隐（`_sync_footer`）。
- 物品页头部文案「一屏两页」的说法、方案库副标题「双击直接写入游戏」都按新行为改写。

## 五、验证

- `randgui.py --uicheck`：界面构建成功、12 项对比度全过、装饰件 5/5。
- `randgui.py --uitest`：全绿。新增/改写的断言包括：
  - 旧管线（v0）的折叠块与开关彻底删掉（不是藏起来）；
  - 敌人页只剩一套控件（`ev1_*`），旧变量一个不留；
  - 敌人页重复的部署入口与旧规则说明都清掉了；
  - 底栏跟页签走：方案库页、敌人页整条收起；物品页上仍在；
  - 详情按钮主次：用这个方案玩是主按钮、写入游戏是次按钮；
  - 双击那一下 = 用这个方案玩（不是写入）。
- `randgui.py --selftest` / `--planlib`：随机引擎与方案库读写仍然通过。
- 三页截图各看了一遍（细节：说明卡文字不再被裁掉、底栏不再在敌人页出现、动作行不再重复）。

## 六、边界（这一轮没做的）

- 敌人页的「自定义敌人配置… / 手动指定…」没动：它们是两个明确功能，不属于死表单。
- 方案库空库时详情面板的标题与列表空状态都写着「还没有方案」——重复但无害，留给以后一起收。
- 界面背后调用的引擎/写盘接口一个字节没改（enemy_write / native_deploy / plan_layer / gamelib 均未动）。

## 七、2026-10-23 傍晚：进一步收成一个「开始随机xxxx」

重排之后底栏还是两个按钮（① 生成 / ② 写入），敌人页另有一套「生成方案层并应用」——
同一个动作在三处能点。这一轮把它们**收成一个**：

- 底栏主按钮 `b_start`（`start_randomize`）：文案按勾选实时变（只看物品 / 只看敌人 / 两者），
  全不勾时禁用并提示先勾类型；`_refresh_start_action()` 是所有状态（勾选、忙碌、环境不就绪）的唯一出口。
- 点击后：只敌人 → 直接建层；物品 → 先生成，生成成功再自动写入（`_pending_start` + `gen_ok` 队列消息），
  物品 + 敌人 → 生成成功后走组合路径（同一份基底上建敌人层，只挂一个层）。
- 敌人页那三个入口删除，只留「预览（不写盘）」；底栏在敌人页**重新显示**（唯一入口不该跟着页签躲）。
- 确认仍在写入之前（生成不写盘），所以「先看一眼」没有丢，只是挪进了确认框之前的取消路径。

验证：--uicheck / --uitest 全绿（含四种勾选组合、分派断言），端到端冒烟一次点击 8.2 s 产出方案层；
文档同步 README.md、`docs\使用说明（给玩家）.md`、`docs\发布\更新日志_v1.3.2.md`。
