# 方案库「用这个方案玩」+ 每个方案独立存档（2026-10-23）

## 一、需求（作者原话）

> 我觉得可以设置成以后可以直接用随机器里的方案库启动，每一个方案独立存档，这样应该很方便

原来方案库的「用这个方案玩」只做一件事：把方案层写进 `YAFSML.ini` 的 `Plan=`，
**启动游戏还得人自己双击 `启动法魂.bat`**。更麻烦的是存档 —— 所有方案共用 `%APPDATA%\EldenRing\<SteamID>\ER0000.sl2`
这一份档：在方案 A 玩到 60 级，切到方案 B，B 直接继承 A 的进度（数值、地图解锁、Boss 击杀全串味），
「换个方案体验另一套世界」这件事就废了。

所以这一版把它做成一条龙：**点一下 = 换档 + 挂载 + 起游戏；退出游戏 = 自动把进度存回这个方案自己的槽**。

## 二、改了什么（两处）

### 2.1 启动链路（`randgui.py` + `gamelib.py` 的 `launch`）

以前「用这个方案玩」只写 `Plan=` + 提示「请去双击启动法魂.bat」。现在一次点完：

1. 覆盖层不在 / 方案改过 → 后台生成（生成不碰法魂本体，只写层目录）；
2. `gamelib.launch(layer)`：查进程（在跑就先问，同意才关）→ `prepare_save()` 换档 → `set_plan()` 挂层 → 起游戏 → 写 `active_state.json`；
3. 界面每 2~4 秒轮询一次进程；游戏退出 → `finish()` 把 live 存档存回这个方案的槽 → 清状态；
4. 关着 GUI 时游戏退出（或 GUI 被杀）→ 下次启动 `recover()` 按 `active_state.json` 补一次回存。

### 2.2 存档库（`gamelib.py`）

新增一支只管存档的模块（不依赖 GUI）：

| 函数 | 干什么 |
|---|---|
| `live_dir()` | 找游戏真正在用的存档目录（`%APPDATA%\EldenRing\<SteamID>`，优先最近写过的） |
| `bank_save(label)` | live → `存档库\<方案名>\`（先给旧槽留底，写 `slot.json`：时间/大小/sha1/备注） |
| `restore_to_live(label)` | 槽 → live（成对换；槽里没有的 `.bak` 会清掉，保证两边一模一样） |
| `prepare_save(label)` | 换档那一步：先回存上一个方案 → 有槽就换入 / 没槽抛 `NeedsNewSave` 让人确认开新档 |
| `backup_live()` / `clear_live()` | 覆盖/删除前一律进 `存档库\_回收\`；新档开局前把旧档归到 `_法魂本体` 槽 |
| `finish()` / `recover()` | 退出回存 / 关着 GUI 时的补存 |
| `game_pids()` / `game_running()` / `kill_game()` | 进程判定与关游戏（先请它自己退，不退才强杀） |
| `--status` / `--selftest` / `--launch` | 命令行查看 / 自检 / 单独换档启动 |

## 三、存档库长什么样

```
<法魂包>\存档库\
├─ _法魂本体\            ← 还没用方案库之前的本体档（第一次开新档时自动归位）
├─ _回收\                ← 任何覆盖/删除之前的留底（时间戳_说明_原文件名）
├─ <方案名>\ER0000.sl2  ← 这个方案自己的档（成对带 .bak）
│            slot.json  ← 存的时间、大小、sha1、备注
```

存档库跟着**法魂包**走（整个包搬走，存档也在）；方案库（`plans\`）跟着**工具**走。

## 四、一次「用这个方案玩」的完整时序

| 步骤 | 做什么 | 失败/边界 |
|---|---|---|
| ① | 方案库双击 / 详情主按钮 | 游戏在跑 → 先问「自动关掉它并启动吗」，拒绝则什么都不动 |
| ② | 覆盖层就绪检查 | 没有/过期 → 后台生成（可取消、按钮置灰） |
| ③ | `prepare_save` | 上一个方案的进度先回存；没槽且没确认 → `NeedsNewSave`（界面弹「用新角色开局吗」） |
| ④ | `set_plan` + 起游戏 | 包根认错 / 没 yafsml → 报错并给做法 |
| ⑤ | 轮询退出 | 超时不算失败（游戏可能还开着）；界面上有「游戏在跑」状态 |
| ⑥ | `finish()` 回存 | 存不进（live 没了 / 权限）不崩，记录日志 |

**顺序不能反**：先回存 → 再换档 → 再挂层 → 再起游戏。反了会把上一个方案的进度写进新方案槽。

## 五、界面上看得见的部分

* 方案库详情多出**「存档」两行**：这个方案的槽（有没有、什么时候存的、多大）与游戏当前 live 档；
* 启动过程写方案目录里的 `启动日志.txt`（窗口版没有控制台，日志是唯一线索）；
* 失败一律说清卡在哪一步，不静默。

## 六、验证

* `gamelib.py --selftest`：存槽 / 换档 / 留底 / 清档 / 新档要确认 / 开新档留旧 / 没游戏不误杀；
* 隔离 dry-run：临时假包 + 假层 + 假存档 + 假启动 bat —— 换新档 → 写 `Plan=` → 启动 bat 真被执行 → 退出回存；
* 真机：两个方案来回切，live 的 sha1 与各自槽一致，`_回收` 每次都有留底；
* `--uitest`：方案库交互、存档两行、启动流程断言全绿。

## 七、2026-10-23 傍晚三：从方案层目录启动会被当成「法魂包根」

### 现象

双击方案层文件夹里的「用这个方案启动.bat」→ 报「法魂包根目录不对（没有 `yafsml\`）」。

### 根因

方案层里也有一份 `mod\regulation.bin`，从层目录启动时（cwd = 层根）向上找包根，先撞上层的 `mod\`，
把**层**当成了法魂包。

### 修法

| 位置 | 改动 |
|---|---|
| `modpaths.py` | `is_layer_root` / 认 `yafsml\` 反推真包根；环境变量被层占住时仍能找到包 |
| `randgui._pack_of_layer` / `cli_play` | `--play` 先发布**真包根**，再走换档/挂载 |
| `plan_layer.set_plan` | 层在别的盘时 relpath 抛 `ValueError` → 跨盘兜底（写绝对路径） |
| 层里两个 bat | 「用这个方案启动.bat」→ `--play <层>`；「切回法魂本体.bat」→ `--plan-off`（都走 exe，不依赖系统 python） |

### 验证

* 隔离 dry-run（临时假包 + 假层 + 假存档 + 假启动 bat）：**PASS** —— `pack_of_layer` 认出包根 → 换新档 → 写 `Plan=../方案/测试层/mod` → 启动 bat 真的被执行 → 退出后存档回存到 `存档库\测试层\`；
* 真实层目录里跑 `--play`（cwd = 层根）：不再报 yafsml，正常走到「这个方案还没有存档，要用新角色开始吗」；
* `--uitest`：新增「层不会被当成包」「能从层反推包根」「`modpaths` 也不认层」三条断言，全绿。

### 仍然成立的老规矩

* 层里的两个 bat 写的是**生成当时那台机器**的路径；换机器/挪目录后，在方案库点一次「用这个方案玩」会自动重写（`launch()` 每次都会重写）；
* 想确认现在认到哪些路径：`ConvergenceClassItemRandomizer.exe --paths`。

## 八、2026-10-23 傍晚四：僵尸进程壳让启动「永远关不掉游戏」

### 现象

点「用这个方案玩」→ 问「游戏正在运行…自动关掉它并启动吗」→ 等 35 秒 → 「关不掉还在跑的游戏」。
但游戏窗口没有，YAFSML 日志也停在几小时前；任务管理器里确实有 `eldenring.exe`，手动结束报 Access is denied。

### 根因

这些是**已退出但进程对象还没被系统收掉的残留壳**：线程数 / 句柄数 0、工作集 32 KB、
`WaitForSingleObject(h, 0)` 立刻 signaled。旧实现只查 tasklist 里有没有名字，于是永远认为游戏在跑。

### 修法

| 位置 | 改动 |
|---|---|
| `gamelib._pid_is_gone(pid)` | 打开句柄后 `WaitForSingleObject(h, 0) == 0` ⇒ 已退出；读不到句柄按「还在跑」算（保守） |
| `gamelib.game_pids()` | 过滤掉残留壳；`zombie_pids()` 只用于诊断日志 |
| `gamelib.game_running()` | 改成 `bool(game_pids())` |
| `gamelib.kill_game()` | 只在真有活进程时动作；残壳写日志；关不掉时提示「管理员权限要对等」 |

### 验证

* 真机两个残留壳（pid 2692 / 19736）：修前 `running=true`；修后 `running=false`、`zombie_pids()=[2692,19736]`，`--play` 正常走到换档；
* `gamelib.py --selftest` 新增第 ⑧ 项「僵尸壳不算在跑」；`--uitest` 新增一条断言。

### 边界

* 受保护 / 读不到句柄的进程一律按「还在跑」处理 —— 宁可多问一句，也不在游戏运行中动存档；
* 游戏若以管理员身份启动，随机器也要用同样权限运行（否则真的会关不掉）。

## 九、2026-10-23 晚：反复跳终端 + 独立存档没生效（两个一起治）

### 现象（作者原话）

> 现在用随机器启动或脚本启动，会反复跳出终端，异常影响体验，赶快查，还有独立存档也没单独生效

### 根因一：等游戏退出时每 2 秒闪一个黑框

轮询「游戏还在不在跑」用的是 `subprocess.run(["tasklist", ...])`。窗口版 exe 自己没有控制台，
每次起 `tasklist` 都会**新建一个控制台窗口** —— 于是判断一次闪一次（方案库界面 2~4 秒一次、
`--play` 等待循环 2 秒一次），一整局都在闪。另外 `launch_bat` 用 `os.startfile` 起
`启动法魂.bat`，也会弹一个 cmd 窗口。

### 根因二：换档换的是游戏「不读」的文件

法魂包 `yafsml\YAFSML.ini`：

```ini
replace_save_filename=.cnv
replace_seamless_coop_save_filename=.cnv.co2
```

行首点号 = 只替换扩展名 ⇒ 游戏把 `ER0000.sl2` 改名成 `ER0000.cnv` 读写。
而 `gamelib` 写死 `ER0000.sl2` / `ER0000.sl2.bak`：换档换 `.sl2`（游戏不读）、
回存存的也是那个游戏没碰过的 `.sl2` —— 归档的永远是 10-19 的老样子，玩家真实进度在 `.cnv` 里从没被存过。
「切回本体」也只清 `Plan=`、不换档，于是切回本体玩的还是那个方案的档。

### 修法

| 位置 | 改动 |
|---|---|
| `gamelib.save_names(pack)` | 从 `YAFSML.ini` 现读 `replace_save_filename` / `.co2`；点号开头 = `ER0000` + 值；没配就回落 `.sl2` |
| `gamelib.live_files / bank_status / bank_save / restore_to_live / clear_live / prepare_save` | 全部按配置的档名工作；成对换（连 `.bak`）；`restore_to_live` 保证 live 与槽完全一致（槽里没有的 `.bak` 会清掉） |
| `gamelib.migrate_legacy_saves(pack)` | 老 `.sl2` 槽 / live 首次运行自动改名成 `.cnv`（内容不动、先备份进 `_回收`、幂等）；`status / prepare_save / launch / finish / switch_to_body` 入口都会调 |
| `gamelib.switch_to_body(pack)` | 切回本体 = 先 `bank_save` 当前方案 → `backup_live` → 把本体槽换进 live → 清状态；`--plan-off` 先调它再清 `Plan=` |
| `gamelib` 进程层 | `_enum_game_pids()`（`CreateToolhelp32Snapshot` + `Process32FirstW/NextW`，ctypes，不起子进程）；`_run_hidden` 统一 `CREATE_NO_WINDOW`；`_terminate_pid`（`OpenProcess(PROCESS_TERMINATE)+TerminateProcess`），失败才回退 taskkill |
| `gamelib.launch_bat` | `os.startfile` → `subprocess.Popen(["cmd","/c",bat], cwd=包根, DEVNULL, _CREATE_NO_WINDOW)` |
| `randgui.cli_play` | 日志带上「存档文件 ER0000.cnv」；`--plan-off` 先换档再清 `Plan=` |
| `randgui --uitest` | 断言换成 `.cnv` 档名关系 + 「切回本体会换档」+「查进程不再起 tasklist 黑框」 |

### 验证

* `gamelib --selftest`：新增第 ⑨ 项「认 .cnv 改名」、第 ⑩ 项「老 .sl2 槽自动改名」，全 PASS；
* 真机迁移（2026-10-23 19:36）：live 的 `ER0000.cnv`（19:20 游戏亲手写的进度，sha1 `ee13396…`）归位到方案槽
  `方案_物品_敌人_种子_4856224_10-_388032`；本体槽 `.sl2`（10-21，sha1 `f33062…`）改名为 `.cnv`；旧文件全部进 `_回收`；
* 端到端（不起游戏）：`switch_to_body()` → live = 本体档 `f33062…`、状态清空 → `prepare_save(方案)` →
  live = 方案档 `ee13396…`、`Plan=` 重新挂上；
* 打包版 exe 真机启动一次：轮询期间新控制台进程 0 个，游戏读写的是 `ER0000.cnv`，退出后回存到方案槽。

### 边界

* 无缝联机档（`.co2`）只识别、不参与换档；
* 换档是整文件替换 —— 游戏运行中不要手动拷档；用多套方案前先关 Steam 云存档；
* 如果以后 `YAFSML.ini` 又改回 `.sl2`，工具按新配置走；旧 `.cnv` 槽不会自动改回去（要的话从 `_回收` 拿）。
