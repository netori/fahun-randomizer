# 敌人随机重制 · v1 实施计划

> 上游：`docs/敌人随机_分类与平衡_设计v0.md`（分类与平衡口径）、`docs/参考实现_thefifthmatt_设计拆解.md`（要抄的机制）、`docs/敌人随机_重制交底.md`（上次为什么失败）。
> 本文只回答一件事：**这版做什么、按什么顺序做、每步怎么算过。**

## 0. v1 是什么 / 不是什么

**是**：让随机后的游戏"看得出来是随机的，而且是对的"——敌人换了外形和种类、数值按位置对齐、东西写在方案层、事后能证明它真的生效了。
**不是**：BGM/掉落/地图覆盖/.rpreset 分享（见 §7）。血条名已做（v1.2 第一半，见 M2 报告 §7.10）；多阶段整组替换已做**可选开关**（v1.1，5 组，见 §M1.1）。

一句话判据：**关掉方案层 → 敌人全变回原样；打开 → 全变且没有一个位置半换。**

---

## 1. 用户看到的产出

1. 敌人页勾选池（楔石 / 追忆 / 圣龛 / 传送门 / 普通怪按类 / 野外精英…），每行带影响面与默认开关。
2. 「预览」→ 一份人可读清单：每个位置 原敌人 → 新敌人、系数、以及**没换的位置与原因**。
3. 「部署」→ 写进 `方案/<label>/mod/`，并在面板上给一张**结果表**（不是"完成"两个字）：写了多少、多少通过读回校验、多少被跳过、为什么。
4. 「校验」→ 任何时刻可重跑，结论可复现（同选项同种子同结果）。

## 2. 五条纪律 → 在代码里长什么样（不是口号，是机制）

| 上次的病 | 这次的机制 | 违反时会怎样 |
|---|---|---|
| 身份没有唯一所有者（5,045/7,740 错位） | plan 里每个 part 带 `owner`（visual / stats / scale / name / bgm）；writer 只改自己 owner 的字段，遇到别人的 part **`raise`** | 直接失败并指出两方，不写半成品 |
| 验收装在写入端（`ok: True` 无条件） | 成功 = **独立读回产物**断言：目标字段变了 ∧ 非目标字段零 diff | 断言不过 = 本次部署作废并回滚 |
| 语义靠猜（unkillable/size/isSoulGetByBoss） | `docs/敌人随机_假设台账.md`：假设 / 证据 / 置信度 / **一条能跑的反例检查**；代码引用台账条目 id | 台账没有的语义结论不许进代码 |
| 静默降级（64.9% 被 skip 没人知道） | 默认**整次 abort**；skip 必须带 reason 进结果表；skip 比例 >2% 直接 abort | 面板上写"为什么没换"，不写"完成" |
| 一次铺满八件事 | 一次只开一条能力；v1 只开"换人 + 数值对齐" | 新能力必须独立开关、独立验收 |

### M1 计划层（纯函数，零 IO）—— 已完成（2026-10-20）
逐项说明见 `docs/敌人随机_M1_计划层报告.md`（规则怎么写、百分比怎么调、传送门 26 个守门位换成谁）。
产出：`investigation/apply/enemy_plan.py`（约 600 行，纯函数 + CLI）
- `build_plan(data, options, seed) → plan.json`：每个位置 `{map, entity_id, old_npc_id, new_npc_id, owner, coef_hp, coef_soul, reason}`。
- `--seed` 派生：`seed = hash(逻辑选项串 + 分类表内容哈希)`，**输出路径等无关项不进种子**（照参考实现 logicless 的做法）。
- `--show` 打印人可读清单（原 → 新、系数、跳过原因）。
- 顺带产出**负向账本**：这次所有"没换"的位置 + 原因。
- **替换单位 = 物理位置，不是行**：同 `link` 组的两行必须进同一个替换单元（一起换或一起不换），否则同一地点从「打开 / 封印」两种状态进会看到两只不同的敌人。
- **多阶段组默认整组跳过**：yaml 里 14 组 / 29 个位置默认全 keep，计划层不得对其任何一个单独出替换；只有显式打开 v1.1 的「整组替换」才处理其中 5 个无 pair 的组（见 §M1.1）。
- **池成员按 (map, entity) 认**：同一个模型在池外位置照常随机（例：c3805 密契女猎手既是法姆亚兹拉 Boss，又在 Bellum Highway 守过传送门）。

**规则矩阵（2026-10-20 追加，用户要求「任意种类随任意种类 + 不同百分比 + 某类 Boss 随全种类 Boss」）**

候选范围不再写死「同 silo」，改由 `enemy_classes_v3.yaml` 的 `randomization.rules` 决定（有序表，第一条命中生效）：

| 规则 | 命中 | 百分比 | 目标类 | 区域 |
|---|---|---|---|---|
| `multiphase_boss` | 多阶段组（v1.1，默认关） | 100% | Boss 六类 + Helper（整组一对一阶段） | 任意 |
| `waygate_guardian` | 属于传送门池的位置 | 100% | Boss / MinorBoss / Miniboss / NightMiniboss / DragonMiniboss | 同区域 |
| `boss_any` | Boss 六类 | 100% | Boss 六类（互相） | 同区域 |
| `fauna` | Basic / Wildlife / Mob | 100% | Basic / Wildlife / Mob（三族互换） | 同区域 |
| `scarab` | Scarab | 100% | Scarab | 同区域 |
| `caravan_troll` | CaravanTroll | 100% | CaravanTroll | 同区域 |

- 规则字段：`match{cls,pools,area,tier,bar,multiphase}` / `rate` / `targets{cls,areas,tier,pools}` / 规则级 `size_max` `hp_band`（可选）。`targets.cls: "all"` = 任意类；`targets.areas` = `same` / `any` / 显式列表。
- **难度守恒不靠候选筛选，靠"写盘时用位置原值"**：每个替换单元输出 `target_hp` / `target_soul` = 该位置原本的 hp/魂，M2 把它们直接写进「为这个位置克隆的 NpcParam 行」。所以候选是谁都不影响换完的强度（实测逐单元断言 0 漂移）；`coef_hp`/`coef_soul` 只作记录。`hp_band` 默认关，想收窄候选范围时才加。
- **`default_rate: 0.0`**：没命中任何规则的位置保持原样（新增规则才会改变它），这条让「加规则只影响它管的那些位置」成为可验证的性质。
- 逐类百分比：`rates.by_class` / `rates.by_silo` 是**绝对覆盖**（覆盖规则给的基数），`rates.multiplier` 是全局倍率。三者都**不进种子** —— 改百分比不会把整张地图重排。
- 上限不设下限：`size_max` 只挡「小位置塞巨物」，允许大位置放小怪（参考实现同样只做上限）。
- 池开关与规则是两套开关：**池先判**（全关 = 该位置保持原样），规则后定来源；池是并集语义（一个位置同时属楔石与追忆时，关掉一个仍随机）。

### M1.1 多阶段 Boss 整组替换（v1.1，可选，2026-10-21 夜）

用户 2026-10-21 晚要求继续推进。多阶段是 v1 里唯一「知道该换、但不敢换」的一块。做法不是 `RemoveGroup` 组手术，而是**把整组阶段当一个单位互换**：一阶段换一阶段、二阶段换二阶段，阶段顺序、实体 ID、换阶段事件都不动，只改每阶段的身份（model/npc/think/chara）；hp/魂仍按该阶段位置原值写克隆行。

- 开关：CLI `--mp-swap`，或 GUI v1 卡片勾「多阶段 Boss 整组替换（实验）」。**默认关**；关着时计划与 v1.3 逐字节一致。
- 只对 yaml 里 `kind: phase` 且 `swap: true` 的 5 组生效：蕾娜菈（m14）、拉卡德（m16）、达格拉夫（m17）、拉达冈（m19）、玛莲妮亚（m15）。
- 4 个有 `CreateReferredDamagePair` 的组（葛孚雷 / 玛利喀斯 / 拉塔恩 / 火焰巨人）**不开**：pair 是 2026-10-21 安塞尔河坏档的根因，整组换会重演。
- 配对规则：阶段数必须相同；逐阶段过体型上限与「模型必须不同」；尽量不让多个目标组换到同一组（体型上限让 5 组最多凑出 4 个不同捐赠者 → 「尽量不同」，实测 4 不同 + 1 重复）。
- 数据闸门（`enemy_data_build --check` ⑤b）：swap=true 的组必须 kind=phase、成员必须全 keep、任何阶段带 `pair` 就 FAIL。
- 计划闸门（`enemy_plan --check`）：组内阶段序号连续、同一捐赠组、逐阶段换入 = 捐赠组对应阶段；未开开关时 29 个位置仍必须零替换。
- 自检第 ⑩ 条：打开后 5 组 10 个阶段整组换掉、其它单元一个字节不变；关着时与默认计划一致。
- 实测（seed=1，`--mp-swap`）：计划 **22,671 单元 / 24,638 位置**，规则命中 `multiphase_boss=10`；捐赠映射 `daergraf→malenia / malenia→rennala / radagon_eldenbeast→malenia / rennala→daergraf / rykard_serpent→radagon_eldenbeast`（4 个不同捐赠组）。
- **风险（实验性，必须实机验）**：这 5 组的阶段切换仍有 `ForceAnimationPlayback`（20000/20002/30000…），换模型后动画可能对不上；阶段事件按实体 ID 工作，所以不会因为换 npc 而断链。若出现「打到一半卡住 / 不换阶段 / T-pose」，把开关关掉重部署即回到 v1.3 行为。
- 已写出独立层 `实验_多阶段_seed1`（不覆盖 `敌人v1_seed1`）：498 张图 / 24,638 个位置 / 650 个文件 / NpcParam 20,537 条克隆（regulation 7,830→28,367 行）/ 血条名 150 图 188 位置 200 处指令；`--verify` PASS、`--reseal` 已记基线、`enemy_gate --offline` PASS。GUI「用这个方案玩」按 mtime 挑最新一层，所以请确认提示里的层名。

**实现路径已探明（2026-10-21 凌晨，比原计划省一个 EMEVD）**：

| 发现 | 证据 |
|---|---|
| 不需要 EMEVD 挂 SpEffect | `NpcParam` 自带 **`spEffectID0`..`spEffectID31`（32 个槽）**，永久生效；克隆行是这个位置独有的，往空槽写一个 SpEffect 行即可 |
| SpEffect 有现成的乘数字段 | `physicsAttackPowerRate` / `magicAttackPowerRate` / `fireAttackPowerRate` / `thunderAttackPowerRate`、`physicsDiffenceRate` 等四系、`toughnessDamageCutRate`、`saReceiveDamageRate`、`soulRate`；paramdef 907 B/行、表内 16,086 行 |
| 1.0 = 基准（安全） | 全表统计：这些倍率字段 `1.0` 占 15,532–16,080 行，`0` 只有 2–4 行（个别特例），法魂自己的圣龛变体 SpEffect 18781/18785/18789 与 3450 全部是 **1.0** → 从一条全 1.0 的模板行克隆再改，默认不会把伤害清零 |
| 防御可以更省：直接抄字段 | `NpcParam` 有 `def_phys/def_slash/def_blow/def_thrust/def_mag/def_fire/def_thunder/def_dark`、`slashGuardCutRate`…、`neutralDamageCutRate` 等具体数值 —— 克隆行可以从"这个位置原本那只"整组抄过来，**精确、不用 clamp、不用 SpEffect** |

**攻击缩放的结论（2026-10-21 实测后确定）**：NpcParam 里确实**没有"攻击力"标量**（伤害在 AtkParam 与 TAE 的招式里，按模型不可归属），但本体用 `spEffectID3` 的 5 档缩放**同时乘攻击与血量** —— 所以攻击缩放不需要代理基准：把克隆行的档位对齐位置原档即可，攻击、血量、防御、耐力、抗性一次性落到原位置的水平。原方案的三选 (a)/(b)/(c) 全部作废。

验收判据：
1. 读回：每条克隆行的 `spEffectID3` 等于**位置原行**的档位（`--verify` 已逐条检查）。
2. 禁令检查：本阶段对**共享** NpcParam 行的写入次数 = 0（只写克隆行）。
3. 端到端：同一位置 M2 后与 M4 后，克隆行的 `hp`/`getSoul` 逐字节一致（缩放只动档位槽）。
4. 血量守恒：克隆行的最终血量 = 位置原基数 × 位置原档 hp 倍率（= 原位置实际血量），45.3% 的旧错配归零。

## 8. 风险与回滚

| 风险 | 触发信号 | 处置 |
|---|---|---|
| id 对齐率低 → 分类错 | M0 报告命中率 <80% | 停下来先做对齐，不硬推 |
| 换入类型不可击杀 → 卡关 | M3 传送门自检不过 | 整体回滚，该位置退回原敌人 |
| 攻击/防御缩放过头（0.6/2.5 clamp 仍不适） | 试玩反馈 | 系数进配置，可调，不重编 |
| 方案层没生效（老病） | YAFSML.log override 条数 ≠ 写集 | 不报成功，直接失败 |

回滚点：`方案/<label>` 是整目录替换（`enemy_write` 写完才换、旧目录改名 `.old_<ts>` 后再删），所以"回上一版"= 把 `YAFSML.ini` 的 `Plan=` 指回上一层、或让 `plan_layer.py --deactivate` 关掉方案层；闸门 `enemy_gate.py` 只读，不负责回滚。
