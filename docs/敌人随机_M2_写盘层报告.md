## 3. 一个位置被换时，到底改了哪些字节

MSB 里那个 part 的 6 个字段（照参考实现 `EldenEnemyEditor.TransplantEnemy`）：

| 字段 | 写成 | 为什么 |
|---|---|---|
| `ModelIndex` | 新模型的下标（必要时先往 `MODEL_PARAM_ST` 追加 `cXXXX` + sib 路径） | 决定"长什么样" |
| `typeData+0x0C NPCParamID` | 该位置**独有克隆行**的 id | 决定血量/魂/掉落 |
| `typeData+0x08 ThinkParamID` | 捐赠者的 think（杂兵→Boss 时用克隆 think） | 决定 AI |
| `typeData+0x18 CharaInitID` | 捐赠者 chara | 决定装备/动作表 |
| `typeData+0x15 UnkT15` | `false` | 参考实现同款（历史"外观不生效"的一个候选位） |
| `typeData+0x38 BackupEventAnimID` | `-1` | 参考实现同款；不清会让旧 Boss 的出场动作套到新模型上 |

**不动**：part 名字、EntityID、实体分组、坐标、朝向、碰撞 part —— 所以 EMEVD 里按实体 ID 写的逻辑（传送门开锁、Boss 血条、BGM）仍然指向"这个位置"。

## 4. 20,530 条克隆行是什么

同一 (捐赠者, 目标 hp, 目标魂, 换向, 位置原威胁等级, **位置原行**) 的所有位置**共用一行**，所以 22,661 个单元落成 20,530 行（涉及约 2,260 个捐赠者行；复用极不均，`61000010` 被 337 个位置用、`61000020` 318 个、`60010010` 313 个）。键里带「位置原行」是 M4 第一半：**防御与掉落必须跟着位置走**，同一只 Boss 在不同位置的克隆行不能共用（§7.8）；键里还带「位置原档位」，克隆行的 `spEffectID3` 按位置原档写，攻击/血量倍率才对得上（§7.9）。

id 分配：从捐赠者 id 往后找第一个空位，且全局不重号 → 新 id 落在 10001001..523940001。行名 `gfE:<捐赠者>:<hp>:<魂>:<换向>:t<威胁>:p<原行>`，重跑时按前缀 `gfE:` 先删旧克隆行，所以**幂等**。

必改项（相对 paramdef 偏移，运行时从 `paramdef` 现算，不写死）：

| 字段 | 改法 | 依据 |
|---|---|---|
| `hp` @36 / `getSoul` @44 | = 这个位置原本的值 | 难度守恒（§5） |
| `isSoulGetByBoss`（byte349 bit0） | 清 0 | 参考实现同款；否则魂量结算方式不对 |
| `disableInitializeDead`（byte333 bit3） | 杂兵→Boss 置 1；Boss→杂兵清 0 | 参考实现 `bossAsBasic`/`basicAsBoss` |
| `disableRespawn`（byte332 bit1） | 清 0 | 同上 |
| `threatLv` @352 | 为 0 则置 1 | 参考实现同款 |
| `teamType` @307 | 捐赠者属于杂兵六类时置 6 | 参考实现 `InitialNpcPass` |
| `hitRadius` @24 / `hitHeight` @20 | 夹到 ≤2.5 / ≤5.1（幽影树化身 3 行跳过） | 参考实现 `ShrinkNpc`；大模型换进小位置时防"打不到" |

**没有**逐字段白名单黑名单 —— 复制行 = 整行照抄，只列必改项。"哪些字段要保持原样"由"照抄"这个默认行为保证，不靠一份永远漏项的清单（上一版就死在 `SAFE_KEEP_FIELDS` 漏项上）。

## 5. 为什么这样能难度守恒

换入谁都不影响换完的强度：每个位置的 `hp`/`getSoul` 直接写成**这个位置原本那只敌人**的值（`target_hp`/`target_soul`，M1 就算好了），不是"乘一个被 clamp 的系数"。

- 旧做法（系数 + clamp 0.6–2.5）实测 31% 的位置偏离 >2 倍、最坏 68 倍 —— 因为 clamp 卡的是倍率，不是结果。
- 现在：逐单元断言 `写出的 hp == 位置原值`，22,672 个单元**零漂移**（最大差 9.9e-07，来自 JSON round）。candidate 是谁只影响"长什么样、什么 AI"，不影响"多强"。
- `coef_hp`/`coef_soul` 仍记在计划里，只作观感参考，不参与写入。

## 6. 安全网

| 机制 | 行为 |
|---|---|
| owner 校验 | 一个 (map, part, occurrence) 只能有一个写者；冲突 **在任何写盘之前** raise。`--selftest` 注入重复单元验证：抛错 + 目标目录不存在 |

### 7.3 野外 Boss 大血条消失：threatLv 被换掉了（2026-10-21 凌晨，已重建并复验）

玩家反馈：宁姆格福大树守卫（`m60_41_51_00` / 实体 `1041510800`）的位置换成了「亚人剑圣」翁吉，**没有大血条**；并怀疑"野外 Boss 的大血条是不是全没了"。

定位（全部实测）：

- 血条不是 `NpcParam` 的字段（315 个字段里只有 `isSoulGetByBoss` 与 boss 沾边），是 EMEVD 给的。野外 Boss 走 `common_func.emevd.dcx` 的模板 `$Event(90005870, ...)`：`WaitFor(CharacterAIState(X0_4, Combat) && FieldBattleBGMActive(X8_4) && !EventFlag(9000))` 通过后才 `DisplayBossHealthBar(Enabled, X0_4, 0, X4_4)`。
- 地图侧调用形如 `InitializeCommonEvent(0, 90005870, <实体>, <血条名>, <threatLv>)`。EMEDF 里这条指令是 `IF Field Battle BGM Active`，第三参数类型叫 **NPC Threat Level**（0..99），就是 `NpcParam.threatLv`。
- 扫 267 个 `event/*.js` 再**剔掉注释掉的旧调用**后，41 个在用的 90005870 调用点里 **38 个**的第三参数与"位置原 npc 的 `threatLv`"完全相等（剩 3 个的实体在位置表里查不到）→ 可以当定律用。
- 我们的克隆行整行照抄捐赠者，`threatLv` 也跟着捐赠者（绝大多数是 1）；于是条件变成 `FieldBattleBGMActive(12)`（大树守卫的等级）在等一个永远不会播的 BGM → 大血条永不出现、BGM 也变调。传奇怪/地牢 Boss 用的是地图事件里字面量的 `DisplayBossHealthBar`（如 `m10_00_00_00` 葛瑞克），不受影响 —— 这正是玩家看到的"地牢 Boss 有、野外 Boss 没有"。

修法（`investigation/apply/enemy_write.py`，不动 EMEVD）：

| 改动 | 说明 |
|---|---|
| 克隆行去重键加第五维 `old_threat` | 同一 donor + hp + 魂，但"位置原本的威胁等级"不同 → 拆成两条克隆行 |
| `make_npc_clone` 写回 `threatLv` | 用**这个位置原本那只**的 `threatLv`；原值为 0 才退回捐赠者的值 |
| `--verify` 新增检查 | 每条克隆行的 `threatLv` 必须等于位置原值（从 manifest 的第五维读） |

重建后：克隆行 18,895 → **18,913**，NpcParam 7,830 → **26,743** 行，`--verify PASS`（含新检查）、`--reseal` 已记 497 张图新指纹；15,023/22,672 个单元有可用的原 `threatLv`。

### 7.4 同一个问题的第二层：把模板里的 BGM 判定删掉（2026-10-21 凌晨，已落地）

`threatLv` 是"让引擎播对 BGM、血条条件成立"的第一步，但它还依赖引擎真的按模型→BGM 映射播那个等级。参考实现干脆**不依赖 BGM**：`diste/Base/events.txt:13208` 的模板 90005870 带 `Removes:`，第一条就是 `- IfFieldBattleBgmActive`。

本轮把这层也补上了（新增 `investigation/apply/evd_edit.py`，自己实现 EMEVD 容器读写，不依赖 soulstruct）：

| 项 | 实测 |
|---|---|
| 容器格式 | 头 16B + 16 个 u64 字段；事件表 48B/条；指令表 32B/条（`cat u32, idx u32, args_size u64, args_local_off i64, layers i64`）；参数在共享区 |
| 不变量 | 4 份文件（common_func + 3 张地图 event）"解析→原样重建"逐字节一致；删指令后 5 条结构不变量仍成立 |
| 处理方式 | **不删指令**：把 6 条 `IF Field Battle BGM Active`（类 3 指令 33）的"结果条件组"改成一个本事件不用的组（15）—— 条件还在、结构不动、不再影响主组；明文 543,728 → 543,800 字节（6 条 × 12 B 追加参数区） |
| 其余事件 | 291 个事件逐条指令一致（零漂移） |
| 写盘集成 | 层里新增 `event/common_func.emevd.dcx`，进 manifest 的 files（参与 sha256）；`--verify` 里用 `evd_edit.verify_patch` 复验同一件事 |

**踩过的坑（重要，别走回头路）**：第一版是**直接删**这 6 条指令。结构校验全过（指令表左移、其余事件逐条一致、日志 0 ERROR），但实机**仍然没有大血条**。根因是 EMEVD 的 **arg 替换表按"指令下标"索引**（每条记录 32 B，首 u32 是事件内指令号）：删掉一条指令后，该事件后续所有替换记录都指错指令，`X0_4`/`X4_4`/`X8_4`（实体 / 血条名 / 威胁等级）被写进了别的指令的参数里 —— 例如 `DisplayBossHealthBar` 的替换落到了后面的 `SKIP IF Player Is In World Type` 上，血条调用自己被跳过。`evd_edit` 现在改成 **neutralize**：只改那 6 条指令的首 4 字节（条件组 1/2/4 → 15），指令数、指令表、arg 替换表全部不动。

重建后：写集 497 → **499 个文件**（+common_func），层里 regulation 仍 26,743 行、克隆行 18,913；`--verify PASS`（地图 497 + common_func + regulation 全过），`--reseal` 已记新基线。

两层的分工：`threatLv` 让 BGM 与原 Boss 一致（听感），删 BGM 判定让血条**不再依赖** BGM（可靠性）。只做前者在 BGM id 对不上时仍会丢血条；只做后者血条会回来但 BGM 可能变调——两个都做才稳。

### 7.7 传送类敌人：从「禁当来源」升级为「换掉战斗 AI」（2026-10-21，实验性，待实机验证）

### 7.8 M4 第一半：防御与掉落按「这个位置原本那只」对齐（2026-10-21，已重建并复验）

### 7.9 M4 第二半：攻击与血量倍率按「本体的 5 档等级缩放」对齐（2026-10-21，已重建并复验）

**起因**：用户 m06382「战斗力要缩，但要合理些」。`NpcParam` 里没有"攻击力"这个标量（伤害在 AtkParam 与 TAE 的招式里，按模型不可归属），原计划只能三选 (a) 不做 / (b) 用 hp·魂复合分当代理乘 SpEffect / (c) 等采样。实测发现第三条路：**本体自己就有 5 档等级缩放**，攻击和血量是同一套倍率。

**机制（读 baseline 实测）**：`NpcParam.spEffectID3` 指向 `SpEffectParam` 的 7000/7010/7020/7030/7040 之一，每档同时乘 hp、攻击、防御、耐力、抗性：

| 档 | hp 倍率 | 攻击倍率 | 防御倍率 | 全表行数 |
|---|---|---|---|---|
| 7000 | ×2.6951 | ×1.6901 | ×1.0 | 20 |
| 7010 | ×3.3403 | ×1.9130 | ×1.0181 | 807 |
| 7020 | ×3.9855 | ×2.1359 | ×1.0362 | 554 |
| 7030 | ×4.6306 | ×2.3588 | ×1.0543 | 268 |
| 7040 | ×5.2758 | ×2.5817 | ×1.0723 | 399 |

全表 7,830 行里只有 **2,049 行**有档；具名 Boss 多数**没有**（玛尔基特 21300000 / 葛瑞克 47500014 / 大树守卫 32510030 / 翁吉 46900008 = None），熔岩土龙 49100026 = 7020（hp 2968 是基础值，实机 ×3.9855 ≈ 11,830）。

**为什么必须修**：克隆行整行照抄 = 连捐赠者的档位一起继承，但 hp/防御写的是**位置原值** → 实际血量 = 位置基数 × **捐赠者**档位倍率。实测 **10,280 / 22,671 = 45.3%** 的替换单元血量倍率与原位置不一致（例：原 7020 的位置换成无档的 c3650 → 血量少 4 倍；反向则多 4 倍）。攻击同理：A_orig/A_donor 落在 **0.387–2.582**，按对齐会有 5,038 个单元缩、5,242 个增、12,391 个不变 —— 用户要的「缩」正是 7030/7040 捐赠者落到低档位那批。

**改法**（都在 `enemy_write.py`）：

| 项 | 改法 |
|---|---|
| 克隆行 | `spEffectID3` 写成**位置原行的值**（原行没有就清 0）；不新建 SpEffect 行、不用 clamp、不用代理 |
| 克隆键 | 加第 7 维 `old_scale` → 同一捐赠者落到不同档次的位置不再共用克隆行 |
| 复验 | `--verify` 逐条断言克隆行 `spEffectID3 == 位置原档` |
| 行名 | 末尾加 `:e<档>`，便于人工抽查 |
| 版本 | `WRITE_VERSION` 2 → 3 |

**实测（2026-10-21 14:0x 重建）**：**19,399 / 22,671** 个替换单元把档位换成了位置原档（原位置有档的 18,263 个单元）；克隆行仍 20,529 条（第 7 维没有额外拆分，说明档位与位置原行一一对应）、NpcParam 仍 28,359 行、写盘 91 s；`--verify` PASS（新增档位断言）。

**语义**：最终数值 = 位置原基数 × 位置原档倍率 = **原位置的实际强度**。高档次捐赠者落到低档位 = 血量与伤害一起回落到原档（这就是"缩"）；反过来低档位捐赠者进高档次位置 = 补上原档倍率（不是无脑削弱）。全部复用本体数值，零调参、零 clamp。

### 7.11 实机反馈之三：安塞尔河坏档 / 禁域没 AI / 部分 Boss 名字没换（2026-10-21 晚，已重建并复验）

**用户原文（m07124）**：「首先一部分随后的boss没换名字，其次禁域的黄金树传送门那里随了个玛尔基特，没AI，最后也是最致命的，地底世界的安塞尔河的黄金树传送门传过去就崩了，然后坏档了」

**根因一：被 EMEVD 脚本绑死的实体不能换模型。** 位置表新增 `evt` 列（扫 267 份地图 EMEVD 得到）：

| 标记 | 指令 | 为什么不能换 | 实测后果 |
|---|---|---|---|
| `pair` | `CreateReferredDamagePair(a,b)` | 两只实体是坐骑/受击绑定对，只换一只或换成非坐骑模型 → 引擎按配对关系生成失败 | **安塞尔河 m12_01 传送门**：12010805（诺克斯修士）+12010806（Giant Ant）被换成塔兰 + Commoner → 读档 0xc0000005（offset 0x3c8e22，两次同偏移），存档正好在这张图 → 看起来像"坏档" |
| `anim` | `ForceAnimationPlayback(实体, 动画)` | 脚本给这只实体强制播待机/起身/阶段动画；换模型后动画槽对不上 → AI 不起 | **禁域 m60_49_52 传送门**：守卫被换成玛尔基特，脚本播 30000（休眠）/20000（起身）→ 站着不动、没 AI |
| `copy` | `CopyPlayerCharacterData(10000, 实体)` | 外观被事件改成玩家，换模型看不到 | 拟态泪本体（已按 keep_places 处理） |
| `aiid` | `SetCharacterAIId(实体, AI)` | AI 被脚本换成特定行为树，换模型后行为可能不匹配 | 与 copy 同位置 |

扫描结果：**420 个 (map,entity) 被绑定 → 位置表命中 232 行**（anim 219 / pair 31 / copy 1 / aiid 3），全部 `policy=keep`（`reason=evt:…`）。`enemy_data_build --check` 新增第 1c 组校验：`evt` 列必须与磁盘 EMEVD 现算一致。

**根因二：血条位置换进了"没有血条名"的模型。** 血条名字是位置 EMEVD 里的 Name ID 字面量，换入模型没有名字时只能保留原名 → 用户看到"Boss 没换名字"。修法两条：
1. `constraints.require_named_donor_for_bar=True`（默认开）：`bar=1` 的位置只从 `enemy_bar_names.csv` 里有名字的模型里抽候选（无候选进负向账本 `no_candidate:no_bar_name`）。
2. `bar_names.targets_for_map` 名字优先级改为 **捐赠位置自己的血条名 > 模型主名**（同一个模型在不同图里叫法不同，用捐赠位那份更贴合）。

**anim 的粒度问题（第一版修过头了）**：一开始把 `evt` 非空一律 keep，结果 232 行被保护，其中 **55 个 Boss + 32 个 MinorBoss**（葛瑞克、恶兆王、蒙格、龙王、玛利喀斯……）都被排除出随机 —— 它们的入场/死亡动画同样被脚本点名，但换模型并不会让 AI 失效。最终规则：

| evt | 是否 keep | 理由 |
|---|---|---|
| `pair` | **是** | 坐骑/受击绑定对，只换一只或换成非坐骑模型 → 加载/生成崩溃（安塞尔河） |

### 7.12 名字没换全的两个漏口（2026-10-21 晚，已重建并复验）

用户 m07737：「目前还有一些boss名字没换过来，其他问题都没有了」。查下来是两类，都不是写盘逻辑错，而是"名字源"没覆盖全：

1. **同一位置有多个旧名字 ID**。`enemy_bar_names.csv` 里 10 个 (map,entity) 各有 2 个 name_id（不同显示路径 / boss_healthbar 的别名），旧代码用 `setdefault` 只取第一个，另一条路径仍显示原 Boss 名。

**重建实测**：计划数字不变（22,661 单元 / 24,628 位置）；血条名 **148 图 / 178 位置 / 188 处指令 / 0 个保原名**；层 **647 文件**（497 图 + 148 event + regulation + manifest）；`--verify` PASS（含 148 图逐图重算）、`--reseal` 497 图、`enemy_gate --offline` PASS（647/647、23 守门位 / 22 条克隆）。

### 7.13 v1.1 多阶段 Boss 整组替换（可选，独立层，2026-10-21 晚）

**做什么**：把一整组多阶段 Boss 当一个单位互换 —— 一阶段换一阶段、二阶段换二阶段；阶段顺序、实体 ID、换阶段事件都不动，只改每阶段身份（model/npc/think/chara），hp/魂仍写该阶段位置原值。

| 项 | 内容 |
|---|---|
| 开关 | yaml `multiphase.groups[*].kind/swap` + 计划选项 `constraints.multiphase_swap`（默认关；CLI `--mp-swap`，GUI 复选框） |

| 计划闸门 | 整组一致性：阶段数、同一 `donor_group`、逐阶段 new_npc/new_model 对齐；任一阶段 evt 含 pair 直接 FAIL |
| 自检 | 第 ⑩ 条：默认关时 29 位置零替换；打开后 5 组 10 阶段整组换、阶段序号连续、同一捐赠组，其它单元零变化 |

**实测（seed=1）**：`--mp-swap` 计划 22,671 单元 / 24,638 位置（数量不变，10 个多阶段位置从 keep 变成替换）；独立层 `方案\实验_多阶段_seed1`：498 张图 / **650 文件**；NpcParam 7,830→**28,367**（+20,537 克隆）/ NpcThinkParam +23；血条名 **150 图 / 188 位置 / 200 处指令**；`--verify PASS`、`--reseal` 498 图、`enemy_gate --offline PASS`（650/650）。

**风险（已知）**：阶段切换事件里还有 `ForceAnimationPlayback`，换模型后阶段动画可能对不上；出现卡阶段/T-pose 就关掉开关重新部署。所以默认关。

### 7.15 v1.4 可选（实验）：敌人倍增 Enemy Onslaught（2026-10-22 凌晨）

参考实现的 Enemy Onslaught 会复制敌人实体并重写事件；本节做的是**低风险子集**：只复制**普通敌人**（Basic / Wildlife / Mob / Scarab）的 MSB part，不动 EMEVD、不复制事件、不复制旧的 NpcParam 行 —— 复制体沿用同一个克隆行（数值、掉落、颜色与原位置换入者完全一致），只分配新的 EntityID / PartID / InstanceID，并把坐标偏移 2.5m。

| 项 | 内容 |
|---|---|
| 开关 | 计划选项 `features.onslaught`（默认 **1.0 = 关**；1.5 ≈ +50%，2.0 = +100%，硬上限 3.0）；GUI v1 卡片滑块 1.0–2.0；CLI `--onslaught` |
| 复制谁 | 只复制 `cls ∈ {Basic, Wildlife, Mob, Scarab}` 且 policy=randomize 的位置 |
| 不复制谁 | 手动指定 / 特殊池 / 有血条 / 有事件绑定 / link 副本组 / Boss 与六类 boss 级 / 多阶段 / `c0000` / think≤0 / hp≤0 / entity_id=0 / part 名含 Sound |
| 复制体 | 新 EntityID 与 PartID/InstanceID 都从该图当前最大值 +1 起；坐标按 `2π(j+1)/n+0.6` 偏移 2.5m；其余 part 字段照抄 |
| 统计 | 2.0× 计划：**5,391 个普通敌人位各 +1（共 5,391 只）**；默认 1.0 时 0 只 |
| 验证 | 2 图测试层：m10_00_00_00 9,151 part（复制 136）、m10_01_00_00 3,588 part（复制 5）；`--verify` PASS（逐个复制体核对 entity/npc/think/model/坐标） |

**踩过的坑**：EntityID 是 u32，`0xFFFFFFFF` 是「无实体」哨兵；第一版直接 `max(entity_id)+1`，遇到哨兵就 `struct.pack_into("<I", ...)` 溢出（`'I' format requires 0 <= number <= 4294967295`）。现在只统计 `0 < id < 0xFFFFFF00` 的实体，并给 `next_ent` 兜底，避开哨兵区。

### 7.18 多阶段 Boss 血量：照参考实现的 5 组修正 + 法魂放宽 clamp（2026-10-22 14:1x / 15:2x）

**做什么**：多阶段 Boss 的血量不是「总血量守恒后按比例分」，参考实现（SoulsRandomizers / thefifthmatt，`EldenEnemyEditor.cs:961-1018`）只对 5 组 Boss 做硬编码的 p1/p2 血量修正。本轮把这 5 组的公式照抄进写盘层（`enemy_write.apply_phase_pair_fixes`），直接改 NpcParam 里那两行的 `hp` 字段；绝对 HP 不抄，全部从当前法魂 `NpcParam` 读取后重算。**法魂放宽**：参考原版 p2 clamp 是 `500..5000`，用户 2026-10-22 15:1x 同意放宽到 `500..6000`，只让火焰巨人的 5045 生效；计划/种子不动。

| 组 | 实体 / NpcParam 行 | 公式（p1=一阶段，p2=二阶段；clamp 法魂 500..6000，参考原版 500..5000） | 本次实测 |
|---|---|---|---|
| 荷莱露 | 11050801/47200070、11050800/47210070 | p2 = p2 - p1；clamp 500..6000（法魂） | p1 1721 不变；p2 4396 → **2675** |
| 玛利喀斯 | 13000801/21100072、13000800/21101072 | p1 = p1×45%；p2 = p2 - p1；clamp | p1 1906 → **857**；p2 1906 → **1049** |
| 火焰巨人 | 1052520801/47600050、1052520800/47601050 | p2 = (p2-p1)×90%；clamp 500..6000（法魂） | (9095-3489)×90% = **5045**，在法魂放宽后的 6000 以内，**写入 5045**（参考原版 5000 会保持 9095） |
| 梅瑟莫 | 21010801/51300099、21010800/51301099 | p1 = p1×50%；p2 = p2-p1；clamp | p1 2963 → **1481**；p2 2963 → **1482** |
| 拉达冈/艾尔登之兽 | 20010801/52200089、20010800/52201089 | p1 = p1×35%；p2 = p2-p1；clamp | p1 3168 → **1108**；p2 3168 → **2060** |

- **不是把参考实现的绝对 HP 抄过来**：`PHASE_PAIR_FIXES` 里只有实体/NpcParam id、模式和百分比，没有写死任何 HP；`apply_phase_pair_fixes` 的 `b1/b2` 全部从**当前法魂层**的 `NpcParam` 读取，再按公式与 clamp 重算。法魂与原版/参考注释的差异正是被这样吃进去的：荷莱露 p2 4396（参考注释 3186）、玛利喀斯 1906/1906（参考注释 1588/1588）、火焰巨人 9095（参考注释 6592）；若照搬参考数值，火焰巨人二阶段会是 ~2792，而不是我们这里算出的 5045。
- 参考实现的 Messmer / PCR 包在 `if (opt["dlc"])` 内；我们按行是否存在执行（本包含 DLC，两行都在）。
- 与参考一致的部分：p1 的百分比写入**无条件**；p2 仍只在 clamp 区间内才写。**法魂放宽**：用户同意把参考原版的 `500 < hp < 5000` 上限放宽到 6000；本包火焰巨人 p2 基数 9095（参考注释 6592），公式结果 5045，参考原版会拒绝，法魂放宽后写入 **5045**。其余组结果都 <5000，不受影响。

### 7.19 区域缩放：换入者整行 + source→target SpEffect（2026-10-22 23:0x 实现，23:3x 主层已挂载）

## 8. 已知限制（v1 先接受）

1. **血条名已跟着换（7.10/7.11/7.12/7.16/7.17），BGM 仍是原 Boss**（H-003/H-019/H-032）：换人后大血条写的是换入者的名字（211 个位置实际改名、223 处指令；含 30 张本体事件兜底图）；换入者没有名字时写占位 `?NpcName?` 或同义中文名，**不再保留原名**（当前计划里那个无名字目标没有独立名字槽，所以实际占位 0 处；逻辑已就位）；但 BGM 还是原位置那首曲子。
2. **攻击/血量按"档位"对齐，不是逐招对齐**：新区域模型最终强度 = 换入者基础面板 × 目标档倍率（source→target；旧主层是位置原基数 × 位置原档倍率，H-030）。同档内不同模型的实际伤害仍取决于它的招式（AtkParam/TAE），所以低档位换进高攻 Boss 时，即使档位对了，单招伤害仍可能偏高——这是"模型的招式设计"，v1 不再往下压。
3. **多阶段 Boss 全 keep**（14 组 29 个位置）：换主体不换阶段会"打到一半变回原样"，v1 整体不动，v1.1 做组手术；血量已按参考实现的 5 组 p1/p2 修正（§7.18），组替换仍默认关。
4. **think 克隆只在杂兵→Boss 时做 22 条**：Boss→杂兵没有对应处理（参考实现的 `bossAsBasic` 也不动 think）。
5. **地图覆盖只限这 497 张**：写集是显式的，没写的图不出现；下次计划变了重写时旧层整体替换（不会残留）。
6. **entity_id=0 的位置也换了**（占 69%）：换的是身份层，不需要实体号；代价是"按实体 ID 干活"的功能（传送门/血条名/BGM）只覆盖有号的位置。
7. **敌人颜色只做了机械验证**：颜色行与克隆行字段已复验，但"游戏里看起来明不明显"取决于模型是否使用该材质槽，尚未实机确认；默认关。
