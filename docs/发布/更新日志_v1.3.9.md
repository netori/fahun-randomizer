# 更新日志 v1.3.9（2026-10-23）

> 这一版只修一个启动判定：**游戏其实早就退了，工具却一直认为「游戏正在运行」，于是每次都弹「关不掉还在跑的游戏」，启动不了**。
> 随机、写盘、方案层、存档逻辑都没改。

## 一、现象

点「用这个方案玩」或双击方案层里的启动 bat：

```
游戏正在运行：要用「…」开局，得先把正在跑的《艾尔登法环》关掉。
现在自动关掉它并启动吗？

… 等 25 秒 … 强制结束 … 再等 10 秒 …

不能启动：关不掉还在跑的游戏 —— 请手动关掉再试
```

但游戏窗口根本没有，YAFSML 日志也停在几小时前；任务管理器/`tasklist` 里却确实有 `eldenring.exe`，
手动 `taskkill /F` 还报 **Access is denied**。

## 二、根因

那些是**已经退出、但进程对象还没被系统收掉的「僵尸壳」**。实测特征：

| 查法 | 结果 |
|---|---|
| 线程数 / 句柄数 | 0 / 0 |
| 工作集 | 32 KB（真正的游戏是 GB 级） |
| `WaitForSingleObject(句柄, 0)` | 立刻返回 signaled（= 已退出） |
| `taskkill /F` | `Access is denied`（对已退出的受保护进程就是会这样） |

旧实现只问一句「`tasklist` 里有没有 `eldenring.exe`」，于是**永远**认为游戏在跑：
先问关游戏 → 等 25 秒 → 强杀（失败）→ 等 10 秒 → 抛「关不掉」。
启动器第一次真能起游戏，就是被这两条残留挡住的。

## 三、修法

| 位置 | 改动 |
|---|---|
| `investigation/apply/gamelib.py` | 新增 `_pid_is_gone(pid)`：打开进程句柄后 `WaitForSingleObject(h, 0) == 0` 就是已退出；`game_pids()` 过滤掉这些壳；新增 `zombie_pids()` 只用于日志；`game_running()` 改成 `bool(game_pids())` |
| `kill_game()` | 只在真有活进程时才动作；残留壳只写进日志（「不影响启动，系统会自己收掉」）；关不掉时的报错补一句：游戏若是管理员身份启动，随机器也要用同样权限 |

判据原则：**读不到句柄（受保护 / 没权限）就按「还在跑」算**，宁可多问一句，也不在游戏真运行时去动存档。

## 四、验证

| 项 | 结果 |
|---|---|
| 真机（本机两个残留壳 pid 2692 / 19736） | 修前 `running=true`、等 35 秒后报关不掉；修后 `running=false`、`zombie_pids()=[2692,19736]` |
| `gamelib.py --selftest` | PASS，新增第 ⑧ 项「僵尸壳不算在跑」（活进程不会被误判、`game_running` 与 `game_pids` 口径一致） |
| `randgui.py --uitest` | PASS，新增一条「进程判定会跳过已退出的残留」 |
| `--plan-off` / `--play` 路径 | 不再被残留壳挡住（`--play` 正常走到换档那一步） |

## 五、注意

- 残留下来的 `eldenring.exe` 条目会由系统自己收掉，**不用手动杀**（也杀不掉）；新版会忽略它们。
- 如果你正开着旧版随机器，请**关掉重开**才会用上新逻辑。
- 如果哪天游戏真的还在跑、而且是以管理员身份启动的：随机器也用管理员身份运行，否则同样会「关不掉」。
