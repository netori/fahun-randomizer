# 更新日志 v1.3.11（2026-10-24）

> 一句话：**GUI 点「开始随机」生成的层，现在自动带 Boss 数值平衡** —— 换进来的 Boss 血量按
> 「这个位置原来那个 Boss 的强度」对齐（0.85~1.25 倍窗口），伤害按位置区域档缩放。
> 以前这套平衡要手工跑两道离线命令才有，现在**出层时自动算**。

---

## 一、为什么改

v1.3.10 之前，数值平衡（分位 LUT 血量 + 伤害口径 A）只是离线脚本：

1. `enemy_plan.py --build` 出计划；
2. `enemy_balance.py --plan ... --out ...` 后处理；
3. `enemy_write.py --plan ...` 建层。

GUI 只跑第 1、3 步 —— 所以 **GUI 随机出来的层没有平衡**。作者实测报「前期 Boss 随到后期血量偏低 /
后期 Boss 随到前期血量巨多」，正是缺这一步。本次把第 2 步搬进写盘层，在**内存里**做，不落中间文件。

## 二、改了什么

### 1）`balance_ref.py`：可以从内存生成参考表

- 新增 `build_from(bnd, places=None, log=None)` —— 吃**已经读进内存的** baseline regulation，
  直接算「档位倍率 / 每行 NPC 自己的档 / 每张地图的兜底档」，返回 dict，不写盘。
- 原 `build(reg, places, out, log)` 变成它的包一层：补 `source.regulation` 与 `sha256` 后写 `investigation/balance_ref.json`
  （离线工具照旧可用）。

### 2）`enemy_write.py`：出层时自动平衡（新增「①.7 Boss 数值平衡」）

- `build()` 在区域缩放之前补一步：
  - 计划里**已经有** `meta.balance` → 直接沿用（上一次离线平衡过的计划）；
  - `features.balance is False` → 跳过（诊断用）；
  - 否则 **现场补算**：从同一份 baseline regulation 读 NpcParam/NpcThinkParam，
    跑 `enemy_balance.apply_to_plan(...)`，默认口径 = 血量分位 LUT（k=10）+ 0.85~1.25 硬夹、伤害 = 位置档缩放。
  - 任何异常只打一行日志「数值平衡跳过（不影响出层）」，**不会**让出层失败。
- **计划快照写的是内存里实际用掉的那一份**（不然快照里 `target_hp` 与层里对不上，复验会报错）。
- `enemy_manifest.json` 的 `features` 加 `balance`，`balance.dmg_model` 记为 `position`。
- 日志多两行，能一眼看出有没有平衡：
  - `[平衡] 245 个 Boss→Boss 单元：KS=… mean …（原 …）`
  - `[写盘] 数值平衡：内存里补算 3.8s`

### 3）`build_exe.py`：把两个新模块打进 exe

`PIPELINE` 列表在 `bar_names.py` 之后加了 `enemy_balance.py`、`balance_ref.py`（少一个，exe 里就 import 不到）。

## 三、口径（没变，只是自动做了）

| 项 | 口径 |
|---|---|
| 有效血量 | `NpcParam.hp × spEffectID3 档的 maxHpRate`（法魂自己的区域加成） |
| 血量 | 位置按「原 Boss 有效血量」排序落 k=10 分位档，种子决定档内抽谁 → 再**硬夹到 0.85~1.25 倍**（相对该位置原版） |
| 伤害 | **位置档缩放**：`dst/src` 的 damage 组倍率，区域缩放比恒 **1.00**（与位置原版一致），不再叠「换入者自己」的派生倍率 |
| 范围 | 只动 Boss→Boss 单元（245 个，含传送门守门位这类「非 Boss→Boss」）；普通杂兵不动 |

> 硬夹是逐位置生效 ⇒ **换任何种子，血量倍率都在 0.85~1.25 内**；种子只决定窗内取哪个值。
> 9 个种子实测：有效血量均值 12,406~12,879（原始池 12,507，±3%）、KS 0.0245~0.0449、逐位置 >1.5× 全 0%。

## 四、验证

- `build_exe.py`：PyInstaller 打包 + **四道隔离自检全 PASS**（`--selftest` / `--planlib` / `--uicheck` / `--uitest`）。
- 端到端 smoke（拿一份**剥掉 balance** 的计划，走 GUI 同一条 `enemy_write.build` 路径）：
  - 日志 `[平衡] 245 个 Boss→Boss 单元：KS=0.0327 … mean 12614（原 12507）`、`数值平衡：内存里补算 3.8s`；
  - 层里区域 SpEffect 402 条（= 402 个唯一 src/dst 组合）、平衡单元 210；
  - manifest `features.balance=true`、`balance.dmg_model=position`；计划快照里 `meta.balance` 与 247 个 `unit.balance` 都在。
- 早前同口径的人工层（方案_物品_敌人_种子_20261024__多阶段_收束A）已**实机跑过 3 分钟+ 无崩溃**，
  退出正常存回槽，见 `docs/敌人随机_数值平衡_20261024.md`。

## 五、升级

直接换 exe 即可（v1.3.10 → v1.3.11 无存档 / 无方案格式变更）。已有方案层不受影响；
**下次点「开始随机」生成的层自动带平衡**。

想关掉平衡（对比实验 / 诊断）：计划里 `features.balance=false`（CLI 侧手工改计划 JSON 或用旧计划快照）。

## 六、边界

- 伤害只校准到「区域缩放」这一层；换入者**招式本身的 raw 伤害**（AtkParam/TAE）差异无法离线量化 —— 那是「这个 Boss 的招式强度」，属于身份特征。
- 多阶段 Boss：pair 绑定 5 组（荷莱露 / 玛利喀斯 / 拉塔恩 / 梅瑟莫 / 火焰巨人）仍不拆；两管血条组按「换模型每阶段各随一个 / 模型不变整场一个」处理（v1.3.10 已有）。
- LUT 的档边界随「参与平衡的位置集合」变 —— 同一份计划两次出层结果一致，但不同计划之间不保证逐位置相同。
- 平衡是**推导**（可离线复验数值对照表），手感仍需实机试玩。
