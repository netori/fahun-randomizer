## A 批：9 个「事件系 Boss」能随了

**为什么以前随不了**：位置表把它们当成「事件生成」，而调查（`investigation\_probe\A_事件生成Boss_调查.md`）证明 15 个位置全是 MSB **预置**的 Enemy part，只是模型写成 `c0000`（玩家模型）——外观由 part 的 `chara_id` 指向的 CharaInitParam 决定。所以：

- 「改事件让它生成别的敌人」没有载体：267 个事件 js / 113,160 个调用点里没有 CreateNPC / SpawnEnemy；
- 「原地改 NpcParam」也不行：NpcParam 没有模型字段，这些行是 hp=1551 的玩家模板。

**现在怎么做**：和参考实现（`EldenEnemyEditor.cs:69-85 TransplantEnemy`）同一个做法——按现有 MSB 四字段换（`model` / `npc` / `think` / `chara`）+ 克隆 NpcParam 行 + 按实体改血条名。数据层用 `overrides.places` 逐条放开这 10 个位置（默认政策仍是 keep，放开是显式覆盖）：

## B 批：双人 Boss 的第二只单只互换

**参考实现不是「保留主只换第二只」**：它把主 Boss 独立随机、第二只从「每场多 Boss」的全局池里跨场互换，还会删原 helper、克隆 donor 的 helper（`EnemyRandomizer.cs:1498-1512 / 2212-2228 / 3729-3761`）。我们不做删/克隆实体，做**单只互换**：

- 保留实体 ID、不删实体、不改事件死亡条件——只换「身份」（模型 / npc / think / chara / 血条名）；
- 第二只从「Boss 六类 + 有血条名」的换入池里抽一只（尺寸/场地以**主人**为基准，血条名优先用捐赠位置自己的名字）；
- 血量按原「第二只 / 主人」比例缩放（例如 0.277 = 这只原本只有主人 27.7% 的血），魂设为 0；
- 第二只不参与「同一个 Boss 最多用几次」的全局上限统计（那是主力位的预算，掺进来会让关掉某条规则时别的位置抽签结果跟着变）。

## 风险与回退

| 风险 | 回退 |
|---|---|
| A 批某个事件系 Boss 换完演出卡住 / 不出现 / 无法击杀 | 把 `overrides.places` 里对应那一行删除（或 `policy: keep`），重建数据；单个位置不影响其它 |
| B 批第二只 T-pose / 悬空 / 卡墙 / 不打人 | 界面取消「双人BOSS第二只也随机」，或 yaml `duo.enabled: false`（整批）；单组出问题把该组 `enabled: false` |
| C 批龙人士兵开启后阶段/动画异常 | 它默认就是 `enabled: false`；真要开，出问题改回 false |
| 双人第二只血量比例观感不对 | yaml `duo.donor.hp_ratio` 的 min/max 是硬边界，实际比例来自原血量比；觉得太高/太低就改这个区间 |

## 升级

1. 覆盖新版 exe；
2. 想在旧方案上生效：重新「开始随机」生成一次（旧方案层里的数据是旧的，不会自动变）；
3. 旧预设兼容：预设格式没变，直接能用；「双人BOSS第二只」默认开，老预设也会带上这 6 个位置（不想要就取消勾选）。
