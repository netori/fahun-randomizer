# 更新日志 v1.3.15（2026-10-24）

> 一句话：**多阶段 Boss 的位置现在也参与随机** —— 荷莱·露、玛利喀斯、蕾娜菈、拉卡德、达格拉夫、
> 拉达冈 / 艾尔登之兽、拉塔恩、梅瑟莫、玛莲妮亚、受封印神祇之嗣、火焰巨人、幽影树化身、融泥骑士、
> 米德拉，14 组全部会换；**默认开、不提供开关**。辅助体只换真身（血条助手 / 坐骑 / 事件共用体不动）。

---

## 一、为什么改

作者原话：「那个位置也要换，而且默认就会换，也不需要给玩家选择的余地，就一定可以换就行」。

v1.3.14 只解决了「多阶段 Boss 的身份能当来源」，它们自己的位置仍然 keep（数据层不动那场战斗）。
这一版把位置侧也打开：14 组全部参与随机，并且默认常开。

## 二、改了什么

### 1）数据：`multiphase.groups` 全部 `swap: true` + 新增 `swap_entities` / `pair`

`investigation/apply/data/enemy_classes_v3.yaml`：

- 14 组全部 `swap: true`；
- 新增 `swap_entities`：**真正要被换掉的实体**（缺省 = `phases`）。辅助组只换真身：
  - 受封印神祇之嗣 `[12010810, 12010812]`（HP 壳 + 真身，两者 pair，必须同换）；
  - 幽影树化身 `[2050480800]`（真身；810–812 三阶段血条助手不动）；
  - 融泥骑士 `[22000800]`（骑士；801 坐骑不动）；
  - 米德拉 `[28000800]`（本体；801 被三个事件共用，不动）；
- 新增 `pair: true` 认账字段：有 `CreateReferredDamagePair` 的 8 组（荷莱·露 / 玛利喀斯 / 拉塔恩 /
  梅瑟莫 / 火焰巨人 / 受封印神祇之嗣 / 幽影树化身 / 融泥骑士）**首次默认连 pair 组一起换**；
  pair 组统一按「整场一个 Boss」处理，pair 关系本身不动。

### 2）计划层：`constraints.multiphase_swap` 默认 `true`

- `_multiphase_plan` 不再只处理 `kind=phase` 的 5 组，而是处理**所有 swap 组**；每组按 `swap_entities` 取实体；
- 分流策略：模型相同的组 / `pair: true` 组 → **one_boss**（整场共用一个换入 Boss、同一份血量）；
  模型不同的三组（蕾娜菈 / 达格拉夫 / 拉达冈·艾尔登之兽）→ **per_phase_model**（每阶段各换一个不同 Boss，
  换入模型互不相同、也不等于任一原模型）；
- 组内实体**不会被抽到自己**（排除组内原模型）；候选为空 → 整组跳过并如实记 `no_mp_donor`；
- 池开关仍然有效：组内单元所在池**全部**被关掉 → 整组不参与（`pool_off:mp:<组>`）；
- Oops All 也会换多阶段位置（新增一条 `multiphase_boss` 规则，目标 = Oops 类别）；
- `--selftest`：④ 改为「25 个位置全部参与替换」、⑩ 改为「14 组默认全换 / 关掉零替换 / 其它单元零变化」、
  ⑭ 允许多阶段条目、② keep 检查排除多阶段位置。

### 3）界面：删掉两个勾选框（这一项不再给玩家选择）

- 敌人页删除「多阶段BOSS整组替换（实验）」；
- 敌人页与预设编辑器删除「多阶段BOSS也能当来源」；
- `_ev1_options` 里 `multiphase_swap` / `multiphase_as_source` **硬编码 True**；
- 预设编辑器右栏保留一行说明「位置默认也换、身份也能当来源（常开，无开关）」。

### 4）数据校验（`enemy_data_build.py --check`）

- 新增 `swap_entities` 不变式：写了就不能为空、实体必须在位置表、必须 keep、不能重复；
  非 phase 组开 swap 时必须显式写 `swap_entities`；
- pair 检查挪到「真正要换的实体」上：要换的实体带 pair 绑定 → 必须显式写 `pair: true`（认账）。

## 四、风险（如实写）

- **这一版首次把有 pair 绑定的组也默认换掉**（荷莱·露 / 玛利喀斯 / 拉塔恩 / 梅瑟莫 / 火焰巨人 /
  受封印神祇之嗣 / 幽影树化身 / 融泥骑士）。pair 是 2026-10-21 安塞尔河坏档的同源风险（H-034 / H-039），
  此前一直靠不换规避；现在按作者要求默认换，**尚未实机验收**。
- 辅助体（血条助手 / 坐骑 / 事件共用体）保持原样，pair 靠实体 id 维持 —— 理论上实体 id 不变 pair 就还在，
  但「换入非坐骑模型 + 坐骑位保留」属于已知风险场景。
- **出问题的回退方式**：设 `constraints.multiphase_swap=false`（命令行）即可回到 v1.3.14 的「位置不动」行为；
  或直接换回 v1.3.14 的 exe。旧方案层 / 旧计划照常可玩。
- 只换身份、不搬事件：目标场地仍跑原来的雾门 / 死亡 / 奖励 / 剧情事件；二阶段身份单独出现时依赖
  转阶段事件的演出不会发生（和普通 Boss 来源一样）。

## 六、升级

换 exe 即可，旧预设不用改。**注意**：yaml 中的组定义变了 → 同一 seed 在 v1.3.15 会生成与 v1.3.14
完全不同的计划（全量重排）。想复现上一版组合请沿用旧版已生成好的方案层。

## 七、边界

- 不搬事件；pair 组的「整场一个 Boss」只保证身份一致，具体转阶段演出仍由原场地事件驱动。
- 辅助组只换真身：幽影树化身的血条助手、融泥骑士的坐骑、米德拉的事件共用体仍是原版。
- 多阶段位置不再受「百分比 / 规则 rate」影响（位置默认换），只受整组跳过（池关闭 / 无候选）影响。
