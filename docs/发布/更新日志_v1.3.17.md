# 更新日志 v1.3.17（2026-10-24）

> 一句话：**内置 7 份预设重做** —— 4 个特殊池里能当来源的 3 个（追忆 / 楔石 / 传送门）**当来源写进权重**了；
> 并按**难度分层**：难目标（主要 BOSS 位、追忆 / 楔石位）多抽难池，简单目标（野外 / 夜间 / 龙类 / 监牢 BOSS）
> 多抽野外池和同类。分层是**概率倾向**，不是硬约束。

---

## 一、为什么改

作者原话：「预设不合理，为什么特殊池不加进去呢，还有我们是内置预设所以追忆boss之类的比较难的boss
可以提高难的boss池的比例，野外boss之类简单的boss可以提高简单boss池的比例，当然不要死板的理解，
我只是给你说一下我的需求」。

两个真问题：

1. **特殊池没进预设**：`pools`（四个特殊池当来源）是 v1.3.13 就有的能力，但 7 份内置预设一份都没用 ——
   所有类的来源只有 9 个可见类，所以「追忆 Boss 池」「楔石池」这些特征在预设里完全看不出来。
   （圣龛池 `reliquary` 只有 1 个成员且是 keep，按设计不能当来源，所以只写另外 3 个。）
2. **不分难度**：以前主要 BOSS 位和野外 BOSS 位抽的是同一套类池、同一套均匀权重；而且就算预设写了类组成，
   **传送门位 / 血条位这类特殊规则也不吃预设的组成**（特殊规则没有显式组成时直接均匀抽）——
   所以「追忆位多抽追忆池」在引擎里根本写不进去。

## 二、改了什么

### 1）计划层：特殊规则沿用「目标位置原类」的组成

`investigation/apply/enemy_plan.py`（约 2026–2036 行）：

```python
_cw = preset_class_weights.get(u["cls"])      # 目标位置原类的来源组成
_rw = rule.get("donor_weights")               # 规则/池/血条位条目自己的组成
_weights = _rw or _cw or donor_weight_map
d = pick_donor(u, cand, rng, ..., weights=_weights, fallback_weights=donor_weight_map)
```

优先级：**预设给池/血条位写的显式组成 > 目标位置原类的组成 > 候选池等概率**。
类组成在当前候选池里一只都对不上时自动退回等概率（不会因为权重写偏就少换）。

### 2）7 份内置预设重做（6 份改内容，07 不动）

## 三、默认计划不变（不用预设时）

没选预设时仍走 YAML 内置规则（没有类组成）→ 特殊规则照旧等概率，默认计划仍是
**25,656 单元 / 替换 22,493 / 跳过 3,163**、yaml 指纹不变 —— 与 v1.3.16 完全一致。

数字说明：v1.3.16 表里 05 记的是 11,318 / 12,334，这次用**种子 99** 重测是 11,493 / 12,449。
用 v1.3.16 的代码 + v1.3.16 的预设实测也是 11,497 / 12,453 —— 说明那张表是当时**中途记的**，不是
v1.3.16 最终代码的复现值；这一版以重测值为准（01–04 / 06 的 22,493 → 22,489 同理，差 4 个来自
特殊规则改用类组成后少数位置的候选池收窄）。

## 四、风险（如实写）

- 分层是**概率倾向**：02 的主要 BOSS 位仍有约 20% 换到杂兵级，04 更是全类互抽 —— 这是「不要死板」的落地方式；
- 难度分档用「类」近似（主要 BOSS = 难），不按具体 Boss 强度排序 —— 游戏里也有偏弱的追忆 Boss；
- 能当来源的池不大：楔石池 16 只 Boss、追忆池 39 只 Boss（含重复模型），所以难池抽多了会重复见到同一只
  （Boss 上限默认 5 次仍生效）；
- 血条位 / 传送门位现在明显更偏难池 → 追忆 Boss 会更常出现在野外位上；模型、AI、场地大小是否扛得住，
  **尚未实机验收**；
- 旧的自定义预设完全不受影响（没写 `pool:` 引用就照旧）；但内置预设内容变了 → 预设指纹变 → 同一 seed
  生成的计划与 v1.3.16 不同（想复现：沿用已生成好的方案层，或继续用旧 exe）。

## 五、自检

- `enemy_plan.py --selftest` **PASS**：新增 ㉑「特殊规则沿用目标类组成」（Boss 类传送门 / 血条位 45 个全部抽自追忆池），
  默认计划数字不变，其余 22 项断言全 PASS；
- 7 份内置预设逐一 `build_plan` + `validate_plan`：**0 错误**（数字见上表）；
- `randgui.py --uitest` PASS（预设编辑器 9 类 / 池面板 / `@sameboss` 断言不受影响）；
- `build_exe.py` 四道闸门（`--selftest` / `--planlib` / `--uicheck` / `--uitest`）全 PASS。

## 六、升级

换 exe 即可，旧预设不用改。预设编辑器里选一份新预设（推荐先看 01 或 06，再试 02）→ 预览 → 部署。
「不要死板」的做法：在编辑器里把某一类的追忆百分比调高 / 调低即可，不必改代码。

## 七、边界

- 只改「换进来的来源构成」和特殊规则的取重方式，**不新增 / 删除任何位置**；
- 池开关照旧：关掉某个池 = 池内位置不参与替换，且该池成员不再当来源；
- 多阶段 Boss 仍按 v1.3.16 的「按模型拆 Boss」处理，本次未改；
- 圣龛池不能当来源（唯一成员是 keep 的剧情对象），所以预设里没有 `pool:reliquary`。
