# 更新日志 v1.3.16（2026-10-24）

> 一句话：**多阶段 Boss 改为按「模型」拆 Boss** —— 同一个模型（跨阶段变身 / 三管血条）算**一只** Boss，
> 整组共用一个换入身份；不同模型（一阶段一只模型）**拆成多只** Boss，各自独立随机。
> 例：幽影树化身（6 个实体全是 c5230）= 1 只 Boss；受封印神祇之嗣（c4135 腐败容器 + c4400 本体）= 2 只 Boss。

---

## 一、为什么改

作者原话：「受封印神祇之嗣两阶段不是两个不同的模型吗,所以拆成两个boss。幽影树化身是一个模型三管血条，
所以还是一个boss,根据模型不同拆成几个boss就行，都可以遵守这个原则」。

v1.3.15 的分流是按「pair 标记 / 模型是否相同」猜的：pair 组一刀切当成一只 Boss，
幽影树化身只换 800、810–812 血条助手不动 —— 两者都不符合上面这条原则。这一版按模型重划。

### 2）计划层 `_multiphase_plan` 重写为 per_model

- 每个 Boss（`bosses` 子列表）抽**一个**捐赠者，该 Boss 的所有位置共用一个身份、同一份血量；
- 不同 Boss 的捐赠者**互不相同**，且都**不等于**组内任何原模型（保证每只都看得出变化）；
- 候选为空 → 整组跳过（如实记 `no_mp_donor`）；池开关仍然整组原子（任一位置所在池被关掉 = 整组不参与）；
- `meta.multiphase_policy` 每组记 `policy=per_model / bosses / phases / donors / models`；
- **Boss 使用上限按「场次」计**：同一个 Boss 在一场多阶段战斗里只算用了一次（否则幽影树化身 6 个位置
  会被算成 6 次，自己就把上限撑爆）；
- `validate_plan` 校验：每只 Boss 的位置数 / 身份一致 / 不同 Boss 身份与模型互异 / 不含组内原模型，
  以及 `mp_boss` 编号。

### 3）数据校验（`enemy_data_build.py --check`）

- `bosses` 不变式：每个子列表非空、实体在 `phases` 里且都在位置表、数据层必须 keep、
  **同一 Boss 内必须同模型**、**不同 Boss 的模型互异**（同模型必须合成一个 Boss）；
- pair 检查改到「真正要换的实体」上（`bosses` 摊平）：带 `CreateReferredDamagePair` 的必须显式写 `pair: true`；
- `sources` 不变式保留。

### 4）界面

- 只改文案：敌人页与预设编辑器写明「14 组 / 20 个 Boss，按模型拆」；功能/开关不变（多阶段仍常开、无开关）。

## 四、风险（如实写）

- 幽影树化身 6 个实体（含 3 个血条壳）现在**一起**换成同一只 Boss：血条名会跟着换（这是目的），
  但血条壳也变成新模型 —— 三管血条的转阶段动画是否正常，**尚未实机验收**；
- 融泥骑士的坐骑位也换成同一只 Boss 的 c5020_9001 部件：坐骑模型是否存在对应部件，**尚未实机验收**；
- 受封印神祇之嗣第一次把「腐败容器 c4135」算成独立 Boss 并参与随机（v1.3.15 之前它根本不在组里）；
- 米德拉现在会换成两只不同 Boss（c5050 人形位 / c5051 本体位）—— 人形位原本是玩家可打的第一形态；
- 回退：设 `constraints.multiphase_swap=false`（命令行）可回到「多阶段位置不动」；或换回 v1.3.15 的 exe。

## 六、升级

换 exe 即可，旧预设不用改。**注意**：yaml 的组定义变了 → 同一 seed 在 v1.3.16 会生成与 v1.3.15
完全不同的计划（全量重排）。想复现上一版组合请沿用旧版已生成好的方案层。

## 七、边界

- 只换身份、不搬事件：目标场地仍跑原来的雾门 / 死亡 / 奖励 / 剧情事件；
- 辅助体（血条壳 / 坐骑 / HP 壳 / 事件共用体）不单独参与随机，只随它所属的 Boss 一起换；
- 多阶段位置不受「百分比 / 规则 rate」影响，只受整组跳过（池关闭 / 无候选）影响。
