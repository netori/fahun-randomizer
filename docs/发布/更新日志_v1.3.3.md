# 更新日志 · v1.3.3（2026-10-23）

> 这一版**修两个让人以为「随机器坏了」的问题**（都是今天实测发现的）：
> 种子一直显示同一个数、写入报「写前复核未通过」整批对不上。随机引擎本身没问题。

## 一、种子：默认每次都换

- 以前种子默认固定成 `20261010`，每次点「开始随机」都是**同一套世界** —— 看起来就像根本没随机。
- 现在种子行默认勾着 **「每次开始随机都换种子」**：点一下 = 一套新世界，种子显示在状态栏里。
- 想复现某一套：取消这个勾，把种子填回去 —— 同种子仍然是完全一样的结果。

## 二、写入失败「写前复核未通过」的真正原因

截图里那种 `766/766 条与当前文件不一致`，不是游戏文件坏了、也不是换了 MOD 版本：
是工具手里的**「原始备份」本身就不是原始版** ——
便携目录第一次运行点「补一份原始备份」时，本体已经被随机过（以前直接写过本体），
于是把改过的文件登记成了「原始」；写入拿它当基底，自然每条都对不上。

这一版的处理：

- **补备份时当场自检**：用工具自带的数据快照（建索引时的那份原始数据）抽样核对物品格子，
  不像原版就**拒绝登记**并说明怎么修（不会再让你踩第二次）。
- **环境卡会说真话**：那份备份可疑时，「原始备份」这一项直接标红，而不是「找到 2/2 份」。
- **写前复核失败时日志里附带诊断**：直接告诉你是备份错了，而不是让你去猜「换过 MOD 版本？」。

## 三、验证

- 界面自检：`--uicheck` / `--uitest` 全绿（新增断言：种子默认重掷、说明文案、`pristine_probe` 缺文件时如实返回 unknown）。
- 备份自检实测：真原始 159 个抽样格子 **158 命中（0.994）**；被随机过的本体 **143 命中（0.899）**，阈值 0.97 能分开。
- 端到端：用用户那份 766 格的计划对真原始备份跑 `apply_native(verify=True)` —— 写前复核 766/766 通过、回读差异 0 字节。
