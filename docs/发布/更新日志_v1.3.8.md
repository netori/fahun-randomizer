# 更新日志 v1.3.8（2026-10-23）

> 这一版只修一个启动问题：**从方案层目录里的「用这个方案启动.bat」启动时，报「法魂包根目录不对（没有 yafsml\）」**。
> 引擎、写盘、随机算法都没动。

## 一、修了什么

### 现象

双击 `<法魂包>\方案\<层名>\用这个方案启动.bat`，弹窗：

```
启动失败
法魂包根目录不对（没有 yafsml\）：...\方案\<层名>
```

### 根因

方案层里也有一份 `mod\regulation.bin`，而「用这个方案启动.bat」被双击时，**工作目录就是层根**。
启动器「尽早发布 MOD 路径」那一步按 `mod\regulation.bin` 找包，于是把**层根**当成了法魂包根本体，
把 `CONVERGENCE_MOD_ROOT` 指到了层根；接着方案层模块找 `yafsml\` 当然找不到 —— 整条启动就断在第一步。
（同样的坑也会让 `--paths` 与「切回法魂本体」在层目录里跑时认错包。）

### 修法

| 位置 | 改动 |
|---|---|
| `investigation/apply/modpaths.py` | 新增 `is_layer_root()`：`<法魂包>\方案\<层>` 这种目录里虽有 `mod\regulation.bin`，但**不算**法魂包根；`is_mod_root()` 排除它；多候选时优先带 `yafsml\` 的那份 |
| `randgui.py` | 新增 `_is_layer_dir()` / `_pack_of_layer()`：从层目录往上找带 `yafsml\` 的包根；`find_mod_root()` 跳过层；`--play` 在换档前先把真正的包根发布成 `CONVERGENCE_MOD_ROOT` |
| `investigation/apply/gamelib.py` | `launch()` / `status()` 先按「层 → 包」反推包根，不再只信环境变量 |
| `investigation/apply/plan_layer.py` | `set_plan()` 的返回值在**层与包不在同一盘**时不再抛 `ValueError`（绝对路径原样报回） |

## 二、验证

| 项 | 结果 |
|---|---|
| 隔离 dry-run（临时假包 + 假层 + 假存档 + 假启动 bat） | **PASS**：`pack_of_layer` 认出包根 → 换档成新档 → 写 `Plan=../方案/测试层/mod` → 启动 bat 真的被执行 → 退出后存档存回 `存档库\测试层\` |
| 真实层目录里跑 `--play`（工作目录 = 层根） | 不再报 yafsml；正常走到「这个方案还没有存档，要用新角色开始吗」这一步 |
| `--uitest` | PASS，新增 3 条：「层不会被当成包」「能从层反推包根」「`modpaths` 同样不认层」 |
| `--uicheck` / `--selftest` / `--planlib` | PASS |

## 三、升级与注意

- 覆盖 exe 即可，方案层与存档库不用动。
- 旧方案层里的两个 bat 里写的是**当时那台机器**的路径；换机器/挪了目录的话，
  在方案库里点一次「用这个方案玩」会自动重写它们（`gamelib.launch` 每次开玩都重写）。
- 如果确实把整个法魂包改了名，`--paths` 可以一条命令看清现在认到哪些路径。
