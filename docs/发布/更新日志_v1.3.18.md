# v1.3.18 更新日志（2026-10-24）

## 一句话

内置 7 份预设里，四个特殊池现在**各自是一组可配来源的位置**：传送门守门（27 位）、楔石首领（18 位）、追忆首领（48 位）都有自己的「换入来源」配置，劳弗圣龛显式关掉并写明原因。上一版只把特殊池当成别的位置的「来源」，池自己的位置组还是空的 —— 这就是你打开池节点看不到特殊池的原因。

## 为什么改（原话）

- 2026-10-24 用户：「我是真搞不明白你了，你跟特殊池子有仇吗？」
- 更早同一件事：「预设不合理，为什么特殊池不加进去呢」（2026-10-24）

## 上一版（v1.3.17）漏了什么

v1.3.17 做的是「把池当来源」：类别的 donor_weights 里加了 pool:remembrance / pool:keystone / pool:waygate，让普通位置有概率换进池里的 Boss。

但预设里还有一段 pools —— **池自己的那组位置换什么**。01–06 六份内置预设当时没有这一段，于是在编辑器的「追忆 / 楔石 / 传送门」节点里：

- 池内位置的来源 = default_preset 摊平的类（池来源 0%）；
- 四个池作为来源，在这组位置上一次都没被用到。

换句话说：池里的 Boss 能当别的位置的来源，但池自己的位置不按池来配。这版补上了。

## 这版怎么配的

每条池条目 = 「这组位置换入的来源及占比」。楔石与追忆位置大量重叠，所以两池给**相同组成**，避免规则顺序影响结果。

劳弗圣龛（reliquary）：**显式关掉**（enabled:false）。原因不是偷懒：9 个变体共用同一个竞技场实体 31810800，阶段二事件 31812811 依赖 SpEffect，这个位置本身在分类表里就是「不换」（policy=keep）；换掉会直接断事件。编辑器里打开它会看到「关掉」，成员说明里也写着这件事。

## 引擎行为（给改代码的人）

- 池条目展开成规则 id: preset:pool:<pid>，插在 YAML 传送门 / 血条规则**之前**；
- 多阶段组的位置仍由 multiphase_boss 规则优先接管（29 个位置），预设池条目不抢；
- 池条目没配置时，行为与 v1.3.17 一致（沿用原类的组成）。

## 自检

## 风险 / 回退

- 池位置现在优先按预设条目换（以前是内置规则按类均匀）。不想要就在编辑器里关掉对应池条目，或换回 v1.3.17 的 exe。
- 圣龛仍然不换（结构原因，见上）。

## 升级

直接用新 exe 覆盖旧 exe 即可；旧预设文件仍能读（没有 pools 段的按旧行为，等价 v1.3.17）。

## 边界

- 仍然只做离线写层：计划文件在本地生成，游戏内实际效果需要试玩验收。
- 传送门 / 楔石 / 追忆的成员由分类表决定，预设里只能改「换成谁」，不能增删成员。
