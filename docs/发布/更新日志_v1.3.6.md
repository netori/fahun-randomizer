# 更新日志 v1.3.6（2026-10-23）

> 这一版只改「怎么开始玩」这一段，引擎与写盘逻辑一行没动。
> 修的是作者反馈的两件事：游戏开着时点「用这个方案玩」还是得自己先退；从方案目录里

## 一、游戏在跑也能一键开局（先问一句，再替你关）

* 点「用这个方案玩」时如果《艾尔登法环》还开着，会先弹一次确认：
  「要用这个方案开局，得先把正在跑的《艾尔登法环》关掉。现在自动关掉它并启动吗？」
* 选「是」：先请游戏自己退（`taskkill /PID`，等 25 秒），实在不退才强制结束
  （`taskkill /F`）—— 强杀会丢最近一小段进度，所以先给时间；
* 关干净了才换档 + 挂载 + 起游戏；
* 选「否」：什么都不动，游戏照常开着。
* 顺序上有意先问「没有存档要不要用新角色开局」，再问「要不要关游戏」——
  免得人拒绝了新档，游戏却已经被关了。

## 二、方案目录里的启动器也走独立存档

以前层目录里的 `用这个方案启动.bat` 是「挂 Plan= → call 启动法魂.bat」，
**完全绕过存档库** —— 所以从那里进游戏用的是当前那份档，不是这个方案自己的。

现在它调随机器自己的命令行模式：

```bat
start "" <随机器> --play "<层目录>\mod"
```

`--play` = 换档（每个方案一份）→ 挂载 → 起游戏 → **等游戏退出** → 进度存回这个方案的槽。
日志追加写到层目录的 `启动日志.txt`；出问题它会弹框说原因，不再静默。

`切回法魂本体.bat` 改调 `--plan-off`（删掉 `Plan=`），不再依赖系统 python。

已有的方案层（包括 v1.3.5 之前生成的）可以一键重写这两个 bat：

```bat
python investigation\apply\plan_layer.py --launchers
```

## 三、命令行（新增两条）

| 命令 | 干什么 |
|---|---|
| `ConvergenceClassItemRandomizer.exe --play <方案层目录>` | 换档 + 挂载 + 起游戏 + 退出回存（层里的启动器调它） |
| `ConvergenceClassItemRandomizer.exe --plan-off` | 切回法魂本体（删掉 Plan=） |

没有图形界面的机器也能用：`--play` 会弹确认框（要新档 / 要关游戏），日志写层目录。

## 四、底层（gamelib）

| 新增 / 变更 | 说明 |
|---|---|
| `game_pids()` | 列出 eldenring.exe 的进程号（可能不止一个残进程） |
| `kill_game(timeout=25, log=None)` | 先请它自己退、等不到再强杀；True = 真关掉了，False = 本来没在跑 |
| `launch(..., kill_running=False, log=None)` | 新增开关；**问人这一步在界面上做**，gamelib 不弹窗 |

## 七、升级注意

* 前置版本 v1.3.5 的包仍然在 `发布包\` 里；
* **不要**把新 exe 直接盖到正在运行的 GUI 上（Windows 会锁文件）—— 关掉 GUI 再替换；
* 老方案层的两个 bat 不会自动变，跑一次 `plan_layer.py --launchers` 就统一了；
* 强杀游戏有风险：工具先等 25 秒请它自己退；如果游戏卡死到不响应，强杀后进游戏确认一次存档；
* Steam 云存档仍可能把档换回去 —— 玩多方案前请关掉云存档。
