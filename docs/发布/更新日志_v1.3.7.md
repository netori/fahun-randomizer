# 更新日志 v1.3.7（便携性：换盘、换机器、改文件夹名都能用）

> 这一版只改「怎么找路径」。随机算法、写盘格式、方案库流程、界面都没变 ——
> 你原来的方案不用重做。

## 为什么

以前有些路径是从「这台机器、这个盘符、这个文件夹名」推出来的，比如写死了

    F:\game\studygame\elden ring\THE_COVERAGE-随机开发\法魂mod V3.0.3 汉化本体（…）

于是把整合包从 F: 挪到 D:、把文件夹改个名（版本一升级就会变）、或者只把 exe 拷给别人，就会报「找不到」。
方案库里的「层路径」也是生成当时存的绝对路径，搬完目录会找不到自己那一层。

## 现在怎么找

- **认内容不认名字**：目录里有 `mod\regulation.bin` 才算法魂包；再往上一级有 `yafsml\` 就能当包根。
- **自动找**：从 exe / 工具目录往上最多 7 层，每层连同级目录一起看；多个候选优先名字带「法魂」/ `convergence` 的，其次 `regulation.bin` 更新的。
- **手动兜底**（任选其一）：
  - 界面「本地文件」→「指定 MOD 目录…」；
  - 环境变量 `CONVERGENCE_MOD_ROOT=<法魂包根目录>`；
  - 把 exe / 工具目录放到法魂整合包**旁边**。
- **游戏目录与 Oodle 库**：从 `CONVERGENCE_GAME_DIR` / `ER_GAME_DIR` 找；没有就从 `Program Files`、Steam 的 `libraryfolders.vdf`、各盘 `SteamLibrary\steamapps\common\ELDEN RING\Game` 挨个试。
- **方案库的覆盖层**：不再信方案里存的旧绝对路径 —— 用层目录名（`built.label`）去**当前**方案目录里找；找不到就当作「还没生成」，下次开玩重新生成（不会报错）。
- **层里的两个启动 bat**：每次点「用这个方案玩」都会按当前这台机器重写（层被拷到别的电脑后不会指向旧路径）。

## 新命令：`--paths`

    ConvergenceClassItemRandomizer.exe --paths

逐行打印 工作区 / exe 目录 / 法魂 MOD 目录 / regulation / 游戏目录 / 法魂包根 / YAFSML.ini / 方案目录 / 当前挂载 / 存档目录 / 存档库 / Oodle DLL。
搬完家有什么不对，先跑这一条，哪一行空了错了就能看出来。

## 升级注意

- **旧方案不用重做**：层还在原处的话，点「用这个方案玩」会按目录名找到它；找不到会重新生成（第一次慢一点）。
- 如果你把 exe 单独放在别处、没和法魂整合包在一起：第一次启动后用「指定 MOD 目录…」选一次，或者设 `CONVERGENCE_MOD_ROOT`。
- 存档不受影响：存档库跟着法魂包走（`<法魂包>\存档库\`），存档本体仍在 `%APPDATA%\EldenRing\`（游戏自己认的位置，不能搬）。
