# v1.5.0 更新日志（2026-10-25）

## 一句话

「多阶段 Boss 当来源」不再只有一阶段：来源是**多阶段 Boss 的初始形态**、目标是**单阶段场地**时，把它「变身成第二形态」那套战场事件一起搬过去 —— 目标场地也会真的进二阶段（换模型、换血条名、按原作比例给二阶段血量、按配方挂 SpEffect / 动画 / 面罩）。

## 为什么改（原话）

> 我之前反应过的「随不到二阶段」的问题，你当时给了以下回答，我暂时没让你做，现在可以做下了：要新做的：把二阶段那套事件一起搬走（按每只 Boss 定制：血量阈值、切实体、SpEffect、动画）。技术上可行，但每只都要单独核对事件，工作量和风险是另一个量级 —— 要做的话我单独立项评估，不塞进这个修复里。

v1.4.2 只做到「名实相符」：多阶段 Boss 当来源只取一阶段身份，避免「血条名是二阶段、招式只有一阶段」。但玩家换到别的战场后，**永远看不到二阶段** —— 因为「血量到阈值 → 关掉一阶段实体 → 打开二阶段实体 → 换血条 / 挂 SpEffect / 放变身动画」这一整套是**原地图 EMEVD 里的事件**，换模型时带不走。

## 一、这次做了什么

只做**单阶段目标**（目标自己就是多阶段场地的，保留原场地事件，不搬，避免双重切换）。满足下面三条才搬：

1. 来源单元是 yaml 多阶段组里的**初始形态实体**（用实体号判定，不能只看 npc —— 玛莲妮亚两阶段同 npc / 同模型）；
2. 目标位置是**单阶段**场地（目标地图不在任何多阶段组的位置里）；
3. 有**人工核对过事件**的配方（`investigation/apply/data/phase_carry.json`）。

每处目标做三件事（都在写盘层完成，不改计划 / 种子）：

- **在目标 MSB 里克隆一个第二形态 part**：同位置、新 EntityID / PartID / InstanceID，模型 = 来源二阶段模型，npc / think / chara 指向来源二阶段身份，初始隐藏；
- **在目标地图 EMEVD 里追加三个事件**：
  - `init`：地图加载时禁用第二形态（隐藏、关碰撞 / AI / 重力 / 网络更新）；
  - `transition`：一阶段血量到配方阈值 → 关一阶段 → 开二阶段 → 血条切到二阶段名字 → 按配方挂 SpEffect / 清 SpEffect / 换面罩 / 放变身动画 → AI replan；
  - `death`：二阶段死亡 → 唤醒并 ForceDeath 一阶段，让目标地图**原本的死亡结算**（雾门、奖励、追忆、剧情 flag）照常触发；
- **克隆一条第二形态 NpcParam**：沿用来源二阶段原行的全部战斗参数，血量改成「目标位置血量 × 来源二阶段/一阶段基础血量比」（并 clamp 0.2–3.0），魂置 0。

## 三、本版实测（计划：敌人v1.4.2，种子 20261025）

- 命中 **11 个 carry 目标 / 11 张图 / 11 个第二形态 part / 33 个新事件**（另 1 张图 `m61_47_45_10` 在 mod 和本体里都没有独立 EMEVD 文件，如实跳过，不克隆 part）；
- 配方组命中：梅瑟莫 2（m61_47_45_00 / m61_50_47）、蕾娜菈 2（m12_02 / m60_34_50）、玛莲妮亚 3（m12_05 / m31_15 / m60_42_38）、拉达冈 1（m35）、拉塔恩 1（m43_01）、荷莱·露 2（m60_39_43 / m60_42_37）；
- 二阶段血量按原作比例缩放（示例：蕾娜菈目标位置 2,530 血 × 1.516 = 3,836）；
- regulation 7,830 → 28,355 行（其中第二形态行 11 条，前缀 `gfPhase2:`，重跑会先清掉旧行）；
- 事件 flag 分配：新 flag 放在**目标地图自己的号段**（用 part 实体号前缀推，例如 m12_05 → 12,059,100、m61_47_45 → 2,047,459,100），并扫描 mod + 本体事件明文避开已用号；跨地图用集合去重；
- 写盘后逐图读回复验：part 数 = 原 + 新增、新 part 身份 / 模型一致、事件数 = 原 + 3、check_chain 全过；整层 `verify_layer` 用「血条名 + carry 事件」逐字节重建比对。

## 四、界面

敌人页新增开关 **「二阶段变身一起搬」**（默认开）。关掉 = 写层时不检测 / 不克隆 / 不写事件（同一份计划也能出「只换身份」的旧行为）。

## 五、风险与边界（如实说）

- 这是**首次**把目标地图原本没有的事件搬过去，尚未实机验收；最坏情况是目标场地战斗卡死 / 二阶段不出来 / 击杀不结算 —— 先关「二阶段变身一起搬」或挂回 v1.4.2 的层；
- 只搬「换阶段」必需的那几条：**不搬**原地图的 cutscene / 镜头 / 玩家 warp（那是来源地图的坐标，搬到目标图会错位），所以二阶段是「原地变身」而不是原版那段演出；
- 玛莲妮亚没搬 `CreateNPCPart` / `SetNPCPartSEAndSFX`（缺义手部件），二阶段的义手弱点等细节不保证；
- 目标地图的原始死亡事件若盯的不是这个实体（极少见），death 桥接会失效；
- 事件 flag 分配只扫了 mod 的 268 个事件文件 + 本体 30 个兜底事件；游戏 Data0 里未被 mod 覆盖的事件看不到，理论上仍有极小概率撞号（已尽量用地图本地号段降低概率）。

## 六、回退

1. 敌人页取消勾选「二阶段变身一起搬」→ 重出计划 / 重写层 = 只换身份（v1.4.2 行为）；
2. 或把 YAFSML 的 `Plan=` 挂回 v1.4.2 的层；
3. 代码回退：`enemy_write.py` 去掉 `phase_carry` 接入（`WRITE_VERSION=10` 起有这一层）。

- `enemy_write.py --selftest` PASS（M2 来源加护表 / owner 冲突 / 重跑无残留）；`enemy_data_build.py --check` PASS（0 项不通过；24,420 行 randomize / 3,360 keep）；
- `randgui.py --uicheck` / `--uitest` PASS（新开关与 10 个控件断言）；
- build_exe 四道隔离自检 PASS（--selftest / --planlib / --uicheck / --uitest，空目录只放 exe）；`enemy_plan.py` / 7 份内置预设本版未改，计划层沿用 v1.4.2 的 selftest 结论；
