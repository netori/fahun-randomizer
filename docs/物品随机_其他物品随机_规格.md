## 0. 一句话

在现有「职业物品随机（G，说明书驱动）」之外，新增一套**格子级**物品随机：把世界拾取（ItemLotParam_map）、敌人掉落（ItemLotParam_enemy）、商店货架（ShopLineupParam）里**除 G 与冻结项之外的 ~10,900 格**，按参考实现的 **silo（可换性分层）** 做守恒置换，并把「重要位置 + 随机权重 + 三态物品组」做成可选设定；范围开关可选「职业物品 / 其他物品 / 全部（G 并入）」，全部模式下 G 页签整体变灰、跟随新机制，同一份计划、同一次写入。

**写盘范围只有 regulation.bin 的三张表**（+ 全部模式下原有的说明书同步）。地图 / 事件 / MSB / 商店价格库存解锁旗一律不动。

## 1. 术语与不变量

### 1.1 术语

| 记号 | 含义 |
|---|---|
| **格（cell）** | 一个可拿物品的位置：<code>表:行id:slot</code>（slot 1–8；商店恒 1）。三表共 11,700 格。 |
| **物品键** | <code>(类别, 数字ID)</code>，类别 ∈ goods / weapon / protector / gem / accessory / customweapon / unknown。比较、分组、去重一律带类别（H10）。 |
| **G** | 职业说明书物品集合（682 件 / 766 格），现有 G 引擎的随机范围。 |
| **非 G 格** | 三表 11,700 格中，去掉 G 格（766）、冻结格（§4.2，默认 629）与无法识别格之后的格子。 |
| **silo** | 可换性分层：<code>(RandomSilo, AreaSilo, ItemSilo, 数量档, 强化档)</code>，只有同一 silo 内才允许互换（§5.2）。 |
| **单元（unit）** | 置换的最小单位：普通物品 = 一个格；G 物品 = 该物品所有格子的整组（H9）；G 套装 = 整套四件（H7）。 |
| **value_tier** | 派生稀缺度 0–3，只用于权重（§5.4）。 |
| **区域档** | SpEffectID3 十步档（docs/敌人随机_区域档位依据_20261022.md），用于「同类不扎堆」与锻造石正相关；缺档的格子不参与该约束。 |
| **重要位置** | 面板勾选出来的格集合（§7），只影响权重，不影响能不能换。 |

### 3.1 范围三选一

|---|---|---|---|---|
| **职业物品**（默认） | 旧 G 引擎随机 | 完全不动 | 可用（原逻辑不动） | engine 1.1，旧格式 |
| **其他物品** | 完全不动 | 新引擎随机 | 灰掉，并提示「本范围不含职业物品」 | engine 2.0 |

- 方案库条目记录：range, seed, sources, bias_priority, 重要位置勾选, 三态, 放置选项, 冻结版本；指纹由这些字段 + 计划行内容派生（planlib.fingerprint）。

## 5. 池构造与置换

### 5.1 参与池的格子

    范围 = 其他：S = 全部格 − G 格(766) − 冻结格(629) − 未知/悬空格
    范围 = 全部：S = 全部格 − 冻结格(629) − 未知/悬空格
    （按面板「世界拾取 / 敌人掉落 / 商店货架」三个勾选再取交集；默认三勾全开）

- 三态为「不随机」的组、以及放置选项关闭时的材料组，从 S 中再剔除。
- 每个格子在计划里**恰好出现一次**；G 格与非 G 格在「其他」范围互斥（A4）。

### 5.2 silo（池键）

    silo_key = (random_silo, area_silo, item_silo, num_tier, stone_tier?)

| 轴 | 取值 | 判定规则 |
|---|---|---|
| **random_silo** | Finite / Infinite / InfiniteShop / Mixed | map 行全部 Finite（事件奖励也是有限）；enemy 行 getItemFlagId != 0 → Finite，否则 Infinite；shop 行：eventFlag_forStock == 0 且 sellQuantity != -1 → InfiniteShop，sellQuantity = -1（565 行，语义未实测）→ **Mixed**（保守），其余 Finite；map getItemFlagId == 0（1,085 行，是否可重复未实测）→ Mixed。 |
| **area_silo** | None / DLC | 行 id ≥ 2e9 或物品 id ≥ 2e6 或地图 m61 → DLC，否则 None。本期**不做 Region 层**（L2 未立项）。 |
| **item_silo** | goods / weapon:<weaponCategory> / armor:<protectorCategory> / gem / accessory / customweapon | 装备类别互不互换；goods 不细分；关键道具不进池（已冻）。 |
| **num_tier** | goods：1 / 2–4 / 5–99；装备固定 1 | 数量档进池键 = num 字段不动（A1），同时避免「5 个素材 ↔ 1 个」的极端；池因此变小属预期，报告里如实给回退数。 |
| **stone_tier** | 仅当「锻造石正相关」开时，对 gt14 强化素材加此轴 | 把强化素材档映射到区域档（同档/相邻档才可换），保证锻造石随流程推进；缺区域档 → 不加此轴并告警。 |

- 池 = 同 silo_key 的单元集合；池内**不再按类别切**（goods 池里消耗品/材料/卢恩/法术可以互换 —— 这是 #9「同 silo 内不分类别全混」的落地）。
- G 并入（全部范围）：G 单元按其 item_silo 进池；法祷护甲额外带 caster 标记，只与 caster 护甲同部位/同套装形态配对；G 套装四件作为**复合单元**（H7）；G 武器/护甲同样按 item_silo 分类。
- G 的冻结表（D1 微光卢恩 / D5 职业初始套装 / fixed_cells.json / multicopy_exclude.json / starter_set_freeze.json）继续排除。

### 5.3 置换（守恒）

- 池内单元列表 U；用 rng = hash(seed, silo_key) 生成**错排**（无固定点）⇒ 每格拿到别人的物品，守恒天然成立。
- 复合单元（G 套装 / G 同物品多格）：整体交换其所有格子内容；目标单元的格子数必须等于来源单元（套装 ↔ 套装、同物品组 ↔ 同物品组），否则该池视为不同质 → 回退。
- 错排无解（池小 / 结构冲突）→ **整池保持原样**，报告 fallback（silo_key、单元数、原因）。禁止半随机。

### 5.4 随机权重（bias_priority）

用户 #7/#12 拍板：单滑块 0–100，**默认 20**；高价值物品优先落已勾选的重要位置；所有 silo 内生效。

- 权重不改池、不改守恒；它只改「池内谁分到哪个重要格」。
- 实现（确定性，可复现）：

    输入: 池 P（单元集）、重要格集合 I(P)（面板勾选 ∩ P）、b = bias_priority/100, rng
    1. d = 随机错排(P)                      # 保证守恒且无固定点
    2. 目标函数 score(d) = Σ_c important(c) * value_tier(new_item_at_c)
    3. 接受交换的轮数 R = round(b * |P| * 4)
       重复 R 次：
         a = 从 I(P) 里随机取一格；b_cell = 从 PI(P) 里随机取一格
         若 score(swap) > score(当前) 且交换后两格都无固定点 → 交换（一次尝试，不回溯）
       若 b == 1：额外做一轮「直到没有改进」的贪心收敛（上限 |P|*20 次）
    4. b == 0 → 跳过 2–3，纯随机错排

- 单调性验收：同一 seed 下 bias 从 0→100，重要格内高价值（tier≥2）比例显著上升；bias=0 时与纯随机在统计上无差。
- 重要格集合按面板项并集，**每个池内单独解释**（地图/敌人/商店 silo 各自有重要格；商店行可被勾为重要位置）。
- 三个物品三态组、钥石、放置选项与权重正交：先剔除/约束池，再跑权重。

### 5.5 同类不扎堆（固定规则）

- 约束：同一 (区域档, item_silo 组) 内，同一物品组（goods 按 goodsType 大组、装备按类型）出现次数 ≤ ceil(该组单元数 / 有该档的档数) + 1。
- 实现：置换完成后做**确定性修复轮**（最多 50 轮定向交换，减少超标组），无法完全满足时记 spread_warning（不失败）。
- 区域档缺失的格子（约 26%）不参与该约束；报告里给出参与率。

## 10. 校验与测试

### 10.1 引擎自检（每次生成必跑，不过不出计划）

- **S1 守恒**：每个 silo 的物品多重集前后一致（含 G 复合单元）。
- **S2 silo**：每行 new 与 old 的 silo_key 完全相同；无跨 silo。
- **S3 冻结**：任何冻结格（含三态 Norandom、材料关闭时的 gt2、钥石默认）old == new。
- **S4 范围互斥**：其他模式不出现任何 G 行；全部模式 G 行出现且 G 冻结照旧。
- **S5 G 规则**（全部模式）：法祷护甲零混入、套装不拆、G 同物品多处一致、D1/D5 未使用。
- **S6 身份**：所有 id 带类别比较；无「同号不同类」误判。
- **S7 确定性**：同 (cfg, seed) 跑两次，计划 CSV sha256 相同。
- **S8 无固定点**：每个池每个单元都换了（池大小 1 或 fallback 除外）。
- **S9 名字**：池内 id 有名字率达标（weapon ≥99.8%、gem/accessory 100%、goods/protector ≥99%），未命中走兜底。
- **S10 统计自洽**：cells_in_scope + frozen + unknown = cells_total；changed ≤ in_scope。

### 10.2 负例与写盘测试（investigation/apply/_negative_tests.py 扩展）

- 冻结格被写 → 拒绝；跨 silo 行 → 拒绝；num 被改 → 写前复核中止；商店 price/stock/flag 字节变化 → 测试失败。
- 池回退不得抛出未捕获异常：报告列出 silo、原因，其余池照常。

### 10.3 基准与构建

- 新 golden：固定 (cfg, seed) 的「其他物品」计划 + 「全部」计划，进 randomization-dryrun/golden/；改引擎若改变结果必须显式更新 golden。
- build_exe.py：把 item_world.py / item_slots.py / item_names.py 加进 PIPELINE，item_freeze.json / item_value_tier.csv / item_slots.csv 加进 DATA 与 _assets/ 同步；空目录四道自检全过。
- GUI 自检（--uicheck）增：范围三选一切换、G 卡片灰化、重要位置面板计数、写入确认文案警告、方案库 metadata。

### 10.4 试玩验收（技术 + 人工）

1. 只随机其他物品：进游戏走到一个赐福，捡 3 个拾取点、杀 1 个普通怪、逛 1 个商人 —— 物品变了、价格/限量没变。
2. 全部模式：职业物品也变，且说明书文本同步、法祷护甲整套仍在、冻结项（灵马笛/圣杯瓶/遗物）原地。
3. 敌人随机 + 物品同层（一次写入）：两个都生效，无崩溃。
4. 回滚：删 Plan= / 还原原始 → 干净回到原版。
5. **人工**：手感与「重要位置」是否符合预期（agent 不能替人拍板）。

## 11. 失败与报告（如实呈现，不静默）

| 情形 | 行为 |
|---|---|
| silo 池太小/结构冲突，错排无解 | 整池不动；报告 fallback_pools（silo_key、单元数、原因）；GUI 摘要显示「N 个池未动」 |
| 未知/悬空 id 格 | 剔出池，计入 cells_unknown；不写 |
| 冻结表/价值表/槽表缺失 | 拒绝生成并指出缺哪份资产（不降级成「随便跑」） |
| 重要位置面板全关 | 允许；权重滑块显示「当前无重要位置，权重不生效」 |
| 三态 Important 但池里无重要格 | 该组回退 Anywhere + 告警 |
| 写前复核失败 | 中止，不写文件；GUI 按现有诊断提示（原始备份/版本/半途写入） |
| 层的方案指纹变化 | 方案库下次开玩重建整层（现有 _lib_layer_fresh 逻辑） |
