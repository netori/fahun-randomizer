## 2. 这一期实际做了什么（口径）

- **交换单位** = `NpcParam` 的**一整行**（一种敌人 = 一行）：血量 / 伤害 / 抗性 / AI 引用 / 掉落…全都跟着走
- **不动的**：`EntityID`、位置、外观（模型在 MSB 里 —— 那是二期）、**阵营 `teamType` 与生成方式 `npcType`**（交换后从原行恢复）
- **池子**：照抄原版敌随 —— 类别池 + 加权来源池；目前三类：
  `Boss`（`isSoulGetByBoss=1`，**170** 行）/ `精英`（hp 高的敌对，**1114** 行）/ `普通敌人`（**5057** 行）
- **体型护栏**：先按 `chrHitRadius`/`chrHitHeight` 自动分四档，**桶内置换** —— 这样"大的不许塞进小的"
  是**由构造保证**的，同时保证置换是双射（种类守恒）
- **比例**：`rate` 控制每个子池里有多大比例参与（同种子确定性）
- **来源标签**：`全部敌人` / `只随机法魂敌人`（后者等分类表补上后生效，现在会**如实报警告**而不是静默）
- **排除**：友好 NPC / 有名有姓的独特角色（实测 736 个有名字的行里只有 26 个是 Boss）
  → 先不参与杂兵池（保守）；想放开就用人工复核表逐行指定 `cls`
- **种子**：敌人用 `seed|enemy|<类别>|<体型>` 独立随机流 → **改动物品设置不会影响敌人结果**（反之亦然）

## 4. 我替你做的决策（不同意就说）

1. **一期只做 regulation 级**（数值/AI/掉落互换、**外观不变**）—— MSB 真换敌人留二期：
   地图解析还没走通（探针只到 `MSB ` 魔数那一步），半夜写没验证过的地图改写器风险太高。
2. **部署时现场生成敌人计划**（不存计划文件、只把设置塞进 `cfg["enemy"]`）：
   同种子 ⇒ 同结果，方案库天然会保存它，也省掉"计划文件与库不同步"这类坑。
3. **"有名有姓的行"先进 skip**：因为没法从字段上可靠区分"友好 NPC"与"有名的敌人"，
   而误换 NPC 的后果比少换几种敌人严重。**人工复核表（CSV：row_id,cls,source,name）已经留好接口**，
   填进去就能放开。
4. **阵营与生成方式交换后恢复**（照原版敌随的先例：他们换完也会重新套 `teamType`）。
5. **体型按桶置换**而不是"逐对判断再跳过"——后者会破坏双射（自检当场抓到过）。
6. 顺手把 `enemy_names.py` 的 FMG 修复用在了**只读名字**上（不改写、不影响随机结果）。
