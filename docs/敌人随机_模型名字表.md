# 敌人随机：462 个模型的名字表（含「无名杂兵」的统一名）

> 数据：`investigation/enemy_model_names.csv`（462 个模型 × 27,780 个位置，由 `enemy_data_build.py --names` 从位置表汇总）

> 名字源：参考实现的 `diste/Names/ModelName.txt`（454 条）/ `ModelNameNT.txt`（218 条）；游戏血条名（`boss_healthbar.csv`）；无名杂兵的统一名（本表生成）

## §0 三句话

1. **462 个模型的名字全有着落了**：291 个来自参考实现的 ModelName 表、136 个来自游戏给 Boss 头顶血条起的名字（中文）、**24 个无名杂兵按参考实现的做法给统一名**、11 个查证后人工命名。
2. 参考实现就是这么干的：`GameData.cs:742` 名字表里查不到 → **直接返回模型号本身**；`EnemyPreset.cs:1024` 给基础类命名成 `"Basic {model}"`。所以我们也不卡住，统一叫「法魂杂兵（cXXXX）」，**24 个模型 445 个位置照常参与随机**。
3. 这 24 个统一名杂兵自成一类 `Mob`（**只在彼此之间互换**，不会跟士兵 / 野兽 / Boss 混），你哪天认出某个的真名或真类，改一行它就搬家。另有 11 个假人 / 危害物（圆桌厅堂训练假人、弹丸假人、闪电球变体）标 `policy=keep`，不参与随机。

## §1 名字从哪来（优先级）

1. **血条名**（中文）—— 游戏只有 Boss 才有血条，所以有血条名 = Boss 级；同一个模型出现在两个 Boss 身上时会并列（如「风暴呼召者塔兰、风暴敕令者科温特、MarikaLineageWoman」）。
2. **参考实现的 ModelName 表**（英文，454 条，覆盖原版具名敌人与大部分杂兵模型）。
3. **ModelNameNT 表**（不翻译的名字，如 `Furnace Golem`）。
4. **统一名**「法魂杂兵（cXXXX）」—— 前三个源都没有时。根因：这些模型的 `NpcParam.nameId` 是 0，游戏压根不给它们准备名字条目（普通杂兵本来就不显示名字）。

## §2 「统一名」是怎么定类的

- 参考表里有这个模型 → 用它给的类（`cls_src=ref`）。
- 参考表里没有、但有血条名 → 临时归 `Boss`（`cls_src=auto:bossbar`），等你在法魂池（楔石 / 追忆 / 圣龛 / 传送门）里给个位置（见 §5）。
- 参考表里没有、也没名字 → 归 `Mob`（`cls_src=auto:noname`），统一名，纳入随机，只在 Mob 池内互换。
- 假人 / 危害物 → `Dummy`，`policy=keep`。

## §6 怎么复跑 / 这张表怎么用

- 重算：`python investigation/apply/enemy_data_build.py --names`（不出 MSB，只读两张现存表，1 秒级）。
- `--build` 会先重扫 MSB、重建位置表，然后顺带重算这张名字表。
- 列含义：`model` / `display_name` / `name_src`（血条名·ModelName·generic·人工指定）/ `cls` / `cls_src`（ref·auto:bossbar·auto:noname·dummy）/ `placements` 位置数 / `npc_rows` 涉及的 NpcParam 行数 / `hp_min`·`hp_max` / `boss_any` / `policy`（randomize·keep）。
- 这份表是后续 `enemy_classes_v3.yaml` 的**输入**：yaml 里只写「覆盖项」（人工改类 / 改 policy / 归法魂池），没写的按这张表的默认值走。
