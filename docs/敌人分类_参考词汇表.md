### 1.1 类 → 布尔的翻译（四个游戏各一套）

派生布尔字段声明在 EA:288-321：`IsBossTarget`(:291)、`IsBuffSource`(:294)、`IsFixedSource`(:298)、`IsImportantTarget`(:301)、`HasPerceptiveNose`(:304)、`IsArenaTarget`(:307)、`IsImmortal`(:310)、`IsMortalSekiroBoss`(:314)、`SourcePhases`(:317)、`TargetPhases`(:319)。

**Elden Ring（任务点名的 :1004-1018）**，原文：

~~~csharp
// ER 分支（ER:1004-1018）
IsBossTarget      = Class == EnemyClass.Boss || Class == EnemyClass.MinorBoss || Class == EnemyClass.Evergaol;   // :1007
IsImportantTarget = IsBossTarget || Class == EnemyClass.Miniboss
                    || Class == EnemyClass.DragonMiniboss || Class == EnemyClass.NightMiniboss;                   // :1008-1010
HasPerceptiveNose = IsBossTarget;                                                                              // :1011
IsBuffSource      = IsImportantTarget;                                                                          // :1012
IsFixedSource     = IsImportantTarget;                                                                          // :1013
IsArenaTarget     = IsImportantTarget;                                                                          // :1016（注释 :1014-1015 说 ER 其实是 entity 级的，此处只是“先复用这个布尔”）
IsImmortal        = HasTag("immortal");                                                                          // :1017
~~~

即 ER 的语义分层是**三层半径**：`Boss/MinorBoss/Evergaol` = BossTarget（内圈）⊂ `+Miniboss/DragonMiniboss/NightMiniboss` = ImportantTarget（外圈）。`Basic`/`Wildlife`/`Scarab`/`HostileNPC`/`Helper` 全为 false。

其余三个游戏（同一函数内）：
- Sekiro（ER:971-979）：`IsBossTarget = Boss||TutorialBoss`；`IsBuffSource = IsBossTarget||Miniboss`；`IsFixedSource = IsBossTarget||FoldingMonkey`；`IsImportantTarget = Boss||TutorialBoss||Miniboss||FoldingMonkey`；`HasPerceptiveNose = IsBossTarget`；`IsArenaTarget = IsImportantTarget`；`IsImmortal = Boss && !HasTag("mortal")`；`IsMortalSekiroBoss = (Boss && mortal) || TutorialBoss`。
- DS3（ER:983-990）：六项全部 `== (Class == Boss)`；`IsImmortal = HasTag("immortal")`。
- DS1（ER:994-1002）：`IsArenaTarget = Boss||Miniboss`（:1000）；`IsImmortal = HasTag("immortal")`。

### 1.2 ClassConfig 六个配置位（EA:759-777）

`Classes` 块的每一项是一个 `ClassConfig`（EA:759）。

| 字段 | 声明 | 语义注释 | 实际被谁读 |
| --- | --- | --- | --- |
| `Class` | EA:761 | 类本身 | EP:868-875（按类建 map）、EP:606-614 |
| `Parent` | EA:763 | “Parent class to optionally merge into” | EP:713（checkMerge 分支）、EP:724（非 merge 分支的继承源）、EP:729-733 沿父链上溯 |
| `AltParent` | EA:765 | “Other possible parents” | EP:713-717：仅当 `assign.ManualParent` 落在这个列表里时才替换 parent |
| `NoSelfRandom` | EA:768 | 不能在自己这一类里随机，只能并进父类（注释：与 randomizedTypes 冗余） | EP:219-222（`if ((NoSelfRandom \|\| NoMerge) && Class != Spectator) assign.Pools = null`，即**清空自池**）、EP:613（`appendPool(..., !conf.NoSelfRandom)`） |
| `DefaultInherit` | EA:770 | 默认行为是没指定池就继承父类池 | EP:215-218（`assign.InheritParent = true`）、EP:724、EP:841 |
| `NoMerge` | EA:774 | 不能并进父类、也不能被并进来、不能用于 Oops All；此情形下不该有 parent | EP:366（`!conf.NoMerge && assign.MergeParent`）、EP:712、EP:841、EP:929、EP:1424（`allowOops = !conf.NoMerge`） |
| `DlcSilo` | EA:776 | “allows siloing DLC. Disabled for classes which only appear in one or the other.” | **0 处消费**（全 RandomizerCommon 只有这一行声明）。真正的 DLC silo 走运行时选项：ER:510-513、ER:1522-1536、ER:2112-2116（`opt["dlcsilo"]` / `preset.OverallSilo` / `AreaSiloType.DLC`） |

关于“并进父类”的完整语义链（这是 NoMerge/Parent/AltParent 真正起作用的地方）：
- EP:700-737 `GetParent(cl, ann, checkMerge)`：最多循环 10 次；`checkMerge` 分支（EP:713）`if (!conf.NoMerge && assign.MergeParent)` → `parent = conf.Parent`，若 `conf.AltParent.Contains(assign.ManualParent)` 则改用 `assign.ManualParent`；非 merge 分支（EP:724）`if (assign == null ? conf.DefaultInherit : assign.InheritParent) parent = conf.Parent`；EP:729-733 沿父链一路上溯到 `targetClass`；EP:735 转超 10 圈直接抛 `Internal error: loop in parent hierarchy`。
- EP:706-707 注释：“Merge will always take precedent in the randomizer itself”。
- ER:332-350：ER 无 preset 时走 `MakeClassBasedDefault`；`opt["mergeboss"]` 打开时把 `MinorBoss/Miniboss/DragonMiniboss/NightMiniboss/Evergaol` 五个类（ER:340）置 `assign.MergeParent = true`。
- EP:834-876 `ProcessParents`：`assign == null` 时若 `(!NoMerge && DefaultInherit)` 造一个 `{InheritParent = true}` 否则返回 null（EP:839-853）；然后按 `assign.MergeParent` 选 `GetParent(checkMerge:true)` 或 `GetParent(checkMerge:false)` 并继承父类的 `EnemyMultiplier`（EP:855-865）。

## 5. Categories 块的结构规则（enemy.txt:41-2463）

### 5.1 字段在数据里的实际用量（实测）

312 个 `- Name:` 条目中，带这些键的条目数：

| 键 | 条目数 | 首个出现的行 |
| --- | --- | --- |
| `Count` | 265 | 43 |
| `Instances` | 63 | 225 |
| `Partitions` | 60 | 220 |
| `Keywords` | 43 | 218 |
| `Classes` | 27 | 44 |
| `Region` | 16 | 97 |
| `Hidden` | 1 | 211 |
| `Contains` | 1 | 199 |

**单数形式 `Partition` / `Partial` / `Partials` / `Instance` / `Parents` 在数据里 0 次出现。** 模型字段存在（EA:62-66、:50），但 ER 数据只写复数形式。

两种形状：
- **类驱动型**（Basic / Boss / AllEnemies / AllBosses / DLCWildlife 等 27 个）：只有 `Classes` + `Count`，没有成员 id 列表。
- **命名型**（312 个里的其余）：`ParentClasses` + `Count`，可选 `Keywords` / `Partitions` / `Instances` / `Hidden` / `Region`。**没有任何成员 id**。

### 5.2 每个键在代码里怎么被解析

**`Classes`（EA:71）+ `Region`（EA:60）→ 决定“类名字符串”成为合法池名**
- EP:910-923：`foreach (EnemyClass cl in cat.Classes)` 时，若 `cat.Region != null` 则 `AddMulti(impliedDlcClasses, (cl, cat.Region == "dlc"), cat.Name)`，否则 `AddMulti(impliedClasses, cl, cat.Name)`——即“把**类别名**登记成该类的一个可用池名”。
- EP:925-937：再补一层，`if (!conf.NoMerge && !impliedClasses.has(class-string)) AddMulti(impliedClasses, conf.Class, conf.Class.ToString())`——类名字符串本身也是合法池名。
- 这两个 map 在 EP:1089-1096 被并进名字空间。

**`Partitions`（EA:63）/ `Partials`（EA:66）/ `Instances`（EA:69）→ 只是父类别的子名**
- EP:896-901：`subNames` 依次收集 `Instance + Instances + Partition + Partitions + Partial + Partials` 的 `Name`。
- EP:902-909：`subNames` 非空时，全部并入 `eligibleNames`，且 `impliedNames[subName] = cat.Name`（子名暗示父名）。
- EP:1109-1110（`debugNames` 分支里）逐个取 `subcat.Count` 与实际数量比对。
- EM:174-175 / EM:474-478：把子名收进需要翻译的名字集合。
- 结论：**Partition/Partial/Instance 三者代码路径完全一致**，没有语义差别；区别只在数据惯例（Partition=按类切，Instance=按具体个体/组合切，Partial=不完整覆盖）。
- 数据里的 0 次单数写法意味着 `cat.Partition` / `cat.Partial` / `cat.Instance` 三个**单值**字段是死字段（ER 数据永不填充）；但代码仍在 EP:896-901 里读它们（为其它游戏/手写数据留的）。

**`Contains`（EA:75）→ 唯一的并集构造**
- 数据唯一用法：`AllDragons`（enemy.txt:197-208）。
- 代码：EP:1164-1179

~~~csharp
foreach (EnemyCategory cat in cats)
    if (cat.Contains != null)                       // EP:1164-1179
    {
        SortedSet<uint> combinedIds = new();
        foreach (string name in cat.Contains)
            if (enemiesForName.TryGetValue(name, out var ids)) combinedIds.UnionWith(ids);
        if (combinedIds.Count > 0) enemiesForName[cat.Name] = combinedIds;

~~~

- EA:75 的注释限定用途：“When this category is defined as the union of two other categories … This is only used for dragons.”
- 反向证据：EM:172 / EM:472 在收集可翻译名字时**跳过** `Contains != null` 的类别（因为它只是并集，不独立存在）。

**`ParentClasses`（EA:52）→ 只用于显示**
- 声明 EA:52；**整个 RandomizerCommon 里唯一赋值处是 EM:640**（手写 `cats["Patches"] = new EnemyCategory { Count = 2, ParentClasses = new() { EnemyClass.MinorBoss } }`）。

- 唯一读取 EM:664：`Info = $"{cat.Count}x in {string.Join(" + ", cat.ParentClasses.Select(getClassName))}{suffix}"`——纯显示串。
- **数据文件里的 `ParentClasses:` 键在 C# 侧从不被读取**（YamlDotNet 会反序列化进属性，但没有任何消费点）：它不是池构建依据，连 EM:655 的检查也只对 EM 自己 new 出来的对象生效。→ 命名型类别对随机化**没有**任何结构作用。

**`Parents`（EA:50）→ 死字段**
- 全 RandomizerCommon 无任何赋值/读取（`EnemyMessages.cs:495` 的 `nameParents`、`EnemyPreset.cs:632` 的 `mergeParents` 都是同名局部变量，与此字段无关）。
- EA:50 注释：“Parent info with other categories, with not directed nested, for purpose of redundant category detection”。

**`Keywords`（EA:54）→ 死字段**
- 数据 43 次；代码侧唯一的读取点被注释掉：EM:659 `// if (cat.Keywords != null) suffix += $". Search keywords: {cat.Keywords}";`

## 6. 哪些分类是“池边界”，哪些只是显示/日志

这是本文件最重要的一节。结论先说：**决定“能不能换”的是 `EnemyClass`（经 merge 之后的 silo），不是 Categories 块里的任何东西。**

### 6.1 池边界的实现链（逐行）

~~~text
randomizedTypes（ER:300-323）—— 哪些类允许参与随机
   ↓
parentClass 字典（ER:358）+ siloClass(cl)（ER:376-379）
   ↓
EnemySiloType.Of(EnemyClass)（EPR:40）—— silo 的唯一键就是"类"
   ↓
perm.GetOrCreateSilo(siloType)（ER:1526-1538）
   ↓
sources = infos.Values.Where(i => siloClass(i.Class) == siloType)（ER:2080）
   ↓
canPlace(source, target, silo, …)（ER:1673 起）—— 只在同一个 silo 内配对
~~~

逐条证据：

1. **ER:300-323** `randomizedTypes`（成员行号）：`Boss`(303)、`Miniboss`(304)、`MinorBoss`(306)、`NightMiniboss`(307)、`DragonMiniboss`(308)、`Evergaol`(309)、`FoldingMonkey`(311)、`TutorialBoss`(312)、`Basic`(314)、`HostileNPC`(316)、`Wildlife`(318)、`CaravanTroll`(319)、`DupeOnly`(322)。`Scarab` **不在**列表里（:320 注释 “Scarab is not currently included here.”）。
2. **ER:1526-1528**：`EnemyClass infoSilo = siloClass(info.Class); if (!randomizedTypes.Contains(infoSilo)) continue;` —— 不在白名单的敌人**根本不进任何 silo**，因此不可能被换。
3. **ER:477-481**（dup 生成阶段）：`if (!randomizedTypes.Contains(info.Class)) dupeInfo.Class = EnemyClass.DupeOnly;` —— 不在白名单的类，它的复制体被降级成 `DupeOnly`（注释 :479 “Currently, this seems to be done for scarabs in Elden Ring”）。
4. **ER:376-379** `siloClass`：

~~~csharp
EnemyClass siloClass(EnemyClass cl)                                        // :376
{
    return parentClass.TryGetValue(cl, out EnemyClass parent) ? parent : cl;  // :378
}
~~~

5. **ER:366-368** 构造 `parentClass`：`if (!conf.NoMerge && assign.MergeParent && randomizedTypes.Contains(assign.RootParent)) parentClass[conf.Class] = assign.RootParent;` —— **NoMerge 直接阻断合并**（HostileNPC 因此永远自成 silo）。
6. **EPR:35-41**：`class EnemySiloType { public EnemyClass Type; public AreaSilo Area; }`，`Of(type) => new { Type = type, Area = AreaSilo.Default }`；`WithArea` 只叠加 DLC 区域维度（ER:1536）。**silo 的 Type 字段类型就是 EnemyClass —— 这是“池边界 = 敌人类”的编译期证据。**
7. **ER:2080**：每个 silo 的 source 池 = `infos.Values.Where(i => siloClass(i.Class) == siloType)`。
8. **ER:1570**：`siloClass(infos[t].Class) == siloClass(info.Class)` —— 判断“目标里有没有同类”也是按 siloClass 比的。
9. **ER:441**：`classDupeCount[siloClass(info.Class)]` —— 连 dup 计数都按 silo 计。
10. **ER:510-513 / :2112-2116**：DLC 维度由运行时选项 `opt["dlc"]` + `opt["dlcsilo"]` + `preset.OverallSilo` 决定，**不是** `ClassConfig.DlcSilo` 决定（后者 0 消费，EA:776）。

### 6.2 Categories 块的作用：只到“预设可写的名字”为止

Categories 的全部影响面收敛到一个字典 —— `enemiesForName`（EP:963-1101）：

- EP:892-909：类别名进 `eligibleNames`；子名（Partitions/Partials/Instances）也进，并记 `impliedNames`。
- EP:1015-1027：model 名、`"Basic <model>"` 也进（受 `nomodelname` 控制）。
- EP:1054-1062：**不在 `eligibleNames` 的名字被删掉**（这是 Categories 唯一的“门” —— 门内是配置面，门外什么也没有）。
- EP:1184-1229 `getIds(name)`：预设里的一个池名 → 具体 id 列表；`eligibleNames` 里有但此刻没有敌人（如 DLC 关闭）→ 返回**空列表而不报错**（注释 :1196）；完全不在 `eligibleNames` → 抛 `Unrecognized enemy name`（:1220 附近）。

因此：
- **类别名只约束“配置里能写什么名字”，不约束“谁换谁”。**
- 命名型类别（`ParentClasses` + `Count`，占 312 里的绝大多数）在池构建里**完全缺席**：`ParentClasses` 只服务 EM:664 的显示串，`Count` 只服务被关掉的 debug 打印。
- `Contains`（只有 `AllDragons`）把若干具名类别并成一个名字，**仍然是名字层**的并集（EP:1164-1179），不产生新的 silo。

### 6.4 三条容易被误判的事实

1. **“类”与“类别”是两套东西。** 类 = `EnemyClass` 枚举（25 值，25 行数据映射见 §1）；类别 = `Categories` 块的 312 个名字。前者是池边界，后者是命名空间。
2. **`Group` 是 tag 生产器，不是池。** ER:1223 把组名写成 tag，之后的 `exclude:*` / `frames` / `nosouls` / `npcpart` / `ballista` 判定都靠这个注入的同名 tag 生效；组本身不参与 silo 计算。
3. **合并（merge）是唯一能把“两个类并成一个池”的机制**，且被 `NoMerge`（EP:366、EP:712、EP:841、EP:929、EP:1424）与 `randomizedTypes.Contains(assign.RootParent)`（ER:366）双重把关；`AltParent` 只在 `assign.ManualParent` 手动指定时才改道（EP:713-717）。`NoSelfRandom` 则是最窄的一刀：清空自己的池（EP:219-222）并禁止自己作为池成员被追加（EP:613）——Scarab 因此在 ER 里只能并进 Basic、不能自我替换。
