# 敌人随机 v1 · M1 计划层报告（2026-10-20）

## 0. 三句话

1. 计划层把「哪些位置换成谁」算成一张 `plan.json`（25,656 个替换单元 → 22,661 个真换、24,628 个位置），不写游戏文件。
2. 候选范围由 `enemy_classes_v3.yaml` 的 `randomization.rules` 决定（任意类→任意类、逐条百分比），不再是写死的「同类互换」。
3. 难度守恒不靠"乘系数"，而是把**位置原本的血量/魂量**直接写进该位置独有的克隆行 —— 换进来的是谁都不影响这一格多难。

> 后续：M2 已把这份计划写成方案层，见 `docs/敌人随机_M2_写盘层报告.md`；参考实现功能对照见 `docs/敌人随机_参考功能对照.md`。

## 2. 规则矩阵：任意类 → 任意类

改 `investigation/apply/data/enemy_classes_v3.yaml` 的 `randomization` 段。规则是**有序表，第一条命中生效**：

| # | 规则 id | 命中（原位置的类/池/血条） | 百分比 | 可换成（目标类） | 区域 |
|---|---|---|---|---|---|
| ① | `multiphase_boss` | 多阶段组（v1.1，**默认关**） | 100% | Boss 六类 + Helper（整组一对一阶段） | 任意 |
| ② | `waygate_guardian` | 属于传送门池 | 100% | Boss / MinorBoss / Miniboss / NightMiniboss / DragonMiniboss | 同区域 |
| ③ | `bossbar_position` | **本来就有 Boss 血条**（位置表 `bar=1`） | 100% | 同上 | 同区域 |
| ④ | `boss_any` | Boss 六类 | 100% | Boss 六类（互相） | 同区域 |
| ⑤ | `fauna` | Basic / Wildlife / Mob | 100% | Basic / Wildlife / Mob（三族互换） | 同区域 |
| ⑥ | `scarab` | Scarab | 100% | Scarab | 同区域 |
| ⑦ | `caravan_troll` | CaravanTroll | 100% | CaravanTroll | 同区域 |

`multiphase_boss` 是 v1.1 的可选能力：它不是逐位置抽，而是把一整组阶段当一个单位互换。
只对 yaml `multiphase.groups` 里 `kind: phase` 且 `swap: true` 的 5 组生效（蕾娜菈 / 拉卡德 / 达格拉夫 / 拉达冈 / 玛莲妮亚）；
4 个有 `CreateReferredDamagePair` 的组不开（安塞尔河坏档根因）。开关默认关；关着时这条规则命中 0 个单元。详见实施计划 §M1.1。

`match.bar: true` 是 2026-10-20 实机反馈后加的一条：血条属于**位置的 EMEVD**，不属于模型。
换人不会丢血条，但**把有血条的位置换成普通杂兵**就等于把 Boss 战变成路人（实测：229 个有血条的位置里
有 32 行是 `Basic`，例如 `m18_00_00_00` 的「猎犬骑士哥廷」被换成了普通杂兵 —— 双 Boss 战少了半场）。
这条规则强制它们只换入 boss 级；判据是位置表的 `bar` 列（扫 267 个 `event/*.js` 得到，`--check` 逐行验）。

字段：

```yaml
- id: boss_only_to_boss
  match:   {cls: [Boss, MinorBoss], pools: [remembrance], area: base}   # 命中谁
  rate: 0.35                                                            # 这一类换多少（0..1）
  targets: {cls: [Boss, MinorBoss, Miniboss], areas: same}               # 能换成谁；"all" = 任意类
  size_max: 3.0            # 可选：换入者体型不超过原位 3 倍（只设上限）
  hp_band: [0.5, 2.0]      # 可选：只从"血量相近"的敌人里抽（默认不写 = 不限）
```

- **没命中任何规则 = 保持原样**（`default_rate: 0.0`）。所以加一条规则只会动它管的那批位置。
- **逐类权重（预设）**：GUI 的逐类预设给每个类一个换入权重（0–100），所有类归一化后就是「换进来的敌人里各类占多少」；总替换量由全局比例控制。权重只影响换入组成，不改变多少位置被换；这些**都不进种子**。
- **「某类 Boss 随全种类 Boss」** = `match.cls: [Boss]` + `targets.cls: "all"`；**「某类只随某类」** = 把 `targets.cls` 写窄。
- **池开关在前**：关掉一个池 = 该池位置保持原样，规则不再对它们生效；一个位置同属两个池时是**并集**（关一个仍随机）。
- **捐赠者黑名单**（`randomization.donor_deny`，2026-10-21 加）：模型级名单，列进去的敌人**可以被换掉，但不能当来源**。用途是「位置依赖型」敌人——唤声船靠边界传送、唤灵蜗牛/病花靠扎根召唤、仿身泪滴靠复制玩家，把它们推进别人的坑位只会得到一个不动/原地传送的废人。初版 4 个：c4950 / c4140 / c4480 / c1000；计划里写进 `meta.donor_deny`。后续把 c4950 从名单里拿出来做实验（见下条）；实验失败，**2026-10-21 下午已恢复**。

- **传送类敌人（`randomization.ai_fallback`，2026-10-21 加，当天下午已清空）**：原设想「克隆 think 行 + 把 `battleGoalID` 换成通用近战 goal 11000」去掉传送。**实机结果：换完完全不动**，比原来的原地循环传送更糟 → 已回退，c4950 回到 `donor_deny`，计划里不再有 `ai_goal` 单元。详见 M2 报告 §7.7。

## 3. 难度守恒：为什么不再乘系数

旧做法是「系数 = 原位置 hp ÷ 换入者 hp，再 clamp 0.6–2.5」。实测它并不守恒：**31% 的替换单元换完难度偏离 2 倍以上，最坏 68 倍**（27 hp 的位置换成 1939 hp 的敌人，0.6 倍仍剩 1163 hp）。原因是 clamp 卡的是**倍率**，不是**结果**。

现在的做法：M2 本来就要为每个位置克隆一条 NpcParam 新行（那是这个位置**独有**的，不是按种类共享的），所以直接把 `hp` 与 `getSoul` 写成**位置原值**即可：

| | 旧（乘系数 + clamp） | 现（直接写位置原值） |
|---|---|---|
| 换完 hp 与原来一致的比例 | 69% | **100%**（逐单元断言） |
| 最坏偏离 | 68 倍 | 0 |
| 对同类其它位置的影响 | 无（本来就没改共享行） | 无（克隆行独有） |

`coef_hp` / `coef_soul` 仍写进计划，但只作**记录**（换入者原本多强 ÷ 位置需要多强），供报告与后续攻击/防御缩放用。攻击/防御/韧性这类没有独立行字段的量留给 M4，用 SpEffect 乘系数，那时 clamp 0.6–2.5 才真正生效。

## 5. 抽样与种子

- **非双射**：一个敌人可以同时被多个位置抽中（参考实现也是独立抽样）；双射会让「抽到谁」被池子编号决定。
- 每个单元一个独立随机流：`rng = sha256(base_seed + "|" + unit_key)` 取前 16 位。所以**改一条规则 / 关一个池 / 调百分比，都不会把整张地图重排**（验收实测：逐条关规则只影响它管的单元，其它 `new_npc_id` 零变化）。
- **进种子的只有** `plan_version` + seed + 三份数据表的哈希。**不进种子**：池开关、规则表、百分比、clamp、`hp_band`。
- 同一个种子 + 同样的数据 → `plan.json` 逐字节一致（36,565,519 字符）。

## 7. 校验与自检

`--check` / `--selftest` 覆盖以下十几项（selftest 逐条打印 PASS）：

1. 同种子逐字节一致；换种子结果必变。
2. `keep` 单元零替换。
3. link 组两行同进同出（重复 MSB：同一地点在"打开/封印"两张图里各有一份）。
4. 多阶段 14 组 29 个位置零替换。
5. 关某个池只影响该池位置，其它单元零变化。
6. 负向账本覆盖全部单元（`units + skips = 全部`）。
7. 关某条规则只影响它管的单元（7 条规则逐条实测：0 / 22 / 141 / 74 / 22,223 / 191 / 10）。
8. 换入的类必须在该规则 `targets.cls` 内；传送门守门位与**有血条的位置**必须全是 boss 级（170 个 bar 单元实测全过）。
9. **难度守恒**：每个单元的 `target_hp` / `target_soul` 必须等于位置原值。
10. **多阶段整组替换（v1.1）**：默认关时 29 个位置零替换；打开后 5 组 10 个阶段全部整组换掉、组内阶段序号连续且来自同一捐赠组，其它单元 `new_npc_id` 零变化。
11. **逐类预设权重叠加**：只让 Basic/Boss 当来源、权重 50:50，实测换入 Boss 占比 49.1%（22,673 个替换单元）；`meta.preset.share` 与权重一致。
12. **生命值倍率**：1.5× 时 22,661 个替换单元的 `target_hp` 逐条核对。
13. **全替换为**：22,673 个替换单元全部换入 Boss（规则 `oops_all`）。
14. **手动指定**：按 `(map,entity)` 覆盖成指定 npc，条目带 `manual: true`，校验通过。

## 8. 已知限制（M2 要接的）

- **BGM 还是原位 Boss 的**（文献 H-003/H-019；血条名已于 v1.2 修掉）：换进来的 Boss 名字条会跟着换，但 BGM 仍由原位置的 90005870/`SetBossBGM` 参数决定。
- **血条本身会保留**：血条属于位置的 EMEVD（`DisplayBossHealthBar` / 90005870 / 90005876 模板），换人只改 MSB 身份层，所以原来有大血条的位置换完仍是大血条（名字仍是原位 Boss 名，见上一条）。**没有血条的位置**换成 Boss 级模型不会凭空长出大血条（v1 不给非 Boss 位加血条）。
- **hp/魂 的落点**：M2 必须真的为每个位置克隆 NpcParam 行并写 `hp`/`getSoul`；如果某个 npc id 后面没有空位，M2 要报错而不是覆盖。
- **防御/韧性/攻击** 跟着换入者原本的种类走（M4 再补），所以"同血量的 Boss 比原杂兵硬"是预期现象。
- `entity_id == 0` 的位置也能换（换的是身份层，不是脚本点名），但它们不参与需要 EMEVD 的功能（血条名/BGM/传送门）。
- **多阶段整组替换仍是实验（v1.1）**：阶段切换事件里还有 `ForceAnimationPlayback`，换模型后动画可能对不上；默认关，实机出现卡阶段/T-pose 就关掉重部署。
- `plan.json` 37.4 MB 不入库（`.gitignore`），5 秒可重建；正式种子在 M2/GUI 里定。
