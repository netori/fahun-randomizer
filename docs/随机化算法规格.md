# 随机化算法规格（v2 · 精确版）

> 目的：把「合理度 / 混池 / 流派隔离 / 守恒 / 说明书同步」写成一份**无歧义**的算法。
> 本文件只描述**规则与判据**，不含实现。

---

## 0. 记号

| 记号 | 含义 |
|---|---|
| `C` | 一个**格子**（unit）：游戏里能拿到某件物品的那个"位置"（宝箱/掉落/固定奖励…）。**随机化只改格子里放什么，格子本身不动。** |
| `I` | 一件**物品**（item）：有域 `dom`、档位 `tier`、流派 `arch` 等属性 |
| `G` | **说明书物品集合**：出现在职业说明书里的物品。**只有 `G` 内的物品参与随机与替换。** |
| `S` | **商店**：**默认不参与**（可在「更多设置」里开启；开启时只换货架上的物品，见 H4） |
| `kw` | 武器；`ka` 护甲；`kr` 卢恩 |
| `coh` | 合理度 ∈ [0,1]（界面 0~100%） |

**总不变量（任何配置都必须成立）**

1. **不搬位置**：格子集合、数量、概率、价格、库存、解锁、事件流程一律不动。
2. **守恒**：对流经随机的格子集合 `U`，其"持有的物品多重集"在随机前后**完全一致**（每个格子换走一件、换进一件）。
3. **范围**：新旧物品都必须属于 `G`；商店格子默认不参与（显式开启时才参与）。
4. **套装整体**：护甲套装不得拆散（见 §3.3）。
5. **可复现**：同一 `(配置, 种子)` → 完全相同的方案。

## 1. 物品属性（输入）

对每个物品 `i` 定义：

- `dom(i)` ∈ {武器, 护甲, 卢恩}
- `tier(i)`：**档位**，取值 `0..4`（见 §2）
- `arch(i)` ∈ {法师, 祷告, 近战}（只对护甲有意义）
- `set(i)`：所属套装标识（护甲）

对每个格子 `c`：

- `dom(c)`、`hold(c)`（当前放的物品）、`tier(c) = tier(hold(c))`、`region(c)`（所在地点档）

---

## 2. 档位（等级）的定义 ★核心

**统一为 4 级：`tier ∈ {0,1,2,3}`**（护甲与卢恩天然都是 4 级 ⇒ 两者可直接逐档对应）

### 2.1 卢恩 ★已定

`学徒=0、熟练=1、精通=2、大师=3、幽影=3`（**大师与幽影同档**）
> ⇒ 因此**不需要**"幽影卢恩是否并入大师级"这样的开关：两者本来就同档（界面上的那个开关已于 2026-10-14 撤掉，见 7.5.5 的旋钮体检）

### 2.2 护甲 ★已定

按**部位**定档：`臂=0、腿=1、身=2、头=3`

> 你的规则：**法师/祷告的装备不分等级（都差不多）** ⇒ 整个「法师/祷告」域**不参与档位判断**（其护甲与武器都按 §3.4 整域隔离、内部自由）。

### 2.3 武器 ★已定 = 候选 A

`tier = 该格子所在地区的推进度`，归入 4 档：

| 档 | 地区 |
|---|---|
| 0 | 宁姆格福、啜泣半岛、史东薇尔、摩恩城、雾林、啜泣… （新手区） |
| 1 | 利耶尼亚、魔法学院、盖利德、希芙拉河、安瑟尔河… |
| 2 | 亚坛高原、王城罗德尔、巨人山顶、化圣雪原、蒙格温王朝… |
| 3 | 米凯拉的圣树、渐崩的法姆·亚兹拉、深根底层、幽影之地… |

> 由「该武器所在格子的地区」决定，**而非**武器自身的强化等级。

### 2.4 档位跨度（由合理度决定的唯一旋钮）

```
span(coh) = 1 + round((1 - coh) * 3)          # ∈ {1,2,3,4}
桶( t )   = floor( t / span )                 # 允许互换的档位集合 = 同一个桶
```

- `coh = 100%` → `span = 1` → **同档位才能互换**（最严）
- `coh = 0%` → `span = 4` → **所有档位一个桶**（完全放开）
- 对应关系：100% → 1 ／ 67% → 2 ／ 33% → 3 ／ 0% → 4

> **这就是"合理度控制高低档混入比例"的精确含义**：允许互换的两个格子必须落在同一个桶里。
> v1 用 `step = round((1-coh)*4)` 有"90% 与 100% 等效"的平台，本式改为**5 档均匀**。

#### 2.4.1 单独设合理度（按类别）★2026-10-14 补

每个池按**自己的类别**取合理度，缺省（不传键）→ 跟全局 `coherence` 走：

```
类别 = 混池            → cfg["coh_mixed"]                （"混池·档组k" 这类池）
     = armor/weapon/rune → cfg["coh_domain"][类别]        （按池键的大类）
优先级：类别自己的 > 全局；两者算法与 §2.4 完全一样（span / 桶 / 越档率都按该值算）
```

两条推论（同时也是界面上的显示规则 —— 界面只列"真正起作用"的那几条）：

| 类别 | 何时有自己那一条 | 为什么 |
|---|---|---|
| 混池 | 当前会建混池（全部混合 / 两两混） | 混池的桶由它决定 |
| 卢恩 / 护甲 | 勾了、**且没有整类进混池** | "全部混合"时近战护甲与卢恩**整类**进混池 → 它们自己已经没有可分档的池了 |
| 装备（武器） | 勾了、**且武器没有进混池** | 进了混池那部分由「混池」条统管（作者 2026-10-14 要求与卢恩 / 护甲同规则）；不进混池时它管的是「高加成地区武器 ↔ 低加成地区武器」的互换概率 |
| （界面） | 上面这几条都藏在**「单独设合理度」总开关**后面 | 勾了才展开，且只摆当前真正起作用的那几条；看不见的值一律不进 cfg |
| 法祷护甲 | **没有** | 法祷护甲不分级（§3.4），合理度对它没有意义 |

> 缺省与显式填成全局值**逐字节一致**（负例 N11d 守着）—— 老配置、老计划不受影响。

### 2.5 合理度控制的另外两项（武器掺入比例 + 越档率）

```
w_mix(coh)   = 0.66 * (1 - coh)               # 混入混池的武器比例，上限 66%
cross(coh)   = (1 - coh)                      # 越档率：被“放行”的单元比例
```

- **越档幅度** 由 §2.4 的 `span` 决定（1~4 档）。
- **越档率** 由 `cross(coh)` 决定：每个单元以该概率被放行（放行者进入跨度桶，可在 `span` 内跨档）；
  **未被放行的单元严格留在自己的档位池**。
- 三者随合理度的变化：

| 合理度 | 跨度（幅度） | 越档率 | 武器掺入 |
|---|---|---|---|
| 100% | 1 | **0%** | **0%** |
| 67% | 2 | 33% | 22% |
| 33% | 3 | 67% | 44% |
| 0% | 4 | **100%** | **66%** |

> 硬要求：**100% 时越档率必须为 0**（跨档在结构上不可能发生）。

### 2.6 护甲/卢恩混入混池比例 ★不随合理度

> 你的规则：**"装甲和卢恩的混入比例从始至终都是完全随机的"**；比例本身**无所谓**，
> 唯一的硬要求是 **100% 时不出现"卢恩高等级 ↔ 护甲低等级"这类跨级**。

⇒ 混入比例取**与 `coh` 无关**的随机值（默认 0.5，可调；以格子为键的稳定哈希 ⇒ 可复现）。
**但混入之后仍必须按 §2.4 的桶分开**（见 §3.5），这才是"不跨级"的真正保证。

## 3. 池构造与随机（算法主体）

### 3.1 分池

对每个格子 `c`（`dom(c) ∈ 已勾选的随机项目`）：

```
池键(c) = ( dom(c), 桶(tier(c)), 流派键(c), 部位键(c) )
流派键(c) = caster  若 dom=护甲 且 arch∈{法师,祷告,法师/祷告混合,祷告/感应,感应}
          = melee   若 dom=护甲 且其余倾向（含"近战"）
          = any     其余（武器/卢恩）
部位键(c) = set     若护甲是**完整四件套**（法祷护甲按整套处理，见 §3.3）
          = 臂/腿/身/头  其余护甲（**以物品 ID 后缀为准**，不看候选表的 subpool 字段）
          = 空      武器 / 卢恩（不参与这一轴）
```

**同名池合并为一个池**；每个池内部独立进行置换。

> **部位键是 2026-10-14 补进来的（踩过坑，别删）**：原先池键只有 (大类, 桶, 流派键) 三个分量，
> 于是「52 个法祷套装」和「13 个法祷散件」被并进同一个池 —— 而 §3.3 要求套装只能与套装互配、
> §3.2 又要求**整池一次性**满足全部配对约束 ⇒ 这个池永远找不到合法错排 ⇒ 按 §3.2 回退成"原样不动"。
> 表现就是**法祷护甲一件都不换**（实测 0/350 行，换种子/换合理度都一样），
> 连带**商店里卖法祷装备的 51 个货架也不动**（货架跟着物品走）。
>
> **流派键只有 caster / melee 两个值**：法祷**内部**是同一个池 —— 法师套 ↔ 祷告套属于正常池内置换，
> 必须隔开的只有"法祷 ↔ 近战"（§3.4）。历史实现里 `_pair_ok` / `verify` / 矩阵测试都写成过
> "法祷必须同流派"，那是与本节相矛盾的，已按本节改回。

### 3.2 池内置换（守恒的实现）

- 池内单位序号 `1..n`；用由 `(种子, 池名)` 派生的随机源做**错排**（derangement）：无固定点 ⇒ 每个格子都换到别人的物品 ⇒ 守恒天然成立。
- 若错排无解（池太小或结构冲突）⇒ **回退**：该池保持不变（并在报告里列出），**不得**用"半随机"蒙过去。
- 注意：错排是**整池一次性**求解的 —— 任何"池里存在永远配不上的两类单位"都会让整池回退。
  所以分池必须保证池内**同质**（同类、同部位、可配对），这正是 §3.1 要带部位键的原因。

#### 3.2.1 改动比例（按类别）★2026-10-14 补

每个池只让 **`round(池大小 × 比例)`** 个单元参与错排（随机抽子集；子集内部一一对应 ⇒ 守恒仍成立），
其余单元原样输出（`keep`）。比例按下列优先级取：

| 优先级 | 键 | 作用范围 |
|---|---|---|
| 1（最高） | `rate_sets` | 法祷**整套**装备（`armor·档组k·caster·set` 这类套装池） |
| 2 | `rate_caster` | 法祷**散件**（`armor·档组k·caster·head/body/arm/leg`） |
| 3 | `rate_shop` | **有商店在卖的**物品（见下：按**物品**抽，不是按行） |
| —（引擎保留，界面不暴露） | `rate_mixed` / `rate_domain` | 混池 / 按大类 |
| 4（默认） | `density` | 全局兜底（界面同样不暴露） |

- **界面只暴露两条**（2026-10-14 按作者要求收敛）：**法祷职业护甲**（= `rate_sets` 与 `rate_caster` 同值）
  与**商店物品**（= `rate_shop`）。其余键保留是为了老方案照旧能用，但界面上没有入口。
- `rate_shop` **必须按物品抽、不能按行抽**：同一件物品在货架与宝箱/掉落里是同一条记录（H9），
  按行抽会出现"货架换了、宝箱还是原来那件"。实现上把抽中的单元**移出池**（而不是事后改行），
  这样池内仍是双射 ⇒ 守恒（H2）不受影响；随机源与主序列分开（`f"{seed}|shop"`）。
- 这几个键**缺省（不传）就退回全局 `density`** ⇒ 老配置与老计划的行为逐字节不变
  （负例 N10d / N12e 守着）。
- 混池（`混池·档组k`）**不参与**按大类/按套装的单独比例 —— 它的成员跨大类，没有唯一的大类可判；用全局比例。
- 比例只影响"**换多少**"，不影响"能跟谁换"：硬约束 H6/H7/§3.4 一律照旧。
- **界面侧只传"用得上且勾了"的键**：第 1 步没勾的类别、以及"整套一起换"关掉时的 `rate_sets`，
  一律**不进 cfg**（等于跟随全局）—— 这样不会出现"界面上看不见、却仍在生效"的值。

### 3.3 套装（护甲）

- **近战护甲**：以**单件**为随机单位（臂/腿/身/头各自独立）。
- **法祷护甲**：**完整四件套**以整套为单位，**整进整出**（不得拆散）；凑不成完整四件套的
  **散件**（如只有身体的套装残件）按单件处理，**各部位各自成池**（臂池只换臂、头池只换头）。
- 部位一律以**物品 ID 后缀**判定（`part_of`），不看候选表的 `subpool` 字段 ——
  xlsx 基础里有 2 件的 subpool 把部位写错了，照它分池会头↔身/腿互串（矩阵测试能抓到）。
- 套装不得跨流派（见 §3.4）。

### 3.4 流派隔离（唯一需要隔离的轴）

> 你的规则：**"法祷近战需要隔离的只有装甲，其他的几乎完全没必要隔离"**；
> **"法祷的套装绝对不能混进来"**。

⇒ **隔离只发生在护甲**：`caster` 池与 `melee` 池**永不合并**。
武器与卢恩**不隔离**（它们本就是通用品）。

**法祷内部不隔离**（2026-10-14 确认）：`caster` 是一个池 —— 法师套 / 祷告套 / 混合套 / 感应套
彼此互换，只要**部位一致、整组进出**即可。要拦的只有"法祷 ↔ 近战"。句子里的
"法祷的套装绝对不能混进来"，指的是不能混进**近战/混池**，不是"法师不能换到祷告"。

### 3.5 混池

在 §3.1 分池之后，按下列规则并入一个"混池"集合（**混池本身仍按桶拆分**）：

1. **近战护甲**：按 §2.6 的随机比例抽 `m` 份进入混池。
2. **卢恩**：按 §2.6 的随机比例抽 `m` 份进入混池。
3. **武器**：按 §2.5 的比例 `w_mix(coh)` 抽一份进入混池。
4. 被抽中的单位从原池**摘除**，其余留在原池。
5. 混池**再按桶拆分**：`混池·桶k` 内部置换；不同桶之间永不互换。

#### 3.5.1 护甲 ↔ 卢恩 的逐档对应 ★已定

护甲的档位（部位 0~3）与卢恩的档位（0~3）**级数相同、含义同构**，因此混池中它们**直接逐档对应**，无需换算：

| 档 | 卢恩 | 护甲 |
|---|---|---|
| 0 | 学徒卢恩 | 臂甲 |
| 1 | 熟练卢恩 | 腿甲 |
| 2 | 精通卢恩 | 铠甲 |
| 3 | 大师 / 幽影卢恩 | 头盔 |

⇒ **100% 时**：`span=1` ⇒ 只有**同一档**的护甲与卢恩才能互换 ⇒ 高等级卢恩**不可能**落到低等级护甲位上，反之亦然。

> **含义**：混池 = "近战护甲 + 卢恩 + 武器一起随（但仍在同一档位桶内）"。
> **法祷护甲永不进入混池**。

### 3.6 未勾选项目的处理

未勾选的域**完全不动**（其格子不进入任何池）。

## 4. 说明书同步（由方案派生）

令 `place(i)` = 该物品在**原版说明书**里写的地点。

对说明书中的每一行 `(物品 X, 地点 L)`：

```
若 X 被随机过：
    Y = X 现在所在格子 c 的**原占用者**（即 plan 中 c 的 old 值）
    新地点 = place(Y)                       # 直接取原版说明书里的中文地点
否则：
    保持原样
```

**硬性约束（逐条自动校验）**

| # | 约束 |
|---|---|
| 1 | **物品名不动**，只改「 - 」之后的地点文本 |
| 2 | 标签结构（`<font size=…>` / `<font color=…>`）与原版**逐条一致** |
| 3 | 每条长度 ≤ **文本框上限**（= 原版最长条目），且不短于各自原长（不足用零宽空格补齐） |
| 4 | 地点不得为空、不得含英文内部名或符号 |
| 5 | 条目之间不得互相覆盖（含**首行相同**的多页 —— 必须按整串/表项定位，不得按前缀） |
| 6 | 物品-地点行数与原版一致 |
| 7 | 写盘后**核对其在游戏文件里确实存在且互不覆盖** |

> 若 `place(Y)` 不存在（Y 不在说明书里）⇒ 该行**保持原地点**，并计入报告。

## 5. 界面参数（与算法的对应）

| 界面 | 参数 | 作用于 |
|---|---|---|
| 随机项目：卢恩 / 护甲 / 装备 | `domains` 子集（≥1） | §3.1 分池范围 |
| 混合方式：全部混合 / 各自随机 | `cross_domain ∈ {真,假}` | 是否启用 §3.5 混池 |
| 合理度滑块 | `coh` | §2.4 跨度、§2.5 武器掺入比例 |
| 随机种子 | `seed` | 一切随机源 |

**固定项**：随机范围固定为说明书；商店**默认**不参与（可在「更多设置」里开启）。

## 6. 算法伪代码

```
输入: domains ⊆ {卢恩,护甲,武器}, coh ∈ [0,1], cross_domain ∈ {真,假}, seed

1  对每个格子 c: 计算 dom(c), tier(c), 桶(c), 流派键(c)
2  分池: 池 ← group_by(c, key=(dom, 桶, 流派键))
3  若 cross_domain:
       m ← 按 §2.6 随机比例抽出的 近战护甲 与 卢恩 单位
       w ← 全部武器单位 × w_mix(coh)
       把 m ∪ w 从各自原池摘除，另组「混池」，再按桶拆成 混池·桶k
4  对每个池 P:
       若 P 的错排无解 → 记入报告，保持原样
       否则 用 rng(seed, P.名字) 生成错排，写入方案
5  对每个格子应用方案 → 新物品
6  校验: 守恒 / 法祷零违规 / 套装完整 / 商店只在勾选时参与 / 可复现
7  说明书: 按 §4 重写地点 → 长度适配 → 七项校验 → 写盘
```

## 7. 已确认的决定（原 Q1~Q5）

| 编号 | 问题 | 决定 |
|---|---|---|
| **Q1** | 武器的档位由什么定？ | **A：地区推进度**（归入 4 档，见 §2.3） |
| **Q2** | 法师/祷告的武器是否也不分级？ | **只有护甲不分级**（修正）｜**武器一律按地区分档** |
| **Q3** | 卢恩"精通"是否并入 3 档？ | **保持 2 档**（只把 大师=幽影 同档） |
| **Q4** | 混池里护甲/卢恩的混入比例？ | **比例无所谓**；硬要求 = 100% 不跨级（⇒ 取与合理度无关的随机比例，默认 0.5） |
| **Q5** | 同一物品出现在多个格子时？ | **只按说明书上的文本为准**：物品在说明书里有几处，它的可换位置就是这几处；换进来的物品也必须落在这些位置上（兼容性最好） |

### 7.1 对 Q5 的落地读法（请确认）

> "只按说明书上的文本" ⇒ 说明书是**位置集合的唯一来源**：

1. **参与随机的格子** = 说明书写到了位置的那些格子；说明书没写到的位置**不进池、不动**。
2. 同一个物品在说明书里出现 `n` 处 ⇒ 它在方案里有 `n` 个位置；各处**独立参与**互换（可能出现多份）。
3. 任意一次互换的两个位置，**都必须来自说明书里的位置集合** ⇒ 不会凭空产生说明书之外的地点。
4. 由 2 与 3 ⇒ **换进来的物品"本来就在这些地方有"**。

> 若第 2 条你希望改成"同一物品的多处**必须整体一致**"（即要么全换、要么全不换），告我一声，我改成"按物品整体参与"。

## 7.5 硬约束清单 ★合理度**允许**覆盖什么、**绝不允许**覆盖什么

> 这一节把散落在代码与实测教训里的约束**显式写下来**，用于防回归。
> 起因：我们踩过的每个坑（100% 仍越档、法祷混入、套装拆散、说明书串页）都源于"某条约束只存在于代码里、没写下来"。

### 7.5.1 合理度**允许**改变的（软约束）

| 允许 | 由谁控制 | 取值 |
|---|---|---|
| 档位跨度 `span` | 合理度 | 1 ~ 4 |
| 越档率 `cross` | 合理度 | 0% ~ 100% |
| 武器掺入混池的比例 | 合理度 | 0% ~ 66% |
| 护甲/卢恩混入混池的比例 | **纯随机**（与合理度无关） | 默认 50% |

### 7.5.2 合理度**绝不允许**覆盖的（硬约束）

无论合理度拖到多少（**包括 0%**）、无论种子如何，以下任何一条都不得被破坏。
**违反任何一条 = 方案作废**，不得"继续执行"、不得静默降级。

| # | 硬约束 | 为什么 |
|---|---|---|
| **H1** | **不动位置**：格子集合、数量、概率、价格、库存、解锁 flag、事件条件一律不变 | 产品第一原则；动了就可能卡关 |
| **H2** | **守恒**：参与随机的格子集合，其持有物品**多重集**在前后完全一致 | 每个格子换走一件、换进一件；否则玩家丢东西 |
| **H3** | **范围 = 职业说明书**：新旧物品都必须属于说明书物品集合 | 范围之外的东西不该被牵动 |
| **H4** | **商店默认不参与**；显式开启时，商店行**只换物品**，价格 / 库存 / 解锁条件**一律不变** | 商店牵扯解锁与库存，默认不碰；开启后也必须只换物品 —— 已用逐字节比对证明只动 equipId 与 equipType |
| **H5** | **冻结项不参与**：被排除表列出的物品不得进入置换 | 审核状态必须被尊重 |
| **H6** | **法祷护甲永不进混池**，且法祷池与近战池**永不合并**（法祷**内部**自由互换 —— 法师套 ↔ 祷告套属于正常池内置换） | 唯一需要隔离的轴（用户规则）；"法祷内部也隔离"曾是实现里的误解，导致整块冻死 |
| **H7** | **套装整组进出、不拆散**；法祷护甲按整套处理 | 拆散会让玩家拿到半套 |
| **H8** | **一个格子只能被一个单元占用**（错排无固定点、无重复目标） | 否则同一格子被写两次 |
| **H9** | **同一物品的多处获取点必须整体一致**（要么全换、要么全不换） | 用户规则："整体换过来" |
| **H10** | **物品身份 = (类别, 数字 ID)**，任何比较/分组/去重都必须带类别 | 实测：767 行计划里有 **6 处**同一数字 ID 出现在不同类别 —— 只用数字 ID 会误判 |
| **H11** | **说明书**：物品名不动；`<font>` 标签结构与原版一致；长度不超文本框上限；条目**不得互相覆盖**（含首行相同的多页） | 分别对应三次实测故障 |
| **H12** | **写前复核**：写入前必须再确认目标格子的原始 ID 与类别与计划一致；不一致**立即中止**，不得留下半成品 | 防止"写了一半"的中间状态 |
| **H13** | **确定性**：同一 `(配置, 种子)` 必须得到逐字节相同的方案 | 用户规则；也是复盘与分享的前提 |
| **H14** | **池内必须同质**：同一个池里不得存在**永远配不上的两类单位**（套装 ↔ 散件、头 ↔ 身…）。部位键必须进池键（§3.1） | 错排是整池一次性求解的：混进一类配不上的单位 ⇒ 整池回退 ⇒ **一整个大类的物品一件都不换**（2026-10-14 法祷 + 商店 51 个货架的真凶） |
| **H15** | **候选格子必须与游戏文件对得上**：索引里存在、但 `regulation.bin` 里其实是空槽/别的物品的格子一律剔出候选（`investigation/apply/stale_cells.json`），用 `investigation/apply/audit_cells_vs_file.py` 对账 | 这种格子在计划里会带着一个假的 `old` ⇒ 写前复核（H12）中止**整次写入**，表现是"点了写入什么也没发生" |

### 7.5.4 计划字段（v1.1 起新增 4 列，旧列顺序不变 ⇒ 向后兼容）

| 列 | 含义 | 解决什么 |
|---|---|---|
| `engine_version` | 生成该计划的引擎版本（当前 `1.1`） | 跨版本对照：同一个种子在不同版本下是否等价 |
| `algorithm_mode` | 本次池结构：`tier_uniform` / `tier_mixed` / `tier_mixed+joins` | 复盘"当时用的是哪种模式" |
| `unchanged_reason` | 该行没换的原因（`kept_by_plan` = 按计划保持原样） | 区分"没换"与"忘了换" |
| `preconditions` | `old=<类别:数字ID>|cat=<类别>` | **写前复核**：写入前逐条比对当前文件，不一致立即中止（H12） |

**H12 的实现位置**：`native_apply.check_preconditions()` —— 在 `apply_native()` 真正动字节**之前**运行；
不通过则抛 `PreconditionError`，**输出文件根本不会被创建**。
旧版计划（没有该列）自动跳过复核，保证向后兼容。

### 7.5.5 这些约束由什么守着

| 关卡 | 位置 | 覆盖 |
|---|---|---|
| 引擎矩阵 | `investigation/apply/_matrix_test2.py` | 15 配置 × 6 种子：守恒 / 可复现 / 法祷零违规 / 压缩帧 |
| **负例回归** | `investigation/apply/_negative_tests.py` | H1~H13 的边界与负例（16 项，含"首行相同 → 串页"的真实 bug 回归） |
| **基准对照** | `investigation/apply/_golden_check.py` + `randomization-dryrun/golden/` | 冻结 golden plan，逐行对比 —— 发现"无意改动了随机结果" |
| 说明书审计 | `investigation/apply/_guide_audit.py` | 标签 / 长度 / 物品名 / 空地点 / 串页 / 行数 / 落盘 / 幂等 |
| **写前复核** | `investigation/apply/native_apply.py` | 写入前逐条比对旧 ID 与类别；不一致抛 `PreconditionError` |
| **旋钮体检** | `investigation/apply/check_config_effects.py` | 每个配置项各跑一对配置，验"**结果真的变了、方向对**"（当前 14 项有效 / 0 异常 / 1 项已知空转：幽影卢恩 —— 界面已于 2026-10-14 撤掉那个开关） |

### 7.5.3 硬约束与合理度的关系

```
合理度只放宽「跨档的幅度与比例」，
绝不放宽「位置、守恒、范围、隔离、套装、身份、确定性」。
```

> 换句话说：**0% 意味着"等级完全放开"，不意味着"什么都能乱来"。**

## 8. 相对 v1 的修正点（都来自实测）

1. **武器必须真分档**：v1 对武器一律给 2 档 ⇒ 100% 也跨档。
2. **混池必须按档位拆**：v1 写死 `("mixed", 0)` ⇒ 100% 也跨档。
3. **档位跨度改为均匀 5 档**：v1 的 `round((1-coh)*4)` 让 90% 与 100% 等效。
4. **套装/流派隔离只作用于护甲**：武器与卢恩不隔离。
5. **说明书必须按整串/表项定位**，不得按前缀（否则同职业多页首行相同 → 串页）。
6. **说明书长度以"文本框上限"为准**，逐条按自身原长会误伤长条目。
