# 敌人随机 v1 · M3 读取端闸门（enemy_gate.py）

> 2026-10-21 凌晨。前情见 `docs/敌人随机_M2_写盘层报告.md`。

## 0. 三句话

1. M2 证明「我把该写的东西写对了」，M3 证明「引擎真的把它们读进去了」——两件事不能互相代替。
2. 工具是 `investigation/apply/enemy_gate.py`，只读、不写任何文件；三组检查：层完整性、引擎加载证据、传送门自检。
3. 静态部分现在就能跑（`--offline`，已 PASS）；**带日志的那一段必须人开一次游戏**，因为它读的是 `YAFSML.log` 里真实发生的 override。

## 1. 它证明什么 / 不证明什么

| 证明 | 怎么证 |
|---|---|
| 方案层文件没缺、没被改过、没有陈旧残留 | manifest 里 499 个文件逐个比 sha256；层目录里多出任何文件都算 FAIL |
| 引擎加载的是**这一层** | 读 `YAFSML.log` 最后一次 `added mod Plan from`，路径必须是本层；出现别的层的 override 直接 FAIL |
| 本层真的被读进去了 | 本次会话里 `regulation:/`、`event:/common_func.emevd.dcx`、`mapstudio:/<图>.msb.dcx` 的 override 都来自本层路径 |
| 传送门位置换得对 | 28 个守门位在**写出的层里**已经是换入身份，克隆行的 `hp`/魂等于位置原值、`isSoulGetByBoss` 已清 |

| **不**证明 | 由谁负责 |
|---|---|
| 换进去的敌人好不好玩、像不像 | 只有人能说（试玩 + 场景戳） |
| 血条名 / BGM 是不是原 Boss 的 | 已知限制（H-003/H-019），v1.2 |
| 攻击/防御/韧性对齐 | M4（SpEffect） |
| 进游戏会不会崩 | 首启实测（H-018 已 0.95）：能进档、能加载 64 张图 |

## 2. 怎么跑

```powershell
# 静态（游戏不用开）：层完整性 + 传送门自检
python investigation\apply\enemy_gate.py --label 敌人v1_seed1 --offline

# 全量（引擎至少加载过一次这一层之后）
python investigation\apply\enemy_gate.py --label 敌人v1_seed1

# 指定日志（默认取 <法魂包>\yafsml\log\YAFSML.log）
python investigation\apply\enemy_gate.py --label 敌人v1_seed1 --log "<包>\yafsml\log\YAFSML.log"
```

退出码 0 = PASS，1 = FAIL（逐条列出哪一项、差多少）。

## 3. 三组检查的判据

### ① 层完整性
- manifest 里每个 `{rel, bytes, sha256}`：文件存在 + 指纹一致；缺一个就 FAIL。
- 层目录（`<层>/mod/`）里出现 manifest 之外的文件 → FAIL（陈旧残留/半套）。
- 实测：写集 **499** 个（497 张图 + regulation + common_func）/ 磁盘 499 个 / OK。

### ② 引擎加载证据
- 从日志里找**最后一次** `[mod] added mod Plan from `<path>``，path 必须指向本层（不然说明你加载的是别的层）。
- 该会话之后、`mod=<本层路径>` 的 `file override` 行 → 归一成 manifest 的相对路径；`regulation.bin` 必须在列。
- 有地图 override 却**没有** `event/common_func.emevd.dcx` → FAIL（血条补丁没生效）。
- 别的方案层的 override → FAIL；本层出现 manifest 里没有的文件 → FAIL。
- **未加载不算失败**：只走到一部分地图时，剩下 486 个文件本来就不会被访问；工具会写一行「未加载（本次没走到那些图，不算失败）」。

### ③ 传送门自检（28 个守门位）
- 计划里 `pools` 含 `waygate` 的单元 → 经 manifest 的 `clone_ids` 映射到真正写进 regulation 的克隆行。
- 每行核对：`hp` = 位置原值、`getSoul` = 位置原值、`isSoulGetByBoss` 位已清（守门位的魂照给）。
- 每个位置在**层里的 MSB** 上核对：`npc_id` = 克隆行、`think_id` = 计划的 think（b2m 时是 think 克隆行）、`model` = 计划换入模型。
- 为什么是"层里的 MSB"而不是"内存里的计划"：这一条要证明的是**磁盘上的产物**，不是我们以为写了什么。

## 4. 当前证据（2026-10-21 00:5x）

| 检查 | 结果 |

| `--offline` | **PASS**：499/499 文件指纹一致、0 个多余文件；28 个守门位 / 27 条克隆行全部换入、数值与位置一致 |

也就是说：**静态全绿，动态等一次重启**。重启走 `启动法魂.bat`、读到存档后，再跑一次不带 `--offline` 的命令；`common_func` 出现 override 且 `regulation`/地图都在，就是 PASS。

## 5. 为什么这一环必须有人

日志里的 override 是引擎在**加载真文件**时写的，不是我们能模拟的；M3 的验收判据本身是「引擎读过这一层」。人只需要做一件机器做不了的事：**开一次游戏、进一次档**。玩得对不对（血条有没有回来、Boss 名是不是还旧、难度像不像）也只有人能说。
