# 界面改版：从「开发者工具」变成「产品」

> 起因：作者反馈 —— 方案库该**单开一个界面**；目前**交互太奇怪，不像成熟产品**。
> 现状：主窗口是**一根竖长条**（980×740，五个 LabelFrame 往下排）；方案库是**另一扇小窗**，
> 里面**一排 12 个按钮**，每个动作都弹对话框。

---

## 一、问题清单（现状为什么不像产品）

| # | 问题 | 现在什么样 |
|---|---|---|
| 1 | **方案库没有"地方"** | 它是一扇弹出的临时小窗，关掉就没了；主界面里只有按钮 |
| 2 | **一排 12 个按钮** | 保存/写入/载入/改名/收藏/备注/复制/删除/导出/导入/刷新/打开文件夹，权重全一样 |
| 3 | **每个操作都弹对话框** | 改名弹、备注弹、标签弹、删除弹、详情弹 —— 想看一眼就得点一次 |
| 4 | **没有详情区** | 方案的种子、参数、备注、标签分散在一堆弹窗里 |
| 5 | **没有空状态** | 一个方案都没有时，列表是空的，也不告诉人该干什么 |
| 6 | **没有搜索/排序** | 方案多了只能靠眼睛找 |
| 7 | **删除没有"撤销"感** | 虽然实际进了回收站，但界面上完全看不出来 |

## 四、暗色主题的施工图（tkinter 有明确的坑，照这个写）

### 4.1 必须用 clam 主题

`ttk.Style().theme_use("clam")` —— 这是**唯一**会老实使用你给颜色的内置主题。
`vista` / `winnative` 会**忽略**你设的 `background` / `foreground`，界面上会一半暗一半亮。

### 4.2 配色（施工时按"看得清"定了最终值，下面的对比度是实测）

| 用途 | 色值 | 对比度（WCAG） |
|---|---|---|
| 窗口底 | `#1a1714` | — |
| 面板底 | `#232019` | — |
| 输入框底 | `#15130f` | — |
| 边框 / 分隔 | `#453e32` | 比第一版的 `#3a342a` 亮一档：暗底上太细的线"看不出来" |
| 主文字 | `#e8e2d4` | 13.8（窗口底上）|
| 次文字（说明 / 时间 / 字段名） | `#c3baa8` | 9.3 / 8.4（**第一版 `#a09884` 只有 6.2，作者反馈"字很不明显"就是它**）|
| **金（标题 / 强调 / 选中）** | `#c9a227`，亮金 `#e8c860` | 7.4 |
| 危险文字（删除 / 还原） | `#e0705e` | 5.2（第一版 `#b6433c` 只有 3.0，暗底上发闷）|
| 危险按钮悬停底 | `#8b352f`（配白字 7.9）| — |
| 选中行底 | `#3d3527`（配白字 12.1）| — |
| 禁用文字 | `#8b8578` | 4.4（第一版 `#6b665c` 只有 2.8，等于看不见）|

字号也跟着调了一档：正文 **11pt**、说明 **10pt**、标题 **15pt 粗**（原来 10 / 9 / 13 —— 中文在暗底上 9pt 太小）。
`--uicheck` 会把上表的对比度**当门槛跑**（正文 ≥10、次文字 ≥8、危险 ≥4.5、禁用 ≥3.5），改坏了当场报出来。

### 4.3 要逐个配的控件（漏一个就会冒出一块白）

```python
st = ttk.Style(); st.theme_use("clam")
st.configure(".", background=BG, foreground=FG, fieldbackground=FIELD, bordercolor=EDGE)
for w in ("TFrame", "TLabelframe", "TLabel", "TPanedwindow"):
    st.configure(w, background=BG, foreground=FG)
st.configure("TLabelframe.Label", background=BG, foreground=GOLD)      # 分组框标题
st.configure("TButton", background=PANEL, foreground=FG, borderwidth=1, focusthickness=0)
st.map("TButton", background=[("active", "#302a20"), ("pressed", "#3d3527")],
       foreground=[("disabled", DISABLED)])
st.configure("Accent.TButton", background=GOLD, foreground="#1a1714")   # 主按钮用金色
st.map("Accent.TButton", background=[("active", "#e8c860")])
st.configure("TEntry", fieldbackground=FIELD, foreground=FG, insertcolor=FG, bordercolor=EDGE)
st.configure("TCombobox", fieldbackground=FIELD, background=PANEL, foreground=FG,
             arrowcolor=GOLD, bordercolor=EDGE)
st.map("TCombobox", fieldbackground=[("readonly", FIELD)], foreground=[("readonly", FG)])
# 勾选框：clam 的指示器**不吃 indicatorcolor**，要配 indicatorbackground / indicatorforeground
st.configure("TCheckbutton", background=BG, foreground=FG,
             indicatorbackground=FIELD, indicatorforeground=GOLD,
             upperbordercolor=EDGE, lowerbordercolor=EDGE)
st.map("TCheckbutton", indicatorbackground=[("selected", GOLD)],
       indicatorforeground=[("selected", BG)])
st.configure("TScale", background=GOLD, troughcolor=FIELD)   # 滑块金色、槽是输入框底
st.configure("TNotebook", background=BG, bordercolor=EDGE, tabmargins=(6, 4, 6, 0))
st.configure("TNotebook.Tab", background=PANEL, foreground=SUB, padding=(18, 8))
st.map("TNotebook.Tab", background=[("selected", BG)], foreground=[("selected", GOLD)])
st.configure("Treeview", background=PANEL, fieldbackground=PANEL, foreground=FG,
             bordercolor=EDGE, rowheight=px(30))
st.configure("Treeview.Heading", background="#2b261d", foreground=GOLD, relief="flat")  # 最容易漏
st.map("Treeview", background=[("selected", "#3d3527")], foreground=[("selected", "#ffffff")])
# 滚动条：lightcolor / darkcolor 是 clam 自己画的高光/阴影边，不配就会推出一圈亮边（像白条）
st.configure("Vertical.TScrollbar", background=PANEL, troughcolor=BG, bordercolor=EDGE,
             arrowcolor=SUB, lightcolor=EDGE, darkcolor=EDGE)
```

### 4.4 五个已知的坑

1. **`tk.Frame` / `tk.Label`（不带 ttk 的）不认样式表** —— 必须**逐个**传 `bg=` / `fg=`。
   现有那个蓝色状态文字（`#06c`）在暗底上会看不清，要换成亮金或亮青。
2. **`messagebox` / `filedialog` 是系统原生窗口** —— 在暗色应用里会**弹出一块白**。
   这属于系统标准行为，可以接受；真在意就自己写对话框，但那是额外工作量。
3. **样式要在建控件之前设好**，否则先建的还是旧配色（要么先设，要么建完再 `st.configure` 一遍）。
4. **`ttk.Scale` 的滑块与槽分开配**（`background` 是滑块、`troughcolor` 是槽），
   配完要**实际拖一下**确认能看清位置。
5. **不做 DPI 感知，150% 屏上"字是糊的"**（这个坑最贵，第一版就踩了）：
   Windows 会把整个窗口**拉伸 1.5 倍再插值**，中文笔画当场发虚 —— 作者说的"字很不明显"一半是它。
   做法是**在第一个 `tk.Tk()` 之前**调 `SetProcessDpiAwareness(1)`（`randgui._enable_dpi_awareness()`，
   放在模块导入时执行），然后按 `winfo_fpixels("1i")/96` 量出缩放倍数 `S`，
   **所有像素间距都要乘它**（`px()` 辅助函数），字号不用动 —— Tk 按"磅"渲染，会自己跟着 DPI 放大。
   只做一半（只改 DPI 不改间距）会更糟：字大了、间距没大，控件互相挤。

## 八、第二轮：作者反馈"字很不明显"（2026-10-14）

一半是**配色**，一半是**DPI**——两个都改了，而且都做成可测的门槛。

**(1) 系统把窗口拉伸了。** 这台机器是 150% 缩放，而 Tk 程序默认**不是 DPI 感知**的：
Windows 把整个窗口放大 1.5 倍再插值，中文笔画当场发虚（对照实验的截图能一眼看出来）。
做法见 4.4 第 5 条：模块导入时 `SetProcessDpiAwareness(1)` + 按 `winfo_fpixels("1i")/96`
量出 `S`，**所有像素间距乘 `S`**（`px()`），字号交给 Tk 的"磅"自己放大。

**(2) 次文字色偏暗。** 实测（WCAG）：

| 用途 | 第一版 | 现在 |
|---|---|---|
| 次文字（说明 / 字段名）| `#a09884` = 6.2 | `#c3baa8` = **9.3** |
| 危险（删除 / 还原）| `#b6433c` = 3.0 | `#e0705e` = **5.2** |
| 禁用文字 | `#6b665c` = 2.8 | `#8b8578` = **4.4** |
| 边框 / 分隔 | `#3a342a` | `#453e32` |

字号整体提一档：正文 10 → **11pt**、说明 9 → **10pt**、标题 13 → **15pt 粗**。

**门槛化**：`--uicheck` 现在会把 4.2 表里的对比度当门槛跑（正文 ≥10 / 次文字 ≥8 /
危险 ≥4.5 / 禁用 ≥3.5），并且报出当前屏幕缩放 —— 以后再"调暗一点好看"会被当场拦下。

## 九、装饰件（AI 生图，2026-10-14）

界面里四处装饰是 AI 生的图，处理脚本 `_make_deco.py`，成品在 `_assets/deco/`：

| 用在哪 | 文件 | 说明 |
|---|---|---|
| 窗口 / exe 图标 | `icon.png`、`app.ico` | 金符文徽记；spec 里 `icon=` 指向 .ico，运行时 `iconphoto()` 换窗口图标 |
| 标题下那条金字 | `divider.png` | 藤蔓纹样，标题行下方居中 |
| 两个页签 | `tab_settings.png` / `tab_library.png` | 齿轮 / 书卷（22px）|
| 空库空状态 | `empty_plans.png` | 古书插画，压在"还没有方案"上面 |

**处理上的三个坑**（第一版都踩了，重做了一遍）：

1. **生成图的"黑底"不是纯黑**（约 `#0a0a0a`）。直接拿亮度当 alpha → 留下一层灰底方块。
   要先把低亮度**砍掉**（低于阈值的归零）再拉曲线，才是真透明。
2. **插画不能转透明**（照片感的东西转出来很脏）。改成"先削黑提亮 → 把黑点抬到窗口底色
   `#1a1714` → 椭圆羽化"，让它融进背景。顺序不能反：先抬黑点再提亮的话，背景会被抬得
   比窗口底色亮，又露出方块。
3. **每件出 1× 与 2× 两档**：程序按屏幕缩放挑（150% 屏用 2×），不然在高 DPI 上会糊。

**刻意的设计**：装饰件是**可缺省**的 —— `deco_image()` 找不到图就返回 `None`，
界面照常建起来（只有 `randgui.py` 一个文件也能跑）。要重新生成：把 AI 生的原图放回
`dsh-image-gen/`（文件名见脚本顶部），再 `python _make_deco.py`。

⚠️ 页签图标是**图**不是 emoji（原来用 ⚙/📚）—— emoji 在不同系统上长得不一样，
而且和金色主题不搭。
