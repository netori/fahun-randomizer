## 1. 界面：一页变三页

| 页 | 内容 |
|---|---|
| **职业物品随机**（原「随机设置」） | 物品那边的全部设置 + ① 生成 ② 写入游戏（**物品与敌人的合并写入走这条**） |
| **敌人随机**（新） | 敌人全部设置 + 「只写入敌人（做成方案层）」+「用这个方案玩」/「切回法魂本体」+「编辑敌人预设…」 |
| **方案库** | 不变；详情面板多了「用这个方案玩」 |

敌人那组控件原先塞在物品页的「更多设置」里 —— 两套随机其实是独立的（写不同的表、独立随机流），
混在一起既不好找也容易误以为必须一起开。

## 2. 方案层：每次随机顺手做成一个 YAFSML 覆盖层

依据（本机实测，不是推测）：
* `yafsml\YAFSML.ini` 的 `[mod]` 段原文：「**后声明的模组覆盖先声明的模组中的同名文件**」
* `使用说明.md`：「YAFSML 是运行时注入式加载器：游戏目录里的文件一个都不会被改」
* 关键体积：`regulation.bin` 只有 **2.9 MB**；地图按**文件**覆盖，只放改过的那几张（每张约 0.4 MB）

于是每次写入后会在 `法魂包\方案\<标签>\` 生成：
```
mod\regulation.bin                       部署完的那份（物品 + 敌人一起）
mod\map\MapStudio\<改过的>.msb.dcx        只有"真换敌人"时才放
mod\msg\zhocn\item_dlc02.msgbnd.dcx       只有同步了说明书、且与原始不同时才放
用这个方案启动.bat / 切回法魂本体.bat / 方案信息.txt
```
切换 = 在 ini 的 `[mod]` 段加/删一行 `Plan=…`；**法魂本体那行 `Convergence=../mod` 永不动**。
实测：挂载只多一行（+170 字节）、卸载后**逐字节复原**（写回时保持编码 / BOM / 行尾）。

**"只写入敌人"**：以**原始 regulation 备份**为底、只套敌人随机，产出独立的方案层。
实测表级比对：`ItemLotParam_map` / `ItemLotParam_enemy` / `ShopLineupParam` **三个表 hash 完全相同**、
说明书没进层 → 物品一个字没动。

⚠ 两条规则：① 同时只能挂一个方案；② 物品与敌人的产物都落在 `regulation.bin` 里，
**两者同时用必须合成一层**（分两层的话后挂的会把前一个顶掉）—— 所以主界面那条路本来就是合一的。

## 3. 敌人页照参考实现（thefifthmatt ER Randomizer）重做

参考实现是打包 exe（没源码），但界面代码在 GitHub 上（Avalonia/C#）：
`EldenRingRandomizer.Avalonia/Views/MainWindow.axaml`（敌人页在第 536 行起）、
`RandomizerCommon.Avalonia/Views/EnemyPresetView.axaml`、`RandomizerCommon/Enemy/EnemyPreset.cs`。

| 参考实现里的东西 | 我们的对应物 |
|---|---|
| 页签标题自带总开关 | 「敌人随机」标题旁就是勾选框 |
| 分组（Game progression / Misc / Enemy placement） | 三个分组：**参与类别** / **总体** / **这次会怎么改** |
| 每类可调（类别树 + 右侧面板） | 每类一行：勾选 + **该类自己的比例滑块** + 百分比 + 说明 |
| Ignore arena size for boss placement | **忽略体型限制（大的也能塞进小的）** |
| Separate enemy seed + Reroll | **用独立的敌人种子** + 🎲 重掷 |
| 预设摘要文字 | 摘要区实时写出参与类别、来源与各开关 |
| 页脚警告 | 「一次换掉太多 Boss 可能卡顿甚至崩…」 |
| 编辑细节走子窗口 | **「编辑敌人预设…」**：左类别 + 右面板 + 全局开关 + 导入/导出/重置/应用 |

引擎跟着补的两项（`plan_for_cfg` 会透传，**不透传就会静默吞设置** —— 差点就这么交出去）：
* `cfg.enemy_rates = {boss, elite, normal}`：每类各自的比例。实测 1.0/0.5/0.2 → boss 296 / elite 500 / normal 1019（严格成比例）
* `cfg.ignore_size`：分桶时合成一桶；双射与种类守恒不变，`verify_plan` 认得这个开关
  （打开时自检 0 问题；同一份计划按默认口径校验仍报 **2028** 条 —— 证明那条检查没被废掉）
