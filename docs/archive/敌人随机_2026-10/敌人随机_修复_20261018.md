## 1. P0-1 方案层路径（两个坑都修了）

1. **少一层 `\mod`**：`plan_layer.set_plan()` 把层根写进 `Plan=`，而 YAFSML 的 `[mod]` 要的是**数据根**
   （`<层根>\mod`）。现在 `set_plan()` 收到层根会自动补 `/mod`（`layer_mod_dir()`），
   调用点/native_deploy/manual_deploy/`.bat`/`方案信息.txt` 全部同步；GUI 敌人页用 `plan_status()`
   如实显示"当前挂载：…（⚠ 无效：缺 \mod）"。
2. **YAFSML 的 Plan 值有长度上限**（实机新发现）：绝对路径 132 字符时被截断，日志报
   `cannot find mod Plan in directory ...`，层仍不生效。现在只要目标在法魂包内就写**相对 yafsml/ 的路径**
   （`../方案/<层>/mod`，与 `Convergence=../mod` 同口径），既短又抗搬目录。
3. 现有坏 Plan 行已清（当时 ini 与原始备份逐字节一致）；当前 ini 只有
   `Plan=../方案/手动_20261018_201005_敌人+外观+血条名/mod`。

**验收**：实机 YAFSML.log 出现 `added mod Plan from .../方案/<层>/mod`，且本会话有来自方案层的
`file override`（mapstudio / mapstudio_dlc2 / event / regulation），会话内 0 条 ERROR。
**用户下一步**：以后换层用 GUI「只写入敌人」或双击层里的 bat 即可。

## 4. P0-4 Boss 池语义修正

- `enemy_ref.py`：`unkillable` 不再由 `exclude:unkillable` 标签（174 个模型）驱动，改为参考数据
  `Groups: unkillable` 组的 5 个显示名 → ModelName.txt 反查 **9 个模型**（∪ `norandom`）。
  重新生成 `enemy_ref.csv` / `enemy_ref_by_id.csv`（只改 unkillable 列：181 行）。
- 位域修复：`paramdef_fields` 的位域按 `(byte>>bit)&1` 读写；`isSoulGetByBoss`、`modelDispMask*`、
  `isMoveAnimWait` 等 keep 不再 no-op。
- Boss 证据收紧：EMEVD 血条链优先；`isSoulGetByBoss` 不再单独当 Boss（要求 hp≥1000 且模型档位不否证）。

  只有这类行才有血条名字和配套 AI；`isSoul/ref-Boss` 升上来的行不进 Boss 池（`cfg boss_only_emevd=False` 可退回）。

  （避免失去 AI）；`u.model` 写回 + 多阶段分组不再把通用模型 323 行并成"巨型组"误升 Boss。

**验收**：Boss 池 213（含 75 个 unkillable 行仍默认不动）；`boss_rows` 337 实体覆盖 256/337 = 76.0%
