# 分类复核：与参考实现（thefifthmatt）的逐模型对照

> 作者的原话是「我看看那些怎么知道填什么，你想办法查下」—— 这份就是"想办法"的结果。
> 我没有让你对着坐标猜，而是找到了**第二方人工意见**并把两边对齐。

## 1. 数据来源

参考实现（ER Randomizer 428）是打包 exe（没源码），但它自带一份数据目录 `randomizer/diste/`：

| 文件 | 内容 |
|---|---|
| `Base/enemy.txt`（1.9 MB） | **23,173 条**人工维护的敌人条目：`ID / Map / Name(cXXXX_YYYY) / Class / Tags / ExtraName / BuddyGroup / …` |
| `Base/annotations.txt`（134 KB） | 物品侧的人工标注 |
| `Vanilla/regulation.bin` | 它自己带的原版 regulation（我们直接用游戏本体的那份，就没用它） |

它的 `Class` 是**人工档位**（Basic / Wildlife / Scarab / Miniboss / MinorBoss / NightMiniboss /
DragonMiniboss / Boss / Helper / Evergaol / None），`Tags` 里还有：
`multi`（多阶段）、`size:N`、`arena:N`、`perceptive`、`exclude:unkillable`、`npcitem`、`partial`…

我们把结论转成自己的表（**运行时不再依赖它那边任何文件**）：
* `investigation/enemy_ref.csv` —— 模型级：ref_class / multi / unkillable / size / arena / perceptive / 真名
* `investigation/enemy_ref_by_id.csv` —— 条目级（保持原样，留给后面的逐点用途）

## 2. 对齐结果

* 我们有数据的模型 **456**，参考实现覆盖 **394**，两边都有 **388**
* **Boss 判定一致率：87.4% → 92.5%**（接上它的档位之后）
* 剩 **29 个不一致**（`investigation/model_class_ref.csv` 有全量，`enemy_ref_overview.md` 有清单）

这 29 个看着吓人，其实是两类**粒度差异**，不是"认错怪"：

| 类型 | 例子 | 为什么两边都对 |
|---|---|---|
| 同一个模型：杂兵位是 Basic，Boss 位是 Boss | `c5840`（参考 Basic×26 / 我们 boss×18）、`c4820`（Omenkiller）、`c3701` | 我们的 `cls` 是**行级**（这一行是否有 Boss 魂 / 血条），它的 `Class` 是**摆放级**。两边都成立 |
| 档位语义不同 | `c3251`（它 Miniboss / 我们 boss）、`c5860`（DragonMiniboss）、`c4980`（NightMiniboss） | 它的 Miniboss = 有 Boss 待遇、但没有 Boss 魂的那种。我们的规则是"参考档位优先，**但不会把已判 Boss 的行降级**" |

**处理原则**（已写进引擎）：参考档位优先，我们只在其**未标注**时兜底；并且**不降级**
（带 Boss 魂 / 血条的行保持 boss —— 那是硬证据）。剩下 29 个就这样留着，不硬凑一致。

## 3. `size:N` 不能当体型护栏（差点做错）

本来打算把它的 `size:N` 用到我们的"防大怪塞进小怪位"护栏上。交叉核对之后**否掉了**：

| 模型 | 参考 size | 我们的桶 | 半径 | 名字 |
|---|---|---|---|---|
| `c4630` | **1** | 3（最大） | **2.3** | **Runebear Boss** |
| `c4020` | 1 | 2 | 1.5 | Royal Revenant Boss |
| `c4340` | 1 | 2 | 1.0 | Mad Pumpkin Head |

Runebear 是游戏里体型数一数二的怪，却标着 `size:1` ⇒ 这个 `size` 指的是**战斗场地/摆放档**，
不是模型体积。所以我们的护栏继续用 NpcParam 的 `chrHitRadius/Height` 自己推
（`size_bucket()`），它的 `size:` / `arena:` 只存着备用。交叉表在 `investigation/size_crosscheck.md`。

## 4. 顺带拿到的三样东西（都已接进引擎）

| 标注 | 规模 | 用法 |
|---|---|---|
| `multi` | 98 个模型 / 1312 行 | **多阶段整组换**（阶段对阶段）；配对信息来自 `ExtraName`：`Rennala 1`/`Rennala 2`、`Beast Clergyman`/`Maliketh` |
| `exclude:unkillable` | 174 个模型 / 1910 行 | **默认不动**（换掉可能卡剧情），界面上有勾选框 |
| `ExtraName` | 101 个模型 | **938 行有了可读名字**（`Rennala 1`、`Frenzied Duelist`、`Miranda Blossom` …） |

## 5. 还剩什么

* 那 29 个不一致：已说明是粒度/档位差异，如果要统一成一套口径，需要你定"以谁为准"
* `arena:N`（52 个模型）：要真正用起来，得把"敌人摆放点"也做成可选的置换层级
  （现在是行级置换，场地信息挂在摆放点上，用不上）
* 法魂新增的 36 个模型：在参考实现 23173 条里**一个都没有**（它不带法魂的内容），
  这批只能靠人工或别的资料源，见 `investigation/models_to_review.csv`
