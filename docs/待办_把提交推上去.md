## 二、根因：你机器上的 GitHub 加速器挂了

**不是 GitHub 的问题** ✓ —— 官方状态页写着 "All Systems Operational"。

| 现象 | 证据 |
|---|---|
| `hosts` 把 40 多个 GitHub 域名指向 `127.0.0.1` | 条目后面标着 `#S302`，是加速器写的 |
| `127.0.0.1:443` 上蹲着一个服务（PID **20316**） | 它现在回 **502**，响应头是 `Server: Caddy` |
| **DNS 也被接管了** | `ssh.github.com` 解析到 **`198.18.0.81`**（加速器的虚拟 IP 段）|
| **直连真实 IP 一切正常** | `github.com → 140.82.113.3` 返回 **200** |

**所以浏览器、`git`、`gh` 全都用不了 GitHub** —— 不只是上传。

### 修法（二选一）

**① 重启那个加速器**（推荐，最省事）
它自己是坏的，重启它（Steam++ / Watt Toolkit 那类）通常就好。

**② 清掉 hosts 里那批条目**
用**管理员**打开 `C:\Windows\System32\drivers\etc\hosts`，
把所有带 `#S302` 的行**前面加 `#`** 注释掉，保存。之后 `github.com` 会正常解析。

### 修好之后，两条命令就完事

```powershell
Set-Location "F:\game\studygame\elden ring\THE_COVERAGE-随机开发\随机mod"
git push origin main
git push origin --delete push-via-api   # 顺手删掉那个半成品的分支
```

**13 个提交、完整历史、正确的中文文件名** —— 一次到位，不会再出今晚那些幺蛾子。

## 三、如果暂时修不了加速器：还有一条绕行路（但要清醒着做）

`_gh_push2.py` 走的是 **GitHub 的 Git Data API + 真实 IP**，**完全绕开**加速器，今晚靠它推上去了
13 个提交里的内容（只是最后没挂到分支上）。已经验证可行，剩下的活是：

1. **修分支更新那处** —— 现在的代码只在第一次成功建了分支，之后每个提交的更新没生效。
   改成：每推完一个就用 `PATCH /git/refs/heads/<branch>` 更新（**建分支只用一次**，
   之后一律走 PATCH）。或更简单：全部推完后**只更新一次**。
2. **处理"改名"状态** —— 脚本只处理了新增与修改，没处理 `R`（改名）。今晚就因此把
   `docs/RELEASE_v1.0.0.md` 留在了远端（本地已改名为 `RELEASE_v1.1.0.md`）。
   做法：`git diff --name-status` 输出里 `R100\told\tnew` 要**同时删 old、写 new**。
3. **`git diff` / `ls-tree` 必须带 `-c core.quotepath=false`** —— 否则中文文件名会被转义成
   `"docs/NEXUS_\346\225\264…"`，脚本照抄就会在远端建出**带反斜杠的垃圾文件名**。
   今晚已经踩过这个坑（建了 12 个垃圾文件，已删分支重来）。
4. 推完后再核对一遍**文件清单与内容**（按同一口径比对，别拿转义过的和原文比）。
