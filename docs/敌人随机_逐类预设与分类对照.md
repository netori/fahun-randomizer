## 0. 三句话

逐类预设编辑器已经做好：左边 16 个类别 + 4 个特殊池 + 全局，右边能调每一类的**开关 / 换入来源百分比 / 来源区域 / 目标区域 / 体型上限**，存成 JSON 可复用。
换入来源是**逐类多来源叠加**（和参考 mod 的 ClassAssignment.Pools 一样）：每个目标类各有一组来源类百分比，合计 100%，决定「这一类换进来的敌人里各来源占多少」。例如常规敌人 = 80% 常规敌人 + 20% 主要BOSS，主要BOSS = 60% 主要BOSS + 40% 次要BOSS；不同类可以配不同组成，不再是全局一套权重。
敌人种类没有变少：v1 的词汇是 **16 个类 / 19 个 silo / 462 个模型**；参考实现只有 **10 个类**（它的 268 个 category 名是预设词汇表，引擎只消费 10 个类）。
你之前在旧「敌型」列表里看到的 18 行是 **v0 遗留的展示词表**，不参与 v1；v1 卡片以前只显示 4 个池 + 6 条规则，所以看起来像少了。

## 3. 编辑器怎么用

入口：敌人页 v1 卡片 →「编辑逐类预设…」。弹窗左边是树：

- **全局设置**：比例语义（**按类百分比**（默认，参考 mod 的逐类池语义）/ 各自独立概率）、总替换量（0.05–1.0，权重模式控制有多少位置被换）、四个池开关。
  （多阶段 Boss 的位置与身份自 v1.3.15 起**默认常开、无开关**；v1.3.16 起按模型拆成 20 只 Boss，也不在这里设置。）
- **类别（9 个可见类，v1.3.12 起）**：每个类一行，后面是替换单元数。右边可以调：参与随机（关掉 = 这一类保持原样）、**换入来源百分比**（14 个输入格 = 9 类 + 4 个特殊池 + 「同类型 Boss」；合计 100%，可勾「自动平衡到 100%」；按钮「只同族 / 全部类别平均 / 清零 / 自动平衡」）、来源区域（本体+DLC / 仅本体 / 仅幽影地）、目标区域（同区域 / 可跨本体/幽影地）、体型上限（空 = 全局 3.0×）。
- **组成怎么叠加**：每个目标类独立算。例：常规敌人页填「常规敌人 80% + 主要BOSS 20%」，则换进常规敌人位的敌人里 80% 是常规敌人、20% 是主要BOSS；主要BOSS页另填「主要BOSS 60% + 次要BOSS 40%」，两类互不影响。权重模式里总替换量只控制「换多少个位置」，不改变某类内部的来源比例。
- **旧预设兼容**：没有 donor_weights 的旧预设仍按旧的全局 weight 推导出每类组成，行为与升级前一致；打开旧预设后不改任何百分比直接应用，不会改变抽签结果。
- **特殊池（4）**：传送门 / 钥石 / 追忆 / 圣龛的成员数与说明；这里只控制这次用不用它，成员由分类表决定。
  （圣龛池只有 1 个位置 —— 9 座圣龛共用同一个竞技场实体；v1.3.19 起它可随，取消勾选即恢复原样。）

底部：预设名、保存为预设、载入（内置规则或已保存的）、恢复默认、应用并关闭、取消。
预设存到 `investigation/enemy_presets/<名字>.json`；不保存直接「应用」也生效，但只到下次打开程序。

### 谁优先

顺序固定：**多阶段组 → 传送门守门位 → 本来有 Boss 血条的位置 → 逐类预设 → 其它**。
所以你把 Boss 关掉，传送门守门位与血条位仍然是 Boss 级；想彻底不换传送门，请关「黄金树传送门」池，而不是关 Boss 类。

## 4. 预设 JSON 与引擎

```json
{
  "version": 1,
  "name": "我的预设",
  "rate_mode": "weight",
  "classes": {
    "Boss": {
      "enabled": true,
      "rate": 1.0,
      "donor_weights": {"Boss": 60.0, "MinorBoss": 40.0},
      "targets": ["Boss", "MinorBoss"],
      "source_areas": ["base", "dlc"],
      "target_areas": "same",
      "size_max": 3.0
    },
    "Basic": {
      "enabled": true,
      "rate": 1.0,
      "donor_weights": {"Basic": 80.0, "Boss": 20.0},
      "targets": ["Basic", "Boss"],
      "source_areas": ["base", "dlc"],
      "target_areas": "same",
      "size_max": 3.0
    }
  }
}
```

- rate_mode: "weight" = 按类百分比（默认）；"independent" = 旧语义（每类 rate 是这一类位置被换的概率，互不影响），老预设没有该字段时按 independent 处理。
- donor_weights = 这一类自己的来源组成：键是来源类，值是权重（不必自己凑 100，规划时归一化；编辑器会显示成百分比并自动平衡）。targets 由正权重的来源类派生；旧预设的 weight 字段仍被读取，在没有 donor_weights 时按旧全局 weight 推导，行为不变。
- 引擎（investigation/apply/enemy_plan.py）：normalize_preset() 校验 donor_weights；class_donor_weights() 取逐类组成；preset_rules() 展开成规则并插在特殊规则之后；pick_donor(weights=..., fallback_weights=...) 先按来源类权重抽类再类内均匀，来源类不在候选时回落到规则/全局权重，仍无候选则候选池内等概率；class_mix_info() 给计划写归一化占比；计划 meta.preset.by_class 记每类的 weights/share 与 sha256 指纹；预设**不进种子**（改预设只影响它管的单元，其它单元抽签结果不变）。
- 目标类仍然会限制来源：某类只允许的 targets 不在它的 donor_weights 里时，这个位置不会被该类预设接管；特殊规则（传送门/血条/多阶段）仍先行 —— **v1.3.17 起它们的来源组成就是目标位置原类的 donor_weights**（没有则候选池等概率）。
- CLI：python investigation/apply/enemy_plan.py --build --preset <path> --out ...。

## 6. 已知限制

1. **按类设组成，不按 silo 分开**：`Boss|base` 与 `Boss|dlc` 共用一套 `donor_weights`；只能用「来源区域」整体开/关。
2. **模型级手选还没做**：参考实现能按具体敌人（如「不要鹰」）调；我们下一步做「模型例外清单」。
3. **目标区域只有同区域/任意**：还不能指定「本体→DLC 单向」。
4. **特殊规则先接管**：多阶段、传送门守门、血条位仍先于类预设；它们的来源组成**沿用目标位置原类**的 `donor_weights`（v1.3.17 起生效），该类没写组成或候选池里对不上时回落到候选池等概率。
5. **改预设不改已写出的层**：要重新「预览 → 部署」才生效。
6. **旧预设迁移**：没有 `donor_weights` 时按旧全局 `weight` 推导；一旦在编辑器里改了任一来源百分比并应用，就会写成新的逐类组成（预期行为）。
