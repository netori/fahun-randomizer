# 纯方案层模式：生成覆盖层，不写法魂本体（2026-10-23）

> 用户原话（m01243）：「现在还是没法直接通过启动器启动游戏，而不直接向法魂mod写入文件吗」
> 这一票把它变成「能」：生成 / 写入都只落进 方案\<层名>\mod\，法魂本体（mod\regulation.bin、
> 说明书）**一个字节都不改**；启动器挂层开局 = 玩这一套，删掉 Plan= 就是纯法魂。

## 一、旧流程为什么做不到

native_deploy.deploy() 的旧顺序是「**先写本体、再抄成层**」：

1. ② 把本体复原成原始（backup/regulation.bin.orig_*、item_dlc02.msgbnd.dcx.zhocn.orig_*）；
2. ④ native_apply.apply_native(plan_csv, source=reg, out_path=reg) —— **原地写本体**的 regulation；
3. ⑤ native_guide.apply_guide(source=msg, out=msg) —— **原地写本体**的说明书；
4. ⑦ export_layer() 才把本体里的这两份抄进 方案\<层>\mod\；
5. 一次写入（enemy_merge）再以**这份写过物品的本体**为 base_reg 构建敌人层。

于是「层」只是本体的一份快照：本体里始终留着物品随机，删 Plan= 也不是纯法魂；
不同方案的敌人层还会悄悄继承本体当时的物品改动。

## 二、现在的机制（deploy(overlay=True)）

同一个函数，换一个写入目标：

| 步骤 | 旧行为 | overlay 模式 |
|---|---|---|
| ① 备份 | 备份本体到 backup/deploy_pre_<ts>/ | **跳过**（本体不动） |
| ② 基底 | 复原原始 **→ 覆盖本体** | 原始两份 **→ 复制到** investigation/apply/work/overlay_<ts>/ |
| ③ 说明书 XML | 照旧 | 照旧 |
| ④ 物品 | 写本体 regulation.bin | 写**工作副本** work/overlay_<ts>/regulation.bin |
| ⑤ 说明书 | 写本体 msg\zhocn\item_dlc02.msgbnd.dcx | 写**工作副本**同名文件 |
| ⑥ 校验 | 读本体 | 读工作副本 |
| ⑦ 出层 | 抄本体的两份 | export_layer(reg_src=工作副本, msg_src=工作副本) |
| 一次写入 | 从本体 base_reg 建敌人层 | 从**工作副本** base_reg 建敌人层，再把说明书拷进层 |

产物：方案\<层名>\mod\ 下

- regulation.bin（物品 + 敌人，整份）
- msg\zhocn\item_dlc02.msgbnd.dcx（说明书，约 0.3 MB）
- map\MapStudio\*.msb.dcx（497 张）
- event\*.emevd.dcx（179 个）

**YAFSML 是文件级覆盖，所以层里必须是整份文件**（不是差分）—— 这也是每层约 35 MB 的原因。

### 3）踩到的坑（已修）

第一版层跑 enemy_gate --offline 是 **FAIL**：

```
[闸门] 完整性：写集 677 个文件（地图 497） / 磁盘 678 个 / 有问题
  - 层里多出文件（陈旧残留）：msg/zhocn/item_dlc02.msgbnd.dcx
```

原因：闸门用 manifest[files] 当写集，说明书是构建完才拷进去的，不在写集里。
修法：拷完说明书后把它追加进 enemy_manifest.json 的 files（含 sha256/bytes）并重算 bytes。
之后同一层 --verify 与 --gate --offline 都是 PASS。

## 四、边界（说清楚，别当 bug）

1. Plan= 那一行仍写在法魂包的 yafsml\YAFSML.ini —— 那是**启动器的挂载开关**，不是 mod\ 本体文件。
2. 「② 写入方案层」（只写敌人，v1 卡片中间那个按钮）**仍是旧路径**：直接 EW.build(base_reg=本体)。
   本体干净时它就是纯敌人层（不含物品）；本体带物品时会顺带继承。要做「物品+敌人」请用
   「①+② 一次写」。
3. 老层（2026-10-22 的 D/E/F 等）的本体里**仍留着当时的物品随机**。要回到「本体不动」：
   先退出游戏 → 点一次「还原成原始」→ 之后所有方案都用纯层。
4. 层大小 ≈ 35 MB/层（regulation 3.4 + 说明书 0.3 + 地图 31.2 + 事件 0.4）。
5. 说明书仍受原版长度约束（③b 长度适配、③c 审计照常跑）。

## 2026-10-23 傍晚：层不再提前建，改成开玩时按需生成

这一版把流程彻底掰成两段（旧流程是「开始随机 = 建层 + 挂载」）：

| | 以前（v1.3.3 及更早） | 现在（v1.3.4） |
|---|---|---|
| 点「开始随机…」 | 生成计划 → 立刻建覆盖层 → 自动挂载 | 只生成计划 → **存进方案库**（不建层、不挂载） |
| 想玩 | 到方案库点「用这个方案玩」（层已经在了） | 到方案库双击方案 → **需要时**才建层 → 换档 → 挂载 → 起游戏 |
| 方案库「写入游戏」 | 有（会提前建层） | 删除；只剩「用这个方案玩」 |
| 法魂本体 | overlay 模式下不写 | 同样不写，而且**连层都不提前建** |

判据（_lib_layer_fresh）：方案\<层名>\mod\ 在 + 构建记录在 + 方案指纹一致 + 敌人设置签名一致 ——
四条都满足才跳过构建；改过任何一项都会重建（整层替换，旧层先删）。

两种方案的构建路径：

- **有物品行**（物品 / 物品+敌人）：native_deploy.deploy(overlay=True, mount=False, plan_label=..., enemy_merge=...)
  —— 从原始 regulation 的 overlay 工作副本写物品 + 说明书，再叠敌人层，最后 plan_layer 导出到 方案\<层名>\。
- **只有敌人**（rows 为 0）：enemy_plan.build_plan + enemy_write.build(base_reg=plan_layer.find_pristine_reg())
  —— 直接从原始 regulation 起，物品一行不动。

实测（2026-10-23 14:25–14:31，真工作区 + 真法魂包）：

- 物品方案 766 行 → 存库 → 库内生成层：5 个文件；本体 regulation SHA 前 16 = 18b8c47e2cbddee9 前后一致；
- 敌人专属方案 → 层 678 个文件 / 171.7 秒；enemy_write --verify PASS（28,400 行 / 20,570 克隆 / 497 图 / 24,628 位置 / 387 条 SpEffect）；
  enemy_gate --offline PASS（写集 677 / 23 守门位）；
- 两个用例里 Plan= 都没有被改动。
