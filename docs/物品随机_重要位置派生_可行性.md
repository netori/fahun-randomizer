# 物品随机：重要位置六项在法魂数据上的派生 —— 可行性笔记（2026-10-24）

> 范围：参考实现 v0.12.2 中文物品页「将哪些位置作为重要位置?」六项，落到法魂 3.0.3 汉化本体（游戏 1.17.1）的本地数据。
> 口径：只读分析，不改产品代码；所有计数均可用文末命令复跑。金额/数量单位均为「格」（ItemLotParam 的一行 × 一个 slot）。

## 0. 结论（先行）

1. **参考实现的「重要位置」是槽标签，不是区域。** 六项分别对应 `itemslots.txt` 里 racemode/boss/altboss/seedtree/church/raceshop 等标签（`annotations.txt:4237-4274`），法魂要复刻只能从 param 反推「哪些格子原来装了什么」。
2. 法魂数据能**纯本地派生**四项：主要关键物品位置（145 格）、主要 BOSS 位置（31 格）、其余 BOSS 位置（12 格）、黄金种子/圣杯露滴位置（85 格）；交易商店只能派生到**行级**（1126 行 / 非魔法 1059 行），店级 25 家不可得；幽影庇佑 0 格，整项跳过。
3. **BOSS 击杀奖励不在 param**：245 个 BOSS npc 里 `itemLotId_enemy>0` 只有 8 个、有格的只有 2 个；31 条追忆全是小 id 行（EMEVD 发放），竞技场 map 行里一条追忆也没有。所以「谁掉什么」本期查不到，「BOSS 位置」只能按竞技场拾取格派生（50 格）。
4. 小型箱庭只能给**地图拾取格**打标（591 格，按实体号前缀）；敌人掉落格 4307 条没有唯一地图，80% 连 area 都推不出来，这项要等 #4 的地点槽表。
5. 五项合计并集 **272 格 / 7401（3.7%）**，远小于参考的 19+42+155+43+25（其口径是手工槽表，不是同一把尺）。

## 1. 参考实现怎么定义「重要位置」

- 六项在 `annotations.txt` 的 `LocationGroups`（`annotations.txt:4237-4274`）：racemode(always)、boss(always)、seedtree/church(受 raceloc_health 开关)、raceshop(raceloc_shops)、cross/fragment/revered(受 raceloc_scadu 与 DLC 开关)；排除项 missable(always)、minidungeon(nocaves)、night。
- `KeyItems` 组（`annotations.txt:4044-4058`）Mode Important，Requires `racemode+boss`，Excludes `missable/minidungeon`；即「关键道具只放这些槽」。
- `itemslots.txt` 实测（本地包 4379 条）：racemode 19、boss 50、altboss 168、seedtree 33、church 12、raceshop 25、minidungeonboss 61、cross 13、fragment 24、revered 17。
- **没有**独立的 `minidungeon` 标签（只有 `minidungeonboss`），nocaves 只能靠前缀/子串匹配 —— 参考自己也没做到「按区域排除」，是**按槽名排除**（不确定：未读到它的匹配实现）。
- UI 上的 42/155/43 与标签数 50/168/45 对不上，说明计数另有过滤（可能按地图号剔 DLC、按 missable 剔）。**不确定（缺参考实现的计数代码）**，但语义方向确定：**是槽集合，不是区域**。
- 结论：法魂的「派生面板」应产出**格集合**（与计划 CSV 的 slot 行一一对应），而不是区域名。

## 3. 六项逐项派生

### 3.1 主要关键物品位置（参考 19）

现成口径 = `goodsType1`（关键道具）的格。三种档位（"`乙`" 为建议默认）：

| 口径 | 定义 | 格 | 不同 id |
|---|---|---|---|
| 甲 | 全部 goodsType1 | 347 | 185 |
| 乙 | 甲 − 铃珠 81 − 地图/碎片 38 − 记忆石 15 − 泪滴幼体 32 − 龙心脏 22 − 失力战灰 14 | **145** | 80 |
| 丙 | 乙 中名字含 钥匙/符节/火种/卷轴，再加 修复卢恩/大卢恩/咒痕 | 33 | 24 |

- 六项扣除互不重叠（81+38+15+32+22+14=202，347−202=145），数字是算出来的不是拍的。
- 大卢恩 `type15` = 12 格 / 6 id（191 葛瑞克、192 拉塔恩、193 蒙葛特、194 拉卡德、195 蒙格、196 玛莲妮亚），另 10080 无缘诞生者的大卢恩在 type1 内；追忆 `type101` = 31 格 / 31 id。乙+大卢恩+追忆 = 188 格。
- **重要限制**：乙里只有 **59 格**的行号是 8/10 位地图实体号（53 本体 / 6 DLC），能对上具体位置；另 **86 格**是小 id 行（如 10011、2000…），行号本身不含地图，**位置不可判**（推测是 EMEVD 事件发放，缺 EMEVD 解析证据）。
- 乙 ∩ 箱庭前缀 = 7 格；丙几乎全是本体主线的钥匙/符节，箱庭交集更小。
- 建议：默认 **乙（145 格）**，并在面板标注「其中 86 格位置不可判、不参与箱庭过滤」；丙作为「只算推进核心」的可选档，甲不推荐（铃珠/地图/记忆石另有归属）。

### 3.2 主要 BOSS（参考 42）

- 敌人随机侧分类（`investigation/enemy_places.csv` 的 `cls` 列，规则见 `docs/敌人分类_现状盘点.md:150-165`）：`cls=Boss` = **94 npc / 117 摆放 / 53 图**；`boss_rows.csv` 337 行 / 233 实体 / 228 npc，其中只有 178 个 npc 落在 BOSSY 类（`docs/敌人分类_现状盘点.md:101-107`）。
- **掉落查不到（关键负结果）**：245 个 BOSS npc 里 `itemLotId_enemy>0` 仅 8 个，落成有内容的 lot 行仅 2 个（58100000→绳索 1 格、38050100→含苞墓地铃兰 1 格）；`itemLotId_map>0` = 0。31 条追忆全部是小 id 行（10011 接肢的追忆、10040 恶兆王的追忆…），**不在任何 BOSS 实体的 map 行里**；`lot_reward_index.json` 的字段只有 `table/lot_id/row_name/slots[]/getItemFlagId`，**没有 npc/boss 关联**，所以「谁掉什么」在现有证据里不可派生。
- **能派生的只有竞技场拾取格**：`ItemLotParam_map` 行号 ∈ BOSS 实体 id 的格 = **50 行 / 50 格**（1 行 1 格）。按 cls：Boss 29 + `Boss|Helper` 2 = **31 格**；Miniboss 6、NightMiniboss 2、MinorBoss 2、Evergaol 1、DragonMiniboss 1 = 12 格；Basic/Helper 7 格是随从/占位，不计。内容以强化素材 15、一般 9、黄金卢恩 6、关键道具 6 为主，没有追忆/大卢恩。
- 帕奇两条（523090010/523090210）在 `enemy_places` 里 `cls=None`，本来就不在 BOSSY，无需再排除。
- 建议：面板「主要 BOSS」= **31 格**（Boss+Boss|Helper），并明说这是「竞技场拾取位」，不含击杀奖励；数量低于参考 42 是数据机制差，不是漏算。

### 3.3 其余 BOSS（参考 155）

- 同一套分类的次级类：MinorBoss 73 npc、Miniboss 34、NightMiniboss 22、DragonMiniboss 14、Evergaol 8 ⟹ **151 npc / 161 摆放**。
- 竞技场格：Miniboss 6 + Night 2 + MinorBoss 2 + Evergaol 1 + Dragon 1 = **12 格**（另 7 格 Basic/Helper 不算）。
- 与主要 BOSS 相加 43 格；参考 42+155=197 的体量在法魂不可能复现（原因同 3.2：奖励走 EMEVD，param 里没有格）。
- 建议：默认**开**（只有 12 格，不会把水搅浑）；但要在 UI 文案里写「按竞技场拾取位计，非敌人数」。

### 3.4 黄金种子树与圣杯露滴教堂（参考 43）

- 这两个是**固定拾取点**，不是区域：当前格装的是黄金种子 `10010` / 圣杯露滴 `10020` 即算。
- 实测：10010 = **49 格**（map 46 / enemy 2 / shop 1）；10020 = **40 格**（map 39 / shop 1），合计 89；只看 map 拾取 = **85 格**（本体 76 / 小 id 8 / DLC 1）。
- 参考 43（33 树 + 12 教堂）是原版投放；法魂 3.0 改了投放（种子 46 处），所以 85 不是错，是 mod 的现状。
- 记忆石 10030（map 15 / shop 3）、护符皮袋 10040（0 格）不属这一项，已在 3.1 的扣除里。
- 建议：默认**开**，取 85 格（map）；enemy 2 格与 shop 2 行作为「同一物品的其它来源」列出但不计入位置数（它们不是树/教堂）。

### 3.5 交易商店（参考 25）

- `ShopLineupParam` 18 个字段里**没有 shopId、没有店级 flag**（`item_world_stats.py:117-121` 读取的字段同）：店级只能靠 `ShopLineupParam` 行区间或 ESD。
- 行级：1553 行，`value>0` 1126 行（沿用既有口径）、`value=0` 427 行（护甲 110000/110200 各 94、露滴 105000 56、追忆 102700 25、武器 102800/105095 等；**427 行是否真能按物品基础价买，未证实**）。
- 价块（连续行、gap>20）**31 段**，内容自洽（101507/101549 全护甲、105000 全露滴、102700 全追忆、110000-112124 各 25 行整块）；25 行块 103 个（76 个含售价行）。**块 ≠ 店**：同一店可拆成多块，只是近似。
- 参考 `itemlocations.txt` 的 45 条 `OpenRegularShop` 区间套到法魂只覆盖 **306/1126 行（27%）**、21 个区间有行 ⟹ 法魂表被重编号/扩表，vanilla 映射搬不过来；ESD（`script/talk/*.talkesdbnd.dcx`）才是店粒度权威，仓库无 ESD 解析。
- 法术行（goodsType16）67 行，全在售价行里；剔掉即「排除魔法/祷告商店」的近似实现：**1059 行**。
- 商店 type1 行 16 行（记忆石×3、泪滴幼体×2、失力战灰×4、菈雅的项链、星星泪滴等）。
- 建议：面板项改叫「交易商店（行）」= **1126 行 / 非魔法 1059 行**，默认**关**；若要显示「25 家」，写「≈31 个价块」并注明非店粒度。

### 3.6 排除小型箱庭（洞窟/地下墓地/英雄墓地/坑道）

- 敌人侧**没有** dungeon 字段：`enemy_classes_v3.yaml` 只有 `l1_classes/l2_silo/l3_tier/multiphase/pools`（`docs/敌人分类_现状盘点.md` 同口径），`enemy_places.csv` 也没有。

- 边界：m34 神授塔 63 格、m35 弃置恶兆之地 83 格**不是**小型箱庭，默认不排除（是否算「小型箱庭」需人拍板）。
- 交集：3.1 乙的关键道具 7 格、3.2 竞技场 1 格、3.4 种子/露滴 6 格落在此前缀内 ⟹ 这项开关实际影响 14 格。
- **缺口**：敌人掉落格 4307 条没有唯一地图（一只怪可多图摆放），80% 连 area 都推不出，**无法逐格打箱庭标签**；要等 #4 的地点槽表。本期若开这个开关，只能对 map 格生效，enemy 格一视同仁。
