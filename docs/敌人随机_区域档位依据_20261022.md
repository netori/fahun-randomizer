## 结论

- 法魂没有单独的作者手写“地区等级表”，但保留了本体的 `NpcParam.spEffectID3` + `SpEffectParam` 等级缩放机制，并扩展到 110 个取值。
- **可以作为“区域相对倍率”使用**的是标准十步档：
  - 本体 `7000, 7010, …, 7120`（13 个）；
  - DLC `20007000, 20007010, …, 20007130`（14 个）。
  这两组在本体/DLC 内分别严格单调：血量、攻击、防御倍率随档位递增。
- **不能当地区档**的值：
  - `7130`：`maxHpRate=0.1`，明显是特殊/占位效果；
  - `7131–7151`：法魂自定义 Boss/特殊效果，数值不单调（`7150 maxHpRate=1.0`）；
  - `1935x`：人类 NPC 档；
  - `200072xx / 200073xx`：DLC 人类 NPC 档（参考实现也忽略）；
  - `4301 / 5300 / 0xFFFFFFFF`：异常/缺行，走兜底。
- 标准档直接覆盖 **20,637 / 27,780** 个位置（74.3%）；同地图标准档众数再补 **6,802** 个；剩 **341** 个（19 张图完全没有标准档）。合并覆盖约 **98.8%**。

## 数据来源与规模

- 当前法魂 `regulation.bin`：

## 难度参考有效性

- 标准档的倍率本身是单调的，直接证明它是“等级缩放”，可以作为区域相对倍率。
- 但“档位”不等于“绝对难度”：实际 HP = 基础 HP × `maxHpRate`，基础 HP 与类别差异很大。实测有效 HP 与档位倍率的 Spearman 相关：
  - Basic：0.553（n=10,485）；
  - Wildlife：0.906（n=462）；
  - Mob：0.616（n=233）；
  - 地图级（地图众数档倍率 vs 地图中位有效 HP）：0.731（203 张图）。
- 结论：**可以作为“这个区域的相对缩放”**，不能拿档位单独给单只敌人排名；单只敌人还要看它的基础面板和类别。
- 人类 NPC 档和 7130–7151 特殊档不参与，否则会把“特殊效果”误当地区难度。

## 推荐用法

1. 为每个位置取档：标准档直接用；非标准/0 取同地图标准档众数；19 张无标准档的图用中立 1.0 或手工表，并记录 fallback。
2. 按从低到高把标准档排成有序 section；base 段与 DLC 段分段排序，不混排。
3. 用 `SpEffectParam` 行的字段算 `source→target` 倍率；同档为 1。
4. 只把倍率乘到换入者面板上，不用旧位置基础 HP；类别桥接（basic→boss 的 `bosshp`、boss→basic 的 0.25 血/魂）另算。
5. 先做独立测试层，抽样验证同档、跨档、DLC 与 0 档兜底。

## 已落地（2026-10-22 23:0x 实现，23:3x 主层已挂载）

实现口径是「换入者整行 + source→target 区域 SpEffect」，不是给单只敌人按 ID 排名：

- paramdef：`enemy_randomizer.paramdef_fields` 把 `SpEffectParam` 映射到 `SpEffect.xml`（ER 的表名与定义文件名不一致），`FieldBook("SpEffectParam")` 可直接按字段名读写；行大小 907、payload 912（末尾 5 字节 padding）。
- 计划层：`enemy_plan._target_hp_for` 的 HP 模型 =
  - 默认写**换入者**的 hp；
  - 普通→Boss 且原位置更厚时写 `sqrt(原 hp × 换入 hp)`（参考实现的 `bosshp`）；
  - 魂默认仍写位置原值（`soul_follow` 另开）。
- 写盘层：`enemy_write` 为每个克隆行挂一条区域 SpEffect（id 从 1,900,000,000 起，避开本体/DLC 行号），倍率按 `SpEffectParam` 的 health/damage/defense/buildup/xp 字段算 `target / source`：
  - source 只看**换入者自己的 `spEffectID3`**，**按那一行的真实字段取值**（标准十步档与特殊档都算）；只有 0 / 行不存在 / 明显不像缩放的占位档（如 `7130` 的 `maxHpRate=0.1`）才记 1.0（中性），**不拿地图档替它补一个不存在的源倍率**；
  - target 才允许「同地图标准档众数」兜底（19 张没有标准档的图）；
  - Boss→杂兵（`b2m`）health/xp 再乘 0.25（参考实现 `ScalingEffects.cs:705-714`），**攻击力（`damage` 组）再乘 0.5**（2026-10-23 追加，见下节）；
  - 同档且非 b2m 不挂 effect。
- 参数化数值全部从当前法魂 `SpEffectParam` 读取；代码里没有写死任何 HP/攻击绝对值，也没有按档位 ID 硬排难度。

## 2026-10-23 修正：特殊档不能当「无档 = 1.0」

初版把「换入者 spEffectID3 非标准」一律当 source=1.0。这在**特殊档**上是错的：法魂给 Boss 用的 `7131..7151` 不是占位效果，而是真的在缩放（`7144`: `maxHpRate=6.6261`、攻击 ×2.6991）。

- **实测爆炸**：计划里 `m60_47_40_00|c4490_9000`（盖利德「大壶」传送门守门位）换成蒙格 `48000068`（`spEffectID3=7144`，`rel=b2m`）：原位置 44907275（hp 1750 / 档 7040）有效 HP 9,233；克隆行 hp 3,064 × 6.6261（蒙格自己的档）× 1.319（目标档 7040 × b2m 0.25）= **26,778**，攻击约 ×2.6991 × 2.5817 ≈ **×7**。
- **修法**：source 用那一档的**真实行**取值，再算 `target / source`。同例 hp 倍率变成 `5.2758 / 6.6261 × 0.25 = 0.1991` → 有效 HP **4,041**；攻击 ×0.9565 × 2.6991 = **×2.58**（就是「面板按目标区域档缩放」的本意）。
- **影响面**：整份计划只有 **35 个单元**的换入者是特殊档、**40 个位置**的原敌人是特殊档（标准档 19,686 / 19,564 不受影响）；区域 effect 行 343 → **390** 条。修正后的层 `敌人v1_区域缩放E_物品+敌人_种子20261010_1022_0040` `--verify` / `enemy_gate --offline` PASS、实机启动 ALIVE。
- 佐证：法魂本体 `regulation.bin` 里这些特殊档行确实带满 `maxHpRate` / `physicsAttackPowerRate`，不是「1.0 效果」；`7130`（`maxHpRate=0.1`）仍然按占位处理。

## 2026-10-23 追加：Boss→杂兵 攻击力砍半

试玩反馈「Boss 换到杂兵位，血量已经压下来了，但打人还是很疼」。原因：b2m 只压 health/xp，攻击力仍按「换入者自己的档 → 目标区域档」缩放；Boss 的基础攻击面板本来就比杂兵高好几倍，所以伤害仍是 Boss 级。

- **改法**：`AREA_BOSS_AS_BASIC_FACTORS = {"health": 0.25, "xp": 0.25, "damage": 0.5}`，`_area_factors` 对 b2m 按组再乘一次。只动 `damage` 组（`*AttackPowerRate`）：十步档本身只缩放这一组，`damagerate` / `defense` / `buildup` 在所有标准档里恒为 1.0，动它们等于凭空造一条游戏里不存在的规则。
- **数量**：整份计划 27 个 b2m 单元 → 26 条去重后的区域 effect 行（同 src/dst 组合共享）。F 层相对 E 层**恰好这 26 行 ×0.5、其余 3,381 行不变**（逐行比对，0 例外）。
- **示例**：蒙格那格 `7144→7040` 攻击倍率 `0.956 → 0.478`；`7800119` `0.7937 → 0.3968`；`7800214` `1.6991 → 0.8496`。血量不跟着动（还是 `0.1991` → 有效 HP 4,041）。
- **含义**：Boss 换进杂兵位 = 「血量砍到 1/4、伤害砍到 1/2」的精英杂兵，而不是「血厚、打人还是 Boss」。
- 调参入口就是这张表：嫌太软改 0.6，还是一招带走改 0.35；重建一层约 4 分钟（`enemy_write.py --plan <计划快照> --label <新名>`）。
