# 法魂敌人随机 · 可行性调查与方案（v0 · 只调研，未动代码）

> 日期：2026-10-15 ｜ 目标：给**法魂（The Convergence V3.0.3 · 汉化本体）**做敌人随机，
> 按**法魂的敌人分类**来区分，参考**原版敌人随机 mod** 的设置项。
> 本文所有结论都标了 **[实测]**（本机跑出来的）/ **[源码]**（一手代码）/ **[检索]**（二手）/ **[推断]** / **[待实测]**。

## 0. 结论先行

| 路线 | 能做到什么 | 投入 | 风险 | 建议 |
|---|---|---|---|---|
| **A · 纯 regulation「敌人参数随机」** | 敌人的**数值 / AI / 掉落**互换；**外观不变**（还是那个怪） | 小（1~2 天） | 低（复用现有写 regulation 的全套安全机制） | 可作为一期，但**不是你要的"敌人随机"** |
| **B · 改地图 MSB「真·敌人随机」** | 地图上的 A 敌人**真的变成** B 敌人（外观 + 数值 + AI + 掉落） | 大（1~2 周） | 中（写错地图 = 该图加载崩，可用"保守失败 + 一键还原"兜住） | **推荐主线** |
| **C · A + B 分期** | 一期先做 A（顺带把"敌人清单 + 分类 + 池"全部建好，B 直接复用同一套模型） | 分期 | 逐期验证 | **推荐做法** |

**一句话**：要做"敌人随机"，**必须动地图文件（MSB）** —— 因为**敌人长什么样**由地图里那条记录的 `ModelName` 决定，
`regulation.bin` 里根本没有"主模型"字段 **[实测]**。

好消息是：要改的那几个字段都是**定宽整数/短字符串**，可以**原地改写、文件长度不变** ——
这和现有工具"原地等长改 regulation"的技术路线完全一致，安全机制（备份 / 还原 / 干跑 / 写前复核）能直接复用 **[源码][推断]**。

## 1. 调查结果

### 1.1 法魂本机的敌人数据（实测）

把法魂的 `mod/regulation.bin`（2.9 MB，DCX+KRAK）解密解包后是 **64.8 MB 的 BND4，含 194 个 `*.param`**；用 Paramdex 的 ER 定义解析：

| 表 | 行数 | 行大小 | 说明 |
|---|---|---|---|
| **`NpcParam`** | **7823** | 358 B | 敌人的数值本体（hp / 伤害 / 抗性 / 掉落 / AI 引用…） |
| `NpcThinkParam` | 2613 | 114 B | AI 行为参数 |
| `CharaInitParam` | 3353 | 69 B | 角色初始化参数 |
| `NpcAiActionParam` | 109 | 10 B | AI 动作参数 |

**`NpcParam` 里能读到的关键字段（实测可读，值合理）**：

| 字段 | 行内偏移 | 含义 | 抽样实测值 |
|---|---|---|---|
| `nameId` | `+0x00c` (s32) | 名字 id（去 `NpcName.fmg` 查） | — |
| `hp` | `+0x024` (u32) | 血量 | 126 / 147 / 162 / 778 / 1418 / 1939 |
| `getSoul` | `+0x02c` (u32) | 击杀获得的卢恩 | 0 / 144 / 1130 |
| `itemLotId_enemy` | `+0x030` (s32) | **掉落表 id**（-1 = 无） | 365000200 / 420000020 |
| `npcType` / `teamType` | `+0x132` / `+0x133` (u8) | 类型 / 阵营 | 0/128、6、51、7… |

**血量分布（7799 条有效值）**：中位 **316**｜75% **873**｜90% **1639**｜最大 **99999**
→ 说明"按强度分档（合理度）"完全可行：低阶杂兵（百级）、精英（千级）、Boss（万级）层次分明。

**`NpcParam` 里没有任何"主模型"字段** —— 只有 `modelDispMask0..31`（部件显示掩码）与几个特例替换字段
（`normalChangeModelId` / `ghostModelId` / `RetargetReferenceChrId`）。
→ **"换敌人外观"这件事，regulation 做不到。** **[实测 + 源码印证]**

**法魂本体不带地图文件**：`mod/map/` 845 个文件全是资源 —— `*.mapbnd.dcx`（803）、`*.hkxbhd/.hkxbdt`（42），
**没有一个 `mapstudio/*.msb`**。
→ 敌人的**摆放**来自游戏本体 `Game/map/mapstudio/*.msb.dcx`；要改就得改本体地图，
   或者把改过的地图放进 `mod/map/mapstudio/`（法魂的加载器认不认 `map/` 覆盖 —— **[待实测]**）。

**敌人名字可读**：`mod/msg/zhocn/item_dlc02.msgbnd.dcx` 里有 **78 个 FMG**，含
`NpcName.fmg` / `NpcName_dlc01.fmg` / `NpcName_dlc02.fmg`；
目前已读出 70+99 条中文名（`归树看门犬（剑）`、`“猎犬骑士”达瑞威尔`、`古龙人`…）。
> ⚠️ 现有读取函数只读出基础版 71 条，**明显偏少**（实际应有数百条）—— 读取逻辑要重写严谨版 **[待做]**。

### 1.2 敌人到底"存在哪"（这张表是方案的地基）

| 你想改的东西 | 存在哪 | 字段 | 现有工具 |
|---|---|---|---|
| 敌人**长什么样**（模型） | **地图 MSB** | Part 的 `ModelName`（如 `c2500`，需 MAP 的 MODEL 段有条目） | ✗ 要新写 |
| 敌人**用哪套数值** | 地图 MSB → 指向 regulation | Part 的 `NPCParamID` | ✗ 要新写（读出后改 regulation 部分已有能力） |
| 敌人**用哪套 AI** | 地图 MSB → 指向 regulation | `ThinkParamID` | ✗ 要新写 |
| 敌人**初始化**（性别/体型等） | 地图 MSB → 指向 regulation | `CharaInitID` | ✗ 要新写 |
| 敌人**站哪 / 朝哪** | **地图 MSB** | Part 的 `Position` / `Rotation` | 不需要动（保持原位）|
| 敌人**被脚本怎么引用** | 地图 MSB + 事件文件 | Part 的 `EntityID` / `EntityGroupIDs`（EMEVD 认这个） | **不要动** |
| 敌人**掉落什么** | regulation | `NpcParam.itemLotId_enemy` | ✓ 已有读写能力 |

**关键安全结论 [源码]**：EMEVD 事件只认 `EntityID` / `EntityGroupIDs` / 事件 flag，
**不认 `NPCParamID` / `ThinkParamID`**。
→ 只换这三个 ID（+模型名），**Boss 血条、死亡触发、开门、雾门这些脚本不会失配** ✓。
→ 会出事的是：改 `EntityID`、改 `EntityGroupIDs`、删 part、或换成依赖特定动作/SpEffect 的多阶段 Boss
（例：神皮双人组的复活靠动画发出的 SpEffect）**[源码]**。

### 1.3 参考实现：原版敌人随机 mod 的设置分类学

主流实现就是 **thefifthmatt 的「Elden Ring Item and Enemy Randomizer」**（Nexus mods/428，源码 `thefifthmatt/SoulsRandomizers`，仍在更新）**[检索]**；
社区清单里**没有第二个独立原版敌人随机器** **[检索]**。它的分类轴（读源码得到）**[源码]**：

**11 个面向玩家的类别（`EnemyClass`）**

| 类别 | 显示名 | 含义 |
|---|---|---|
| Basic | Regular Enemies | 其它都不属于的普通敌人 |
| Miniboss | World Minibosses | 露天带 Boss 血条的精英 |
| Boss | Major Bosses | 有成就/剧情重要性、跑不掉的 Boss |
| MinorBoss | Minor Bosses | 其它跑不掉的 Boss（含支线地牢 Boss） |
| NightMiniboss | Night Minibosses | 只在夜晚生成 |
| DragonMiniboss | Dragon Minibosses | 龙类精英 |
| Evergaol | Evergaol Minibosses | 监牢 Boss |
| HostileNPC | Hostile Humans | 入侵者 / 无长任务线的敌对 NPC |
| Wildlife | Passive Wildlife | 被动野生动物 |
| Scarab | Scarabs | 粪金龟 |
| Spectator | Spectators | **小 Boss 身边的小怪**（防"露天战斗忽然变成超高难度"）|

**合并池（ClassGroup）**：All Enemies / All Dragons / All Bosses，以及 Base·DLC 各自的
All / Regular / Boss / Minor / Miniboss / Dragon / Wildlife 组合 **[源码]**。

**合并规则（ClassConfig）**：每个类别可配 `Parent` / `AltParent`（并入父类）、
`NoSelfRandom`（只能并进父类，如粪金龟）、`DefaultInherit`（默认继承父类池）、
`NoMerge`（永不合并，如敌对 NPC）、`DlcSilo`（DLC 单独隔离）**[源码]**。

**频率调整（PassiveAdjustments）**：同一类别内某个敌人出现概率可单独缩放
（原文例子："把螃蟹设成 50%，它的出现几率减半"）**[源码]** —— 这正好是你要的"按类别细调"。

**为什么它们要那么多保护字段**（也就是"换敌人会翻车"的清单）**[源码]**：
`DefeatFlag` / `AppearFlag` / `StartFlag` / `EncounterFlag` / `MusicFlag`（事件与音乐绑定）、
`HealthbarIndex`（Boss 血条槽位）、`NextPhase`（多阶段 Boss 的第二形态）、
`OwnedBy`（随从跟着主人走）、`BuddyGroup`（骨灰）、`Arena` / `ArenaExclude`（Boss 必须落在封闭场地内）、
`SplitFrom` / `DupeFrom`（派生个体）……

**法魂专用先例**：Nexus 上已经有 **「Randomizer for all - Enemy Pickup for Convergence 3」（mods/11031，twicewayYYB）**，
作者写明写 `mod\regulation.bin` **与 maps**，并带"盲盒模式" **[检索]**。

### 1.4 Python 侧的工具现状（决定自研成本）

| 工具 | 语言 | ER MSB | 结论 |
|---|---|---|---|
| soulstruct | Python | 有 `eldenring/maps/msb` 代码，但**官方不支持、无测试** | 只能当**格式参考**，不当依赖 |
| soulstruct-blender | Python | ❌ | — |
| Firelink / pyrelink | C++ (+Python 绑定) | ✔️（作者把 ER MSB 放这条线） | 依赖重，不符合本项目"**零外部依赖单文件 exe**"的定位 |
| SoulsFormats (JKAnderson) | C# | ❌ 无 MSBE（已归档） | — |
| SoulsFormatsNEXT / Smithbox / DSMapStudio | C# | ✔️ | 参考实现，不能直接用 |

**结论 [检索]**：Python 侧没有成熟可用的 ER MSB 写回方案 → **要自研**。
**但自研量比想象小**：我们不需要"完整的 MSB 读写器"，只需要一个**定点改写器**：

1. DCX 解包（KRAK / ZSTD）—— **已有** ✓
2. 读 MSBE 头部的 param 偏移表（`版本 + 条目数 + name 偏移 + 条目绝对偏移数组 + 下一块偏移`）**[源码]**
3. 定位到 `PARTS_PARAM_ST` 里的 **Enemy** 子段（`PartType.Enemy = 2`，另有 `DummyEnemy = 10`）
4. 每条 enemy 记录是**定长结构**，按字段偏移改 `NPCParamID` / `ThinkParamID` / `CharaInitID`（int32 → **长度不变**）
   ；`ModelName` 是内联字符串 → **等长或更短（补 0）也能原地改**，**超过原长度就跳过该处**
5. 回包：外层压缩类型**必须沿用原文件**（KRAK level 6 / 或 ZSTD），重写 DCS 里的两个尺寸字段 —— **已有** ✓
   （ER 1.12+ 有文件改用 ZSTD 包装，旧工具会 `Unknown DCX format`；本工具已经处理 ZSTD ✓）

**风险点 [源码]**：entry 内偏移是**相对 entry 起点**的，entry 之后紧跟名字串 —— 所以"改字符串"必须**不超长**；
压缩层长度必然变化（游戏不关心，但要重写尺寸字段）。

### 1.5 地图文件的现场实测（本机，2026-10-15）

拿**别的 mod 自带的地图**（`重回巅峰MOD v1.17.1` 的 `mod/map/mapstudio/`）当样本，实测 MSB 读写链路：

| 实测项 | 结果 | 含义 |
|---|---|---|
| 样本文件 | `m10_00_00_00.msb.dcx` 0.49 MB → 解压 **12.05 MB** | MSB 很大但可解 ✓ |
| 解压后文件头 | **`MSB ` + version 1** | 与公开的 MSBE 格式一致 ✓ |
| **DCX 外层类型** | **`DFLT`（zlib）—— 不是 KRAK** | ★ 写回可用**纯 Python zlib**，不需要 Oodle 压缩器 |
| 这个外层类型游戏认不认 | **认**（该 mod 正常工作） | → 我们产出的覆盖地图用 DFLT 包就行 ✓ |
| 现有工具链 | `erio` 支持 KRAK / ZSTD，**不支持 DFLT** ✗ | 小缺口：补一行 zlib ✓ |
| MSBE 内部 param 表走法 | **还没走通** ✗（我们的头部假设与真实布局有出入） | 二期第一件事，有 SoulsFormats `MSBE.cs` 可依 ✓ |

**另一条重要发现：游戏本体的地图不是散装文件** —— 本机
`ELDEN RING Tarnished Edition v1.17/Game/` 下面只有 `Data0/1/2.bdt + .bhd` 归档，
**没有 `map/` 目录**（0 个 msb）。

→ 两个直接后果：
- **"读现有地图"** 需要能读 **BHD5/BDT 归档**（或改从 MOD 目录里的覆盖文件读）—— **[新工作项]**
- **"写回地图"不需要碰归档** ✓：只产出 `mod/map/mapstudio/<地图名>.msb.dcx` 覆盖文件即可
  （`重回巅峰MOD` 就是这么做的，样本在手 ✓✓）—— 附带好处：**"还原" = 删掉覆盖文件**，比改归档干净得多

## 2. 方案

### 方案 A：纯 regulation「敌人参数随机」（1~2 天）

不碰地图。把每个 `NpcParam` 行当作"敌人的灵魂"，在**同类敌人的池子**里做**原地互换**：

- 换什么：`hp` / 伤害 / 防御 / 抗性 / `getSoul` / **AI（`NpcThinkParam` 引用）** / **掉落（`itemLotId_enemy`）**
- 不换什么：外观（做不到）、位置、`EntityID`、事件
- 玩家感受：**还是那只怪、还是那个位置，但打起来完全不一样了**（数值/AI/掉落全换）
- 复用：现有的"池 + 合理度 + 比例 + 种子 + 备份 + 还原 + 写前复核"整套机制，**一天能出原型**
- 适合：作为**一期**，同时把下面 B 需要的"敌人清单 / 分类 / 强度档"全部建出来

### 方案 B：真·敌人随机（改地图 MSB）（1~2 周）

在 A 的池子模型之上，写 **MSB 定点改写器**，把地图上每条敌人记录指向**同类别另一个敌人**：

- **B1（最安全）**：只换 `NPCParamID` + `ThinkParamID` + `CharaInitID`（三个 int32，长度不变）
  → 敌人**外观不变**、灵魂变了（等价于 A，但按**地图上的实际出现**来做，覆盖面更准）
- **B2（真正换敌人）**：再换 `ModelName`（**仅在"新模型名 ≤ 原名字长度"且"该模型已在本图 MODEL 段里"时允许**）
  → **外观也换** ✓✓ 这是你要的效果
- **B3（远期，先不做）**：完整 MSB 重建（新增模型条目、编辑事件）—— 投入翻几倍，收益有限

**覆盖范围建议**：一次只改**一张图**（一个 `mXX_YY_ZZ_ZZ`）＝ 一个独立可验证单元；改完就地跑"图能不能加载"的验证，
失败只回滚这一张。逐图推进、可随时停。

### 方案 C：A + B 分期（推荐）

| 期 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **一期** | 敌人清单（从 `NpcParam` + `NpcName` + MSB 生成）→ **自动分类 + 人工复核表** → 类别池 → 方案 A 的随机器 + UI | 「敌人参数随机」能玩；**分类表肉眼可审** | 同类互换率 100%、零越池、同种子可复现、写入前复核、还原逐字节一致 |
| **二期** | MSB 读取器（只读）→ 输出"每张图有哪些敌人、什么类别、模型名"清单 | 一张**可核对的敌人分布表** | 读取器与 Smithbox/游戏内表现抽样比对一致 |
| **三期** | MSB 定点改写器（B1 → B2）→ 与一期共用池/合理度/比例 UI | 真·敌人随机 | 每张图改完真机启动进主菜单（沿用现有 14 配置真机验证的做法）；还原逐字节一致 |

## 3. 类别池设计（法魂版）

**骨架照抄参考 mod（已被验证好用）**，内容换成法魂自己的：

1. **顶层类别**（先做 8 个，够用且好理解）：
   `普通杂兵` / `精英（野外带血条）` / `主线 Boss` / `次要 Boss（地牢等）` / `夜间精英` / `龙类` / `监牢 Boss` / `被动动物`
   —— 另加两个法魂特色位：`法魂新敌（其它）`、`骑乘/成组敌人`（特殊处理）
2. **合并池**：`全部敌人` / `全部 Boss` / `本体` / `DLC` 各自的组合 —— 直接给"一键大乱斗"和"只换 Boss"两个常用预设
3. **类别内可调频率**：某个敌人出现率缩放（照抄 PassiveAdjustments 的做法）
4. **法魂的分类怎么来**（这是你要的"按法魂的敌人类别"）：
   - 名字：`NpcName.fmg`（法魂的增改都在它自己的 msg 里）→ 关键词能认出大半（`骑士` / `法师` / `弓` / `巨兽` / `亡灵`…）
   - 数值：`hp` + `getSoul`（卢恩奖励，最接近"官方强度刻度"）→ **自动分 4 档**（沿用现有合理度的档位思想）
   - 模型：MSB 的 `ModelName`（`cXXXX`）→ 同一模型 = 同一敌人类型，最可靠的一手线索
   - **最后落成一张人工复核表**（CSV/JSON，进仓库）—— 自动分类只做初稿，类别归属由你拍板
5. **保护清单（不可动）**：多阶段 Boss、随从/骨灰、场景剧情敌人、`EntityID` 被事件引用的特殊个体。
   一期就把它们**排除在池外**（而不是"指望随机不抽到"）。

## 4. 与现有物品随机器怎么共存

- **文件不冲突**：物品随机写 `regulation.bin`；敌人随机写 `mod/map/mapstudio/*.msb.dcx`（+ 少量 regulation）
- **叠放顺序建议**：**先敌人随机、后物品随机**。理由：敌人随机决定"这里是谁"，物品随机决定"这格/这敌人给什么"；
  反过来做的话，物品随机的改动会被之后的敌人随机覆盖掉一部分（掉落归属变了）
- **掉落归属规则（要你拍板）**：
  - 只用敌人随机 → 掉落自然跟着敌人走（像原版敌随那样）
  - 只用物品随机 → 现状不变
  - 两个都用 → 最终掉落由**物品随机**决定（因为它后跑）
- **共同原则**（延续现有工具）：只换内容、不搬位置；总量守恒；同种子可复现；写入前复核；一键还原

## 5. 安全与验证（全部复用现有做法）

| 关卡 | 用法 |
|---|---|
| 自动备份 | 写入前备份 `regulation.bin` **与被改的每一张地图** |
| 写前复核 | 逐条核对"当前值 == 我以为的原值"，不一致**立即中止**（不产出半个文件） |
| 干跑 / 预览 | 生成方案后先给"这次会改哪张图、哪些敌人、换成什么"的清单 |
| 逐图验证 | 每张图独立改、独立验、独立回滚（一图失败不牵连全局） |
| 真机验证 | 沿用现有做法：每套配置实际启动游戏进主菜单 |
| 一键还原 | 地图与 regulation 一起还原，**逐字节**比对原备份 |
| 同种子可复现 | 与现有 `seed` 机制一致 |

## 8. 风险清单（诚实版）

| 风险 | 影响 | 应对 |
|---|---|---|
| MSB 改写错位 | 该地图加载崩 / 游戏进不去 | 只改定宽字段、不超长、不改偏移表；逐图验证 + 一键还原 |
| 模型名超长 | 布局错位 | 超长就**跳过该处**（不冒进） |
| 换到"带特殊动作需求"的敌人（多阶段 Boss） | 事件/动画不匹配 | 保护清单：多阶段 Boss、随从、剧情敌人**排除** |
| 换敌人后卡地形 / 站在空中 | 体验差 | 一期只做**同图内、同类、同站位**；后续再考虑"场地适配" |
| 法魂本体地图被改后，法魂更新/校验冲突 | 需还原 | 保留原始备份 + 一键还原；写入前显示"改了哪几张图" |
| Python 侧无成熟库 → 自研解析器 | 工期与正确性风险 | 只做"定点改写"（不做完整重建）；用 Smithbox 抽样对照验证 |
| 游戏地图打包在 `Data*.bdt`（本机实测） | "读现有地图"多一个归档解析工作项 | 只读解析归档；**写出不碰归档**（走 `mod/map/mapstudio/` 覆盖） |
| 覆盖文件法魂的加载器认不认 | 若只认本体归档，路线要重估 | **必须优先实测**：放一个改过的地图进 `mod/map/mapstudio/` 看法魂加载不加载 |
| 参考实现是 C# 且不能直接用 | 无法抄代码，只能抄**设计** | 抄类别学与保护清单（已在一手源码里读清） |
