## 0. 先说结论：池子照抄原版敌随，本文件的 12 敌型只是"画像"

**池子怎么组：直接学法环原版的敌人随机（thefifthmatt）**[源码] —— 不要再另创一套：

- **池 = 类别（Class）**：普通敌人 / 野外精英 / 主线 Boss / 次要 Boss / 夜间精英 / 龙类 / 监牢 / 敌对 NPC /
  被动动物 / 粪金龟 / 旁观者；每个类别可配**父类**（默认各池独立，想合并要显式声明）
- **每个类别里配"加权来源池"**：例如「90% 同类别 + 10% 全部 Boss」= 10% 的敌人换成 Boss；
  「50% 同类别 + 50% 不随机」= 只随机一半 —— **比例就是这么表达的，不需要单独的"比例滑块"**
- **法魂新增不改变这套模型**：它只是给每个敌人多贴一个**来源标签**，用来决定"谁有资格当来源"（见 §0.1）

> 所以：本文 §1 的 **12 个敌型**不当作池的轴，它是**人工复核表用的画像**
> （分类时知道"这是个法师""这是个巨兽"），以及以后做"只换同类外观"这类高级选项时的备用标签。
> §2 的强度档、§3 的体型档同理：**强度档不建池**（原版敌随也没有强度池），
> **体型档只当护栏**（大的不许进小的，这条原版敌随是有的，叫 `arena/size`）。

### 0.1 新增：来源标签（原版 / 法魂新增）与对应 UI 选项（作者 2026-10-15 定）

给每个敌人贴一个标签：

| 标签 | 含义 | 例子 |
|---|---|---|
| **原版** | 原版艾尔登法环就有的敌人/Boss（法魂可能改了数值）| 梅瑟莫士兵、失乡骑士、火焰巨人 |
| **法魂新增** | 法魂自己加的敌人/Boss（含"老模型新身份"的换皮 Boss）| 密契女猎手、血怪密契者、伪龙主 Daergraft、神皮母神、熔炉叛逆者 Skarde |

**UI 给一个选项**（默认第一个）：

| 选项 | 含义 | 实现方式（就是本文档说的加权来源池）|
|---|---|---|
| **敌人全随机**（默认）| 原版怪与法魂新怪**都能当来源** | 该类别来源池 = 100% 全部（原版 + 法魂）|
| **只随机法魂敌人** | 只把位置换成**法魂新增**的敌人（原版怪不会出现）| 该类别来源池 = 100% 法魂新增 |

> 想再加一个"只随机原版敌人"也是一行配置的事（来源池 = 100% 原版），先按作者要的两个做。

### 0.2 作者 2026-10-15 补充：**池子的类型可以自创**，法魂与原版的种类**合并进同一个池**

这一条把前面的框架补全了 —— 原版敌随本身就支持"**自定义分类**"（一手源码里就有
`BaseCategories` / `Categories` / `Partition` / `Partials` / `Instance` / `Contains` 这些字段
**[源码]**），所以：

- **基础类别池**（照抄原版）：普通敌人 / 野外精英 / 主线 Boss / 次要 Boss / 夜间精英 / 龙类 / 监牢 /
  敌对 NPC / 被动动物 / 粪金龟 / 旁观者
- **自创池**（法魂特有的，用"标签组合"定义）：**楔石 Boss** / **追忆 Boss** / **守门 Boss** /
  **法魂新增 Boss** / **法魂新增敌人** / **骑乘·成组** —— 想加就加，不动代码
- **合并池**（原版有）：全部 Boss / 全部敌人 / 本体 / DLC

**默认模板：法魂的 Boss 种类与原版的 Boss 种类合在一起** ✓
→ 例如「**追忆 Boss 池**」里既有原版追忆 Boss（葛瑞克、玛莲妮亚…）也有法魂新增的 7 个（Skarde、神皮母神…）✓；
「主线 Boss 池」同理 ✓。
只有勾了「只随机法魂敌人」时，来源才被收窄到法魂新增那一侧。

> 同一个 Boss 可以**同时属于多个池**（既是"追忆 Boss"又是"主线 Boss"）——
> 池是**标签的组合**，不是互斥的抽屉。这一点和原版敌随一致 **[源码]**。

## 2. 强度档（`hp` 四档，实测分布）**[实测]**

| 档 | hp 区间 | 行数 | 含义 |
|---|---|---|---|
| 1 | ≤ 300 | **3818** | 杂兵（大多数） |
| 2 | 301–1000 | **2163** | 老兵 / 精英杂兵 |
| 3 | 1001–3000 | **1647** | 高级精英 |
| 4 | > 3000 | **171** | Boss 级血量（与 `isSoulGetByBoss=1` 的 170 行几乎重合）|

`getSoul`（卢恩奖励）四档：≤100 → 653 行；101–500 → 926；501–2000 → 1093；>2000 → 667 **[实测]**
→ 两个字段都适合做"合理度"的档位来源：**同档互换 = 100% 合理度，跨档 = 降低合理度**（与现有物品随机器的"合理度"概念无缝对齐 ✓）。

## 3. 体型档（`chrHitRadius` / `chrHitHeight` 自动分档）**[实测]**

| 档 | 半径 | 高度 | 占比（半径）| 用途 |
|---|---|---|---|---|
| 小 | ≤ 0.5 | ≤ 2.0 | ~50%（中位 0.5）| 人形杂兵、虫兽 |
| 中 | 0.51–0.7 | 2.0–2.4 | ~25% | 重甲人形、中型兽 |
| 大 | 0.71–1.5 | 2.4–3.5 | ~15% | 巨兽、龙 |
| 巨 | > 1.5 | > 3.5 | ~5%（最大 18.0 / 59.0）| 火焰巨人这类场地杀手 |

**为什么这条重要**：参考实现是靠**手写** `arena:N` / `size:N` 标签来解决"塞不塞得进"的 **[源码]**；
而这两个字段**游戏数据里本来就有** **[实测]** → 我们可以**自动分档**，
规则直接照抄它的语义：**来源体型 > 目标场地容量 ⇒ 拒绝，换一个来源**（不挪位置）**[源码]**。

## 5. 法魂新增怎么识别（三条线索叠加 + 人工复核）

1. **官方名单**：更新日志里的新增/替换 Boss 清单 **[官方]**（例：Konrad、Bloodflame Dragon Sanguivaros、
   Scion of the Sealed God、Godskin Matriarch、Erdtree Sentry、Dakk、Sigur、Seera、Oleg、Skarde、Gethin、Duncan…）
2. **名字风格**（本机数据里的法魂特征词）**[实测]**：密契 / 血怪 / 水银 / 癫火 / 幽影 / 风暴 / 劳弗 /
   「拾荒之王」「降灵者」「冰之守护者」这类新称号
3. **同模型换皮**：法魂大量新增是"老模型 + 新参数（换颜色/属性/阵营）" **[社区]**
   → 这类**归入对应敌型**，但打上「法魂新增」标签，UI 里可单独开关（"只随机法魂新怪 / 不碰原版怪"）

> **不追求"自动 100% 区分"** —— 参考实现也是 10 万行人工标注 **[源码]**。
> 我们的目标：自动初稿 + **一张几百行的人工复核表**。

## 6. 实现口径（字段与待做项）

**已实测可用的字段**（`NpcParam`，行 358 B）**[实测]**：

| 字段 | 偏移 | 用途 |
|---|---|---|
| `hp` | +0x024 (u32) | 强度档 |
| `getSoul` | +0x02c (u32) | 强度档 |
| `chrHitRadius` / `chrHitHeight` | +0x158 / +0x154 (f32) | **体型档** |
| `isSoulGetByBoss` | +0x0b0 (u8) | Boss 判定（170 行）|
| `itemLotId_enemy` | +0x030 (s32) | 掉落 |
| `npcType` / `teamType` | +0x132 / +0x133 (u8) | 阵营 / 类型（辅助）|
| `nameId` | +0x00c (s32) | 名字（**见下**）|

**一个还没解决的小问题（如实记录）**：`nameId` 的值在 10 万~20 万区间，
而我的 FMG 解析器给出的 NpcName id 只到 628 ✗ —— 说明 **ER 的 FMG v2 里 id 是显式存的**，
我现在的解析把"数组下标"当成了 id。已确认的结构线索：
FMG 头 `0x00=0x20000`、`0x04=文件大小`、`0x0C=265`、`0x10=626`（疑似条目数），
`0x38` 处出现 `110000 / 110200` 这类 id 值 **[实测]**。
→ **实现期第一件小事**：把 NpcName 的 (id → 文本) 对上（可用 `GoodsName` 里已知 id 反推验证），
之后"名字 → 行"就能全量 join，自动分类表才能直接生成。
