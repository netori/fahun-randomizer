# 有血条 Boss 名单 · 补全与缺口说明

> 只读游戏/mod 文件；产出 `investigation/boss_healthbar.csv`（v2）。
> 复现：
> ```
> cd investigation/apply
> python boss_healthbar.py            # 抽名单 → ../boss_healthbar.csv
> python boss_healthbar.py --explain-fmg   # FMG 区间语义自检
> python boss_names_gaps.py           # 追忆↔Boss 对照表
> python boss_names_gaps.py --diff --gaps  # 再加 v1/v2 差异 + 缺口清单
> ```

---

## 0. 一句话结论

上一版（v1）的名单**两处机制性错误**：

1. **FMG 区间记录解析错了** —— 把 `[lo,hi]` 区间内所有 id 都当成"跟第一条同名"。
   实际语义是 **id `lo+k` → 字符串槽 `slot+k`**（每条 id 有自己的名字）。
   后果：**“恶兆王”蒙葛特、“黑剑”玛利喀斯**、战士荷莱·露、“背叛熔炉者”斯卡德、
   “塑灵者”凯玛、“米凯拉的王”拉塔恩……这些 Boss 不是"没抓到"，而是**名字被区间里第一个名字盖住了**
   —— v1 名单里 42 个 `name_id` 的名字是错的。
2. **公共模板事件整条丢掉** —— 野外（大地图 m60_*/m61_*）Boss 的血条不写在本图脚本里，而是
   `InitializeCommonEvent(0, 90005870, <实体>, <名字id>, <BGM区域>)` 去调 `common_func.emevd` 里的模板，
   模板体内是 `DisplayBossHealthBar(Enabled, X0_4, 0, X4_4)`（实体与名字都是**形参**）。
   v1 用"占位符过滤"把这些整条丢了 → **少 153 行**（现在从 `common`/`alias` 两个来源补回）。

v2 结果：**332 行 / 197 个唯一 Boss 名 / 245 个唯一实体 / 174 张地图**（v1：175 行 / 110 名 / 117 地图）。

## 1. 缺口 1：FMG 区间记录（这是"蒙葛特/玛利喀斯不见了"的真正原因）

### 证据（原始记录 → 逐 id 字符串）

`mod/msg/zhocn/item_dlc02.msgbnd.dcx` 里 `NpcName.fmg` 的原始记录是**区间**形式，
一条记录覆盖多个 id，而**每个 id 在偏移表里指向自己那条字符串**：

```
NpcName    slot=369 lo=902130000 hi=902130003 首个文本='“恶兆妖鬼”玛尔基特'
    902130000 → '“恶兆妖鬼”玛尔基特'
    902130002 → '“恶兆王”蒙葛特'      ← v1 在这里拿到的是"玛尔基特"（错）
    902130003 → '“恶兆王”蒙葛特'
NpcName    slot=365 lo=902110000 hi=902110001 首个文本='野兽祭司'
    902110000 → '野兽祭司'
    902110001 → '“黑剑”玛利喀斯'      ← v1 在这里拿到的是"野兽祭司"（错）
```

自检（`--explain-fmg` 会打印）：**Σ(hi-lo+1) ≈ 字符串槽数 n_str**，说明区间里每个 id 各占一条字符串：

| FMG | n_str | Σ(hi-lo+1) |
|---|---|---|
| GoodsName | 4791 | 4689 |
| GoodsName_dlc01 | 1549 | 1549 |
| NpcName | 626 | 617 |
| NpcName_dlc01 | 105 | 105 |

### ⚠️ 同一个坑还在别处：`enemy_names.parse_fmg`

`enemy_names.parse_fmg(expand_ranges=True)` 就是错的那一版（整段共用第一条文本），
而 `investigation/enemy_table.csv`、`enemy_names.export_enemy_table()`、以及并行项目的
`_boss_taxonomy*.py`（它自己另写了一个"按字符串槽号当 id"的解析器，id 口径与 NpcParam 的
`nameId` 不是一回事，只是做文本搜索时才碰巧没事）都受它影响。

**本次任务范围不允许我改 `enemy_names.py`**，所以 `boss_healthbar.py` 里自带修正版
`parse_fmg_by_slot()`。**建议**：把 `enemy_names.parse_fmg` 的区间分支改成
`for k in range(hi-lo+1): out[lo+k] = text_at(slot+k)`，然后重跑 `enemy_table.csv`
（`nameId` 非 0 的 750 行里，凡是落在区间内部的都会改名）。

## 4. 你猜的三条原因，逐条验证

| 猜测 | 结论 | 证据 |
|---|---|---|
| ① 公共脚本/模板开血条，实体是 `X0_4` 占位符，真值由调用方传入 | ✅ **成立，而且是大头** | 见第 2 节：`common_func:7619/7630` 的模板 + 各 tile 的 `InitializeCommonEvent`。新增 153 行里 149 行走 `common`、4 行走同文件 `alias` |
| ② 另一条指令（如 `HandleBossDefeatAndDisplayBanner`） | ❌ **不成立** | 全库指令计数：`DisplayBossHealthBar` ×234（**唯一带名字 id 的**）、`HandleBossDefeatAndDisplayBanner` ×173（参数只有 `(实体, TextBannerType)`，没有任何名字）、`SetBossBGM` ×96、`DisplayBanner` ×19、`IssueBossRoomEntryNotification()` ×16（**无参数**）。没有第二个能写血条名字的指令 |
| ③ 别的名字号段 | ✅ **成立，有三段并存** | (a) 9 亿号段 `902030000–907100301` = Boss 显示名主号段（本体在 `NpcName`，DLC 在 `NpcName_dlc01` 的 `905xxxxxx–906xxxxxx`）；(b) 小号段 `130000–143200` 也真的被血条调用使用，例：`m31_00_00_00.emevd.dcx.js:610 → 130900`（帕奇）、`m31_19_00_00.emevd.dcx.js:248 → 137600`（死术师哥瑞斯）、`m43_01_00_00.emevd.dcx.js:79 → 140700`（古龙人）、`m41_02_00_00.emevd.dcx.js:379 → 142700`（喟叹者）；(c) **`NpcParam.nameId` 不是名字来源**：7823 行里 750 行 `nameId≠0`，但**没有一个落在 9 亿号段**（`enemy_table.csv` 实测），所以 Boss 名只能从事件脚本拿 |

（名字在第 3 个形参位）—— 如果只按 `90005870` 的位次代入，会把这些行的实体当成名字 id。

## 5. ⚠️ 这份名单看不到什么（明确局限，不猜）

1. **`m60_47_37_10.emevd.dcx` 没有 `.js` 反编译版**（同目录 268 个 `.emevd.dcx`，只有 267 个 `.js`）。
   这**一个脚本**里的血条我看不到。
2. **名单只覆盖 mod 自己带的事件脚本**（`mod/event/` 里 267 个）。
   目录里 `m60_*_*_10` 这类分层 tile 只带了少数几个（例如有 `m60_44_36_10.emevd.dcx.js`，
   但**根本没有** `m60_38_49_10.emevd.dcx.js`）。凡是血条写在"游戏本体 bdt 里那份脚本"的 Boss，
   本名单看不到 —— **"未找到"≠"游戏里没有血条"**。
3. **51 个名字（74 个 id）在 267 个脚本里没有任何血条调用引用**，典型是
   `黑夜骑兵`(903150600-609)、`死亡仪式鸟`(904980606/906260600)、`尖刺山的飞龙`(905580600)、

   完整清单：`boss_names_gaps.py --gaps`。

   名单没覆盖的只剩 22 个 —— 全是音效/flag 号（`900005610`、`999997800` 之类），**没有一个能解析出名字**。

## 8. 这套名单能不能当随机器的 Boss 池依据？

**能当骨架，但要按下面几条用**（都用板上字段判断，不靠印象）：

1. **先用 `note` 剔注释行**：35 行是 `.js` 里 `//` 关掉的调用（比如
   `m12_01_00_00.emevd.dcx.js:154 //InitializeCommonEvent(0, 90005870, 12010805, 904810603, 18);`），
   剔掉后 **297 行**。
2. **再剔无名行**：2 行 `name_id=0`（`common_func / 11000800` 是模板自带的占位实体，不是 Boss），
   剔掉后 **295 行 / 197 个名字**。
3. **同名归并**：同一个 Boss 会以多个 `name_id`/实体出现（多形态、多个变体、多张图）。
   197 个唯一名字里，**32 个是追忆 Boss**，其余 165 个是野外/洞窟/守门 Boss —— 两者要分层：
   追忆 Boss 的位置与野外 Boss 的位置语义完全不同，混在一个池里会串味。
4. **"血条 Boss" ≠ "追忆 Boss"，但追忆 Boss 全在里面**：32 个追忆里 31 个能直接定位到名单行，
   1 个（梅蒂尔）名单里没有 → 如果你要做"追忆 Boss 互换"，这一个位置必须单独处理或先不放进池子。
5. **名单是"Boss 位置"表，不是"怪种类"表**：同一名字在多张图出现（例如 黑刀刺客、归树看门犬、
   黄金树化身都有多个点位），随机器要按 `(map, entity)` 定位，按 `name` 归并统计。
6. **不覆盖的地方要认**：`m60_47_37_10` 没有 `.js`；51 个名字（黑夜骑兵、死亡仪式鸟、尖刺山的飞龙…）
   在脚本里没被引用。想把这些也纳入池子，得换依据（MSB 里的 BossArea / NpcParam 的
   `isSoulGetByBoss` / 另一份脚本），**不能靠这份 CSV 说"它们没有血条"**。
