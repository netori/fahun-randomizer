# 池子选项说明（法魂随机化 · 干跑）

> 这份文档说明：**能调什么、不能调什么、GUI 怎么用、命令行怎么用、结果怎么验证**。
> 全部只写 `investigation/`，不写回 MOD、不写注入代码。

---

## 一、固定规则（不可更改）

| 编号 | 规则 | 说明 |
|---|---|---|
| F1 | **法师 / 祷告护甲独立成池** | 只与**同职业倾向、同部位**的护甲互换；**永不**进入联合池；**永不**与武器/卢恩互换。倾向 = 法师 / 祷告 / 法师·祷告混合 / 祷告·感应 |
| F2 | 套装整组不拆散 | 完整四件套只与完整四件套互换，且严格 头→头、身→身、臂→臂、腿→腿 |
| F3 | 同一物品多处来源整组一致 | 一件东西在几个地方能拿到，替换它的东西也同时出现在那几个地方 |
| F4 | 非联合池内：护甲同部位、不跨倾向 | 头↔头、身↔身…；近战护甲只与近战护甲互换（除非显式并入联合池） |
| F5 | 按池多重集合守恒 | 每种物品的总数不变，只是换位置；不新增、不删除 |

`F1` 就是你说的"法师祷告的护甲要自己一个池子随机（固定，不能改）"。

## 二、可调的选项

| 选项 | 取值 | 说明 |
|---|---|---|
| **参与域 `domains`** | 卢恩 / 护甲 / 武器 的任意子集 | 只随机你选中的域 |
| **池子组织 `joins`** | 各自独立（默认）／两两联合／三者全联合／"卢恩＋武器联合、护甲独立" | **联合 = 组内共用一池，允许跨类别互换**；写回时需同时改写该槽的类别字段（`lotItemCategory` / 商店行的 `equipType`） |
| **商店 `shops`** | 开 / 关 | 关掉则只动光点/宝箱/敌人掉落等 Lot 槽 |
| **套装 `sets`** | 开 / 关 | 关掉则护甲全按单件同部位处理（整套逻辑失效，仅用于对照） |
| **幽影合并 `merge_shadow`** | 开 / 关 | 开：幽影卢恩并入 `rune:大师级`（池 18 → 37 槽） |
| **种子 `seed`** | 任意整数 | 同一种子结果可复现（python 与 GUI 各用各的随机源，逐行不会一致） |

**联合池的语义**（例：`卢恩＋武器 联合`）：这两个域的单件单元共用一个池 → 某个武器的位置可能换成一条卢恩（反之亦然）。

**⚠️ 把护甲并入联合池的代价**：该池内的护甲格可能拿到武器/卢恩，需要同时改写槽的类别字段；**法师/祷告护甲不受影响**（F1 永远生效）。

## 三、GUI 怎么用

打开 `GUI.html`（双击即可，无需服务器）：
1. **① 选项**：勾选参与域 → 选池子组织 → 其它开关与种子；
2. 点 **随机一次**（改种子用「换个种子再随机」）；
3. **② 结果统计**：池数、置换行数、各域行数、商店行、联合池放宽格数、需改类别字段数；
4. **③ 约束校验**：F1~F5 每次随机都重算并显示 ✅/❌；
5. **④ 池子清单**：池名 / 类型 / 单元数（按大小排序）；
6. **⑤ 置换表**：可筛选（池名/物品/位置/行名），只显示前 300 行，**导出完整 CSV** 按钮给全量；
7. **自检**按钮：7 域组合 × 4 种联合 × 商店/套装开关 × 4 种子 = **208 次运行**，页面上直接给出通过/失败（当前：**0 失败**）。

## 四、命令行怎么用

```bash
# 默认：三域各自独立成池（112 池 / 764 行）
python scripts/randomizer.py --out dryrun_config_swaps.csv

# 卢恩 + 武器 联合（护甲独立）
python scripts/randomizer.py --join rune,weapon --out swaps_join_rune_weapon.csv

# 三者全部联合（近战护甲会跨类别；法师护甲仍独立）
python scripts/randomizer.py --join rune,armor,weapon --out swaps_join_all.csv

# 其它开关
python scripts/randomizer.py --no-shops --no-sets --merge-shadow --seed 777 --out swaps_custom.csv

# 配置矩阵测试（180 次运行 / 60 种组合，逐一断言 F1~F5）
python scripts/test_configs.py
```

**名称解析与「职业专属」判定**（口径：**不是职业专属就不入池**）：

| 处理 | 条目 | 依据 |
|---|---|---|
| **补进池（职业专属）** | 燃炉拳套 `21090000`（火焰预言家）、石像鬼大剑 `3190000`（风暴呼召者）、众使者的笛子 `11100000` / 秘文剑 `2110000`（基本主义者）、死王子杖 `33180000`（死灵术士） | 只被 **1 个职业直接推荐** + 名称可精确对应 |

| **专属但名称无法唯一对应 → 暂不入池** | 龙戟（候选 龙人戟 有两处 id）、王室大剑（候选 王室巨剑 0.75）、龙装墓碑（候选 龙之墓碑 0.75） | 为避免错配（例如把「戟的龙人派生」当成独立武器） |

顺带修掉一个真 bug：以「套」结尾的**普通物品**（如 `燃炉拳套`）曾被误判为"套装名"而丢弃；现在只有"套装表里查得到"或"FMG 前缀命中 ≥2 件"的名字才按套装展开（`XX套装` 允许 1 件命中）。

**当前候选规模**：**785 条有入口**（去重 718 件：护甲 359 / 武器 271 / 卢恩 88），护甲含 61 套完整四件套；判定记录见 `evidence/exclusivity_judgement.json` 与 `evidence/name_resolution_curated.json` 的 `exclusivity_decision`。

### 套装名怎么展开（关键规则）

正文里的「拉塔恩套装」「黑夜套装」是**套装名**，MOD 里没有同名物品，只有件名。规则：

1. 用「基名 + 部位词」的信号定位 **id 家族** —— 例：`黑夜套装` → 找到件名恰好是 **黑夜头盔/黑夜铠甲/黑夜臂甲/黑夜腿甲** 的家族 `5090`；
2. 取**该家族全部件**（不看件名是否规整）—— 这样 `黑夜女巫套装` 的 **双生冠 / 手环** 也不会漏；
3. 件名不规整时退化为「前缀命中 ≤12 件」。

**更正**：上一轮我把 `黑夜套装 - 波尼监牢` 猜成 `咒剑士面具 5210000`（只因两者箱子号相邻），是**错的**。MOD 里确实有独立的一套：`5090000 黑夜头盔 / 5090100 黑夜铠甲 / 5090200 黑夜臂甲 / 5090300 黑夜腿甲`（`Helm/Armor/Gauntlets/Greaves of Night`，`ItemLotParam_map:41010300~0303`）。现在它按家族正确展开。

### 两处早先的 bug（都已修）

1. **部位尾号**：护甲 id 有 **6/7/8 三种长度**（`872000`、`5253000`、`5230100`），部位码是**末 3 位**；此前只按末 4 位判断 → **7 位 id 的护甲（神鸟/神兽/熔炉/塑灵者/玛雷家/黑夜女巫 等 DLC 套装）被引擎整批跳过**。现统一为 `part_code_of()`。
2. **正文格式**：说明书是「名称 - 地点」，早先脚本按「名称(编号)」解析，只捞到 7 件防具。
