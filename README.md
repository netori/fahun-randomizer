# 法魂职业道具和装备随机器

> **Convergence Class Item Randomizer** ｜ 给「法魂」（The Convergence）MOD 用的物品随机化小工具
> 发布包：`ConvergenceClassItemRandomizer.exe` ｜ 当前发布版本 **v1.2.0**（引擎 1.1）

> ⚠️ **目前仅支持中文版（法魂汉化本体）** —— 界面、说明书改地点、文件自检都按中文版做的；
> **英文版（及其它语言）暂不支持**：英文玩家玩的是原版 The Convergence，物品池与文件结构都不同，
> 不是翻译几个字就能用。以后可以做（管线支持从别的语言重建目录），但现在没有。

一句话：**把职业说明书里那些道具，在"合理"的范围内互相对调一下，让每一周目都得重新找东西、重新搭流派。**

---

## 一、为什么做这个

法魂这类大改 MOD，职业流派基本是钉死的：玩辉石法师就那几件装备、就那几个卢恩，开局路线几乎固定。
市面上的随机器要么只管原版、要么"一键全乱"——**东西是乱了，但流派也废了**。

我们想要的不是"全乱"，而是：

- 我玩辉石法师，还是辉石法师，只是**这一周目的关键道具换到别的地方去了**；
- 强度上别太离谱——**后期道具别跑到新手村、新手道具别堵在终盘**；
- 我随时能**一键还原**，不用担心把游戏搞坏。

## 二、设计理念

### 1) 只换物品，不搬位置

格子在哪儿就是哪儿：宝箱还是那个宝箱、掉落还是那个掉落。
我们只改"这个格子里放什么"，**绝不动**格子的数量、概率、价格、库存、解锁条件、事件流程。

这条看着保守，其实是**整个工具的立身之本**：
只要不搬位置，就不可能出现"某个任务道具没了导致卡关"，也不需要动事件脚本。
**商店默认不参与**（可在「更多设置」里开启；开启后也只换职业专属装备，价格、限量、解锁条件一律不动）。

### 2) 以「职业说明书」为准

随机范围严格等于**游戏内职业说明书里出现过的物品**。

说明书是这个 MOD 给玩家的"流派指南"：它写了每个职业该拿什么、去哪儿拿。
我们只在这份名单里换——换完之后，玩家翻开说明书，看到的就是**这座世界的真实分布**。

### 3) 合理度是一个旋钮，但它的含义必须精确

滑块 0~100%，但它同时控制**三件互相独立的事**（完整定义见 [随机化算法规格.md](docs/随机化算法规格.md)）：

| 合理度 | 越档幅度（最远能跨几档） | 越档率（多少东西真的跨） | 武器掺进混池的比例 |
|---|---|---|---|
| 100% | 1 档（只能同档） | 0% | 0% |
| 67% | 2 档 | 33% | 22% |
| 33% | 3 档 | 67% | 44% |
| 0% | 4 档（完全放开） | 100% | 66% |

而"档位"不是拍脑袋定的，是按**游戏自己的等级感**：

| 档 | 卢恩 | 护甲 | 武器 |
|---|---|---|---|
| 0 | 学徒 | 臂甲 | 宁姆格福 / 啜泣半岛 / 史东薇尔… |
| 1 | 熟练 | 腿甲 | 利耶尼亚 / 魔法学院 / 盖利德… |
| 2 | 精通 | 铠甲 | 亚坛高原 / 王城罗德尔 / 巨人山顶… |
| 3 | 大师 / 幽影 | 头盔 | 圣树 / 法姆·亚兹拉 / 深根底层 / 幽影之地… |

**护甲与卢恩天然都是四级**，所以在混池里它们能**逐档直接对应**（臂甲 ↔ 学徒、头盔 ↔ 大师），不需要任何换算。

一句话记住规则：**任何一次互换，都必须发生在同一个「档位桶」里。**

### 4) 写不进去的东西，等于没写

这个工具**不是**"生成一个方案文件"就完事——它要真的把你游戏里的 `regulation.bin` 和说明书文本改掉，
而且**改完要能进去玩**。所以我们把"能不能玩"当成第一判据：

- 每次写入前**自动备份**，界面上一个按钮就能**还原成原始**；
- 每次写入后**自动审计说明书**（8 项检查）；
- 发布前**每一种配置都真启动过一次游戏**（见第五节）。

### 5) 保守失败

池子太小、凑不出合法互换时，我们宁可**这个池子不动**并在报告里说明，
也不用"半随机"糊过去——糊过去的结果是玩家那边丢东西，而我们这边看不出来。

## 三、怎么用

界面是**一屏三页**：顶上 **⚙ 职业物品随机**（随机设置）、**敌人随机**（v1 卡片）和 **📚 方案库**（每次随机都存到这里，双击就玩）。
**动作跟着页走**：物品页的生成 / 写入 / 还原在窗口底部（只在这一页出现）；敌人页的生成与挂载在页里的
「随机规则」与「当前方案」两张卡上；方案库是**左边列表 + 右边详情**，详情里的名字 / 备注 / 标签
**点一下直接改**，不弹框。

1. 把 `ConvergenceClassItemRandomizer.exe` 放到**法魂包根目录**（该目录下应有 `mod\regulation.bin` 与 `yafsml\`），双击打开。
   放旁边也行 —— 它会从自己所在目录往上找（认 `mod\regulation.bin`，不认名字）；实在找不到就在下面「环境」那一行点
   「指定 MOD 目录…」。搬过盘 / 换过机器后想确认它到底在用什么，跑 `ConvergenceClassItemRandomizer.exe --paths`。
   界面里的「**环境**」那一行会自检：MOD 目录、游戏数据、说明书、原始备份、说明书基准、随机引擎。
   平时只显示「N / N 项通过」，点右边的「**逐项详情 ▸**」才展开逐项清单；缺哪项会标红并
   **禁用底部的「开始随机…」**，可按旁边「指定 MOD 目录…」或「补一份原始备份」。
2. 选**随机项目**（卢恩 / 护甲 / 装备，至少一项）→ 选**混合方式**
   （勾三项时共 5 种：全部混合、两两混·一个独自 ×3、各自随机）→ 拉**合理度** → 填**种子**。

   **合理度那一段会跟着混合方式自己变**（2026-10-14 定稿的表单规则）：
   - 有混池 → 上面那条**总合理度管混池**；下面只摆"自己还成池"的类别，**没动过的跟着总合理度走**。
   - **全部混合** → 只剩总合理度（三个类别都进了混池）。
   - **各自随机** → 总合理度**置灰**，卢恩 / 护甲 / 装备三条各管自己那一类。
   - 每行末尾实时写着这条设定会造成什么（`相邻两档可互换　跨度 2/4　越档率 ≤20%`）。

   「更多设置」里（默认折叠）：
   - **法祷护甲整套一起换**：整套四件一起走，不拆散（关掉则按部位单件换）。
   - **改动比例 · 法祷职业护甲**：整套与散件一起按比例抽子集互换（例如 40% ≈ 四成参与）。
   - **商店里的职业装备也一起换**：勾上＝**在卖的职业装备全部参与**（不做二次抽比例）。
     ⚠️ 它只管**说明书里那批职业装备**：商店里在卖的职业装备实测 **69 行**（法祷护甲 50 / 近战护甲 16 / 武器 2），
     这些全都会变；商店里其余货品（普通装备、消耗品、非在售、职业初始装备表）按设计不动。
   - **说明书跟着一起改**：写入时同步改说明书里的取得地点（默认开）。
3. 点底部的 **「开始随机物品」**（想同时随机敌人，就把「敌人随机」页签的勾也留着，按钮会变成 **「开始随机物品和敌人」**）——
   只生成方案并**自动存进方案库**，**不写任何游戏文件**。不满意就来点 **还原成原始**（本体本来就没动）。
   方案层从来不是提前写好的：**第一次开玩时才按需生成**，产物只落进 `<法魂包>\方案\<层名>\mod\`，
   **法魂本体一个字节不改**。细节见 `docs/纯方案层模式_20261023.md`。
4. 到 **方案库**（📚 页签）**双击刚生成的那一行**（或选中它点 **「用这个方案玩」**）。
   第一次开玩会先生成覆盖层，然后 **换档 → 挂载 → 起游戏** 一条龙；之后再玩直接开局。
   退出游戏后进度自动存回这个方案自己的槽（`<法魂包>\存档库\<方案名>\`）。
   **每个方案一份独立存档，互不串味**；第一次用它玩会问一次「用新角色开局吗」，旧档先留底在 `存档库\_回收\`。
   游戏还开着也能直接点：会先问一句「自动关掉它并启动吗」，同意就替你关掉再开（先请它自己退，实在不退才强杀）。
   方案目录里的 **「用这个方案启动.bat」也算这条路**（换档 → 挂载 → 起游戏 → 退出回存），日志写在层目录的 `启动日志.txt`。
   ⚠️ 玩多套方案前把 Elden Ring 的 **Steam 云存档关掉**，否则 Steam 可能把档换回去。
   细节见 `docs/方案库启动与独立存档_20261023.md`。

命令行（可选）：

```bat
ConvergenceClassItemRandomizer.exe --paths                             :: 打印它在用的所有路径（搬过目录/换机器先看这个）
ConvergenceClassItemRandomizer.exe --play <方案层目录>                 :: 换档 + 挂载 + 起游戏 + 退出回存（层里的启动器调它）
ConvergenceClassItemRandomizer.exe --plan-off                          :: 切回法魂本体（删掉 Plan=）
ConvergenceClassItemRandomizer.exe --deploy <plan.csv> [--no-guide]   :: 只写入，不开界面
ConvergenceClassItemRandomizer.exe --selftest                          :: 自检（引擎 / 同种子可复现）
ConvergenceClassItemRandomizer.exe --uicheck                           :: 只构建界面 + 查主题白块（自动化测试用）
ConvergenceClassItemRandomizer.exe --uitest                            :: 方案库交互自检（临时目录，不碰真 plans）
ConvergenceClassItemRandomizer.exe --planlib                           :: 方案库模块自检（保存/列出/改名/导出/删除）
```

**同一种子 = 完全一样的结果**；换种子就是另一套世界。种子记下来就能复盘，也能分享给别人复现。

## 四、实现方式（说人话）

### 游戏文件长什么样

`mod\regulation.bin` 里装着游戏几乎所有数值表（物品、掉落、敌人、商店…），外面套了好几层壳：

```
regulation.bin
  = 16 字节 IV(全 0) + AES-256-CBC      ← 加密
      → DCX（一种带压缩的容器）          ← 压缩
          → BND4（一个包里打了上百个文件）
              → PARAM（真正的数值表：每行是一个格子，每列是一个物品槽）
```

说明书文本在另一个文件 `mod\msg\zhocn\item_dlc02.msgbnd.dcx` 里，同样是 DCX + BND4，里面装着 78 个 FMG 文本表。

**这套读写全是我们自己实现的**（AES / DCX / BND4 / PARAM / FMG，以及调用游戏自带的 Oodle 压缩 DLL），
不依赖任何外部工具——因为工具链里多一个环节，就多一个"玩家那边跑不起来"的理由。

### 一个踩了两天的坑：压缩参数决定游戏能不能开

改完 `regulation.bin` 要**重新压缩**再加密。第一版用了压缩库的默认参数，结果：

> **文件内容逐字节正确、结构完全一致、各项校验全过——游戏一启动就崩。**

最后查到：默认参数产出的是"单段 + 带内容长度 + 超大窗口"的压缩帧，
而游戏自带的解码器**只吃它自己那种帧**（小窗口、不带内容长度）。参数对齐之后一切正常。

> 所以现在矩阵测试里专门有一条**压缩帧校验**：参数一旦退化，测试立刻报错。

### 说明书为什么有三道关

1. **换地点**：物品名不动，只改它现在所在的地点。
   规则很直白：X 搬进了原本放 Y 的格子 ⇒ X 的地点写成 **Y 在原版说明书里的地点**（零翻译、零猜测）。
2. **长度适配**：游戏按**固定大小的文本框**排版，文本超长会把**尾部裁掉**——
   症状很迷惑：近战职业"缺武器"、法祷"缺卢恩"（因为这些恰好都排在条目末尾）。
   现在每条都适配到安全长度：该缩的缩（冗长的地点措辞规则化缩写）、该补的补（零宽空格）。
3. **写入与审计**：FMG 文本表按**整串/表项**定位——曾经因为按"前 20 个字"定位而**串页**
   （同一职业的多页首行一模一样，两次都改到同一处）；
   并且每行都**原样保留** `<font size=...>` / `<font color=...>` 标签（丢标签会让字号、颜色变样）。

## 五、质量保障

| 关卡 | 内容 |
|---|---|
| **矩阵测试** | 15 配置 × 6 种子 = **90 组**：6 项引擎校验 / 守恒 / 同种子可复现 / 法祷零违规 / 压缩帧校验 |
| **真机验证** | 发布前把**每一种配置**都实际启动一次游戏，确认进入主菜单（14/14） |
| **说明书审计** | 每次写入自动跑：标签结构、长度、物品名、空地点、串页、行数、落盘核对、幂等 |
| **审计自检** | 对审计本身做"变异测试"：人为制造 5 类故障，确认都能被抓到、且不误报 |
| **文件自检** | 界面启动即检查本地必需文件，缺项禁用写入 |
| **负例回归** | `_negative_tests.py`：**30 项**边界/负例（含"同职业多页首行相同"这个真实 bug 的回归测试、商店比例 H9 一致性） |
| **旋钮体检** | `check_config_effects.py`：每个配置项各跑一对配置，验"结果真的变了、方向对"（当前 **18 项有效 / 0 异常 / 2 项已知空转**） |
| **写入侧体检** | `check_write_options.py`：在**临时 MOD 副本**上真跑写入与还原——说明书开关两个方向、商店行**只动 equipId/equipType**、还原成原始逐字节复原 |
| **基准对照** | `_golden_check.py`：冻结一份 golden plan，重新生成逐行对比，能发现"无意改动了随机结果" |
| **写前复核** | 写入前逐条比对当前文件的旧物品 ID 与类别，不一致**立即中止**（输出文件根本不会被创建） |

**守恒**是硬要求：对任何一个参与随机的格子集合，它持有的物品多重集在随机前后**完全一致**——
每个格子换走一件、换进一件，套装整组进出、不拆散。

## 七、边界与免责

- 本工具**只改数据文件**（物品分布与说明书文本），**不修改游戏本体**，也**不绕过任何反作弊/联网校验**。
- 仓库里**不含**任何游戏本体文件或 MOD 本体文件；Release 里只有本工具的 exe。
  使用前请自备**原版**的 `regulation.bin` 与说明书文件；工具会在写入前自动备份。
- 这是**单人游戏**的存档体验工具。请勿用于联机。使用前请自行备份存档。
- 「法魂」「The Convergence」「ELDEN RING」等名称与内容归各自权利人所有，本项目与之无隶属关系。
